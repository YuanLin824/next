## 第一阶段：CI/CD 概念与安装（入门）

### 1. 什么是 CI/CD？

```
CI（持续集成）:  代码提交 → 自动构建 → 自动测试 → 反馈结果
CD（持续交付）:  CI 通过后 → 自动部署到测试/预发布环境
CD（持续部署）:  全部自动 → 直接部署到生产环境

Jenkins 在其中的角色: 自动化一切（触发 → 构建 → 测试 → 部署 → 通知）
```

### 2. Docker 安装 Jenkins

```bash
docker pull jenkins/jenkins:lts

docker run -d \
  --name jenkins \
  -p 8080:8080 -p 50000:50000 \
  -v /var/jenkins_home:/var/jenkins_home \
  -v /var/run/docker.sock:/var/run/docker.sock \
  --restart unless-stopped \
  jenkins/jenkins:lts
```

### 3. 首次登录与初始化

```bash
# 查看初始管理员密码
docker exec -it jenkins cat /var/jenkins_home/secrets/initialAdminPassword

# 浏览器访问 http://localhost:8080
# 输入密码 → 安装推荐插件 → 创建管理员账号 → 配置 Jenkins URL → 完成
```

### 4. Docker-Compose 一键部署

```yaml
services:
  jenkins:
    image: jenkins/jenkins:lts
    container_name: jenkins
    ports: ["8080:8080", "50000:50000"]
    volumes:
      - jenkins_home:/var/jenkins_home
      - /var/run/docker.sock:/var/run/docker.sock
    restart: unless-stopped
volumes:
  jenkins_home:
```

> **小结**: 理解 CI/CD 概念，能用 Docker 运行 Jenkins 并完成初始化。

## 第二阶段：基础配置（会用 Jenkins）

### 5. 核心概念

| 概念            | 说明             | 类比     |
| --------------- | ---------------- | -------- |
| **Job/Project** | 一个构建任务     | 项目     |
| **Build**       | 一次构建执行     | 构建版本 |
| **Workspace**   | 拉取代码的目录   | 工作区   |
| **Agent/Node**  | 执行构建的机器   | 执行机   |
| **Master**      | Jenkins 主控节点 | 调度中心 |

### 6. 插件管理

```
Manage Jenkins → Plugins → Available plugins

必装插件:
- Pipeline              — 声明式流水线（内置）
- Git / Git Parameter   — 代码管理和参数化
- Blue Ocean            — 可视化 UI
- Credentials Binding   — 凭据管理
- NodeJS                — Node.js 环境管理
- Docker Pipeline       — Docker 操作
```

### 7. 全局工具配置

```
Manage Jenkins → Tools:
  JDK: 自动安装 → jdk-17
  Git: 自动安装
  NodeJS: 自动安装 → Node 20.x
  Maven: 自动安装（Java 项目需要）
```

### 8. 凭据管理（连接外部系统）

```
Manage Jenkins → Credentials → System → Global credentials:

Username with password        — Git 账号、服务器登录

Secret text                   — API Token、Webhook Secret
Secret file                   — kubeconfig、证书文件
```

## 第三阶段：创建第一个 Job（FreeStyle）

### 9. FreeStyle Job 创建

```
New Item → Freestyle project → 输入名称

1. General: 勾选 "This project is parameterized"
   → 添加 Git Parameter（动态分支选择）
2. Source Code Management:
   → Git → Repository URL + Credentials + 分支
3. Build Triggers:
   → Poll SCM: H/5 * * * *（每 5 分钟检查变更）
4. Build Steps:
   → Execute shell:
     npm install
     npm run build
     npm test
5. Post-build Actions:
   → Archive the artifacts（归档 dist/ 目录）
   → Publish JUnit test result report（test-results/*.xml）
```

### 10. 构建触发方式对比

| 方式         | 说明                      | 适用         |
| ------------ | ------------------------- | ------------ |
| **手动**     | 点"Build Now"             | 测试         |
| **Poll SCM** | 定时检查 Git 变更         | 替代 Webhook |
| **Webhook**  | Git Push 自动触发（推荐） | 正式项目     |
| **定时构建** | `0 2 * * *` 每天凌晨 2 点 | 定期任务     |
| **上游触发** | Job A 成功后触发 Job B    | 流水线串联   |

> **小结**: 能创建并配置一个完整的 FreeStyle Job，理解构建触发方式。

## 第四阶段：Pipeline 入门（声明式流水线）

### 11. 创建第一个 Jenkinsfile

```groovy
// Jenkinsfile
pipeline {
    agent any

    stages {
        stage("Checkout") {
            steps {
                checkout scm
                echo "分支: ${env.GIT_BRANCH}"
            }
        }
        stage("Install") {
            steps {
                sh "npm ci"
            }
        }
        stage("Build") {
            steps {
                sh "npm run build"
            }
        }
        stage("Test") {
            steps {
                sh "npm test"
            }
        }
    }

    post {
        success { echo "构建成功!" }
        failure { echo "构建失败: ${env.BUILD_URL}" }
    }
}
```

### 12. Job 与 Jenkinsfile 关联

```
方式一: New Item → Pipeline
  Definition: Pipeline script from SCM
  SCM: Git → 仓库 URL
  Script Path: Jenkinsfile

方式二: Multibranch Pipeline
  自动扫描所有包含 Jenkinsfile 的分支，各自独立构建
```

### 13. 环境变量与参数

```groovy
pipeline {
    agent any

    environment {
        APP_NAME = "my-app"
        DEPLOY_DIR = "/var/www/html"
    }

    parameters {
        string(name: "VERSION", defaultValue: "1.0.0", description: "版本号")
        choice(name: "ENV", choices: ["dev", "staging", "prod"], description: "部署环境")
        booleanParam(name: "RUN_TESTS", defaultValue: true)
    }

    stages {
        stage("Build") {
            steps {
                echo "构建 ${APP_NAME} ${params.VERSION} → ${params.ENV}"
            }
        }
    }
}
```

### 14. when 条件执行

```groovy
stage("Deploy") {
    when {
        branch "main"                            // 仅 main 分支
        expression { params.ENV == "prod" }      // 仅生产环境
        anyOf { branch "main"; branch "develop" } // main 或 develop
    }
    steps { sh "deploy.sh" }
}

stage("Skip on PR") {
    when { not { changeRequest() } }  // 非 PR 才执行
    steps { sh "npm run deploy" }
}
```

> **小结**: 能编写声明式 Pipeline，理解 environment/parameters/when 的基本用法。

## 第五阶段：Pipeline 进阶（生产级流水线）

### 15. 前端项目完整 Jenkinsfile

```groovy
pipeline {
    agent any

    environment {
        APP = "frontend-app"
        DOCKER_REGISTRY = "registry.example.com"
    }

    parameters {
        choice(name: "ENV", choices: ["dev", "staging", "prod"])
        gitParameter(name: "BRANCH", type: "PT_BRANCH", defaultValue: "main")
    }

    stages {
        stage("Checkout") { steps { checkout scm } }

        stage("Install") {
            steps { nodejs("Node 20") { sh "npm ci" } }
        }

        stage("Lint & Type Check") {
            steps {
                sh "npm run lint"
                sh "npx tsc --noEmit"
            }
        }

        stage("Unit Tests") {
            steps { sh "npm test -- --coverage" }
            post { always { junit "coverage/junit.xml" } }
        }

        stage("Build") {
            steps {
                script {
                    def mode = params.ENV == "prod" ? "production" : "staging"
                    sh "npm run build -- --mode ${mode}"
                }
            }
        }

        stage("Build Docker Image") {
            when { expression { params.ENV != "dev" } }
            steps {
                sh "docker build -t ${DOCKER_REGISTRY}/${APP}:${BUILD_NUMBER} ."
                sh "docker push ${DOCKER_REGISTRY}/${APP}:${BUILD_NUMBER}"
            }
        }

        stage("Deploy") {
            when { expression { params.ENV == "prod" } }
            steps {
                sh """
                    ssh deploy@server "docker pull ${DOCKER_REGISTRY}/${APP}:${BUILD_NUMBER}"
                    ssh deploy@server "docker-compose -f docker-compose.prod.yml up -d"
                """
            }
        }
    }

    post {
        success { echo "✅ ${env.JOB_NAME} #${BUILD_NUMBER} 成功" }
        failure { echo "❌ 查看: ${env.BUILD_URL}" }
        always { cleanWs() }
    }
}
```

### 16. 并行执行

```groovy
stage("Tests") {
    parallel {
        stage("Unit") { steps { sh "npm run test:unit" } }
        stage("E2E")  { steps { sh "npm run test:e2e" } }
        stage("Lint") { steps { sh "npm run lint" } }
    }
}
```

### 17. 手动审批（Input）

```groovy
stage("Deploy Prod") {
    input {
        message "确认部署到生产环境？版本: ${params.VERSION}"
        ok "确认部署"
        submitter "admin,team-lead"  // 只有指定用户可审批
    }
    steps { sh "deploy-prod.sh" }
}
```

### 18. 重试与超时

```groovy
// 重试 — 处理偶发性失败
retry(3) { sh "npm run flaky-test" }

// 超时 — 防止挂死
timeout(time: 10, unit: "MINUTES") {
    sh "npm run build"
}
```

> **小结**: 能编写生产级 Pipeline（参数化 + 并行 + 审批 + 重试 + 通知）。

## 第六阶段：Groovy 脚本进阶（Scripted Pipeline）

### 19. 声明式 vs Scripted Pipeline

| 声明式                                                  | Scripted               |
| ------------------------------------------------------- | ---------------------- |
| `pipeline { agent any stages { stage { steps { } } } }` | `node { stage { } }`   |
| 严格结构、约束清晰                                      | 灵活、完全 Groovy 代码 |
| 适合大多数场景                                          | 复杂逻辑控制时使用     |

### 20. Scripted Pipeline 示例

```groovy
node {
    stage("Checkout") { checkout scm }

    def modules = ["auth", "user", "order"]

    stage("Parallel Build") {
        def builds = [:]
        for (module in modules) {
            def m = module  // Groovy 闭包特性：需要用局部变量
            builds[m] = {
                dir(m) {
                    sh "npm ci && npm run build"
                }
            }
        }
        parallel builds
    }

    stage("Deploy") {
        def env = params.ENV ?: "dev"
        sh "deploy.sh ${env}"
    }
}
```

### 21. 共享库 (Shared Library) — 代码复用

```
jenkins-shared-library/
├── vars/
│   ├── npmBuild.groovy      # npmBuild('prod')
│   ├── dockerPush.groovy    # dockerPush('my-app', '1.0.0')
│   └── notifySlack.groovy
├── src/
│   └── org/example/
│       └── Utils.groovy
└── resources/
    └── templates/
```

```groovy
// vars/npmBuild.groovy — 自定义步骤
def call(String env = "dev") {
    nodejs("Node 20") {
        sh "npm ci"
        sh "npm run build -- --mode ${env}"
    }
}
```

```groovy
// Jenkinsfile 中使用共享库
@Library("my-shared-library") _

pipeline {
    agent any
    stages {
        stage("Build") { steps { npmBuild "prod" } }
    }
}
```

> **小结**: 理解 Scripted Pipeline 的灵活性，能用共享库复用流水线代码。

## 第七阶段：Webhook 与自动触发

### 22. GitHub Webhook 配置

```
1. Jenkins 安装 GitHub Integration 插件
2. GitHub 仓库 → Settings → Webhooks → Add webhook:
   Payload URL: http://jenkins:8080/github-webhook/
   Content type: application/json
   Events: Just the push event
3. Jenkins Job 中:
   勾选 "GitHub hook trigger for GITScm polling"
   (或 Pipeline: triggers { githubPush() })
```

### 23. Generic Webhook（通用 Webhook）

```bash
# 安装 Generic Webhook Trigger 插件
```

```groovy
// Jenkinsfile
triggers {
    GenericTrigger(
        genericVariables: [
            [key: "branch", value: "\$.ref"],
            [key: "author", value: "\$.pusher.name"],
        ],
        token: "my-secret-token",
        causeString: "Triggered by \$author on \$branch"
    )
}
```

```
Webhook URL: http://jenkins:8080/generic-webhook-trigger/invoke?token=my-secret-token
```

### 24. 定时触发语法 (Cron)

```
MINUTE HOUR DOM MONTH DOW

H/5 * * * *      每 5 分钟（H 是 Jenkins 哈希分布，避免集中触发）
0 2 * * *        每天凌晨 2 点
0 9 * * 1-5      工作日早上 9 点
0 0 1 * *        每月 1 号
```

> **小结**: 掌握 Webhook 自动触发 + Cron 定时触发两种自动化方式。

## 第八阶段：Agent 与分布式构建

### 25. Agent（节点）概念

```
Master（主节点）:  调度 + 管理，不执行构建
Agent（从节点）:   实际执行构建的机器

为什么需要 Agent:
- 隔离不同环境（不同项目需要不同 JDK/Node 版本）
- 分担负载
- 限制资源
```

### 26. Agent 配置方式

```groovy
// 1. 任意 Agent
agent any

// 2. 指定标签
agent { label "linux-docker" }

// 3. Docker Agent（每个构建使用干净的容器）
agent { docker { image "node:20-alpine" } }

// 4. 不同 stage 用不同 Agent
pipeline {
    agent none
    stages {
        stage("Build") {
            agent { label "linux" }
            steps { sh "npm run build" }
        }
        stage("Deploy") {
            agent { label "deployer" }
            steps { sh "deploy.sh" }
        }
    }
}
```

### 27. 添加 Agent 节点

```
Manage Jenkins → Nodes → New Node

1. 输入名称 + 标签
2. 远程工作目录: /home/jenkins/agent
3. 启动方式: Launch agent via SSH
4. 添加凭据（SSH 密钥）
5. 保存 → Launch
```

> **小结**: 理解 Master-Agent 架构，能配置多节点和 Docker Agent。

### 31. 权限管理

```

1. 安全域: Jenkins' own user database
2. 授权策略: Role-Based Strategy
```

```txt

3. 限制 Input 审批权限（submitter 字段）
4. 定期更新 Jenkins + 插件
5. 开启 CSRF 保护（默认开启）
```

## 第十三阶段：Jenkins Job DSL（Job 即代码）

### 39. Job DSL 概念

通过 Groovy 脚本**批量创建和管理 Job**，而非手动在 UI 操作。

```bash
# 安装 Job DSL 插件
```

```groovy
// jobs.groovy — 批量创建 3 个前端项目的 Job
["project-a", "project-b", "project-c"].each { name ->
    pipelineJob("${name}-pipeline") {
        description("${name} CI/CD Pipeline")
        parameters {
            stringParam("BRANCH", "main", "分支")
            choiceParam("ENV", ["dev", "staging", "prod"], "环境")
        }
        definition {
            cpsScm {
                scm {
                    git { remote { url("https://github.com/org/${name}.git") } }
                }
                scriptPath("Jenkinsfile")
            }
        }
        triggers { githubPush() }
    }
}
```

### 40. Job DSL 种子作业

```
1. 创建一个 Seed Job（Freestyle）
2. Build Steps → Process Job DSLs
3. 指向 Git 仓库中的 jobs.groovy
4. 运行 Seed Job → 自动创建/更新所有 Job
```

## 第十四阶段：JCasC（配置即代码）

### 41. JCasC 概念

Jenkins Configuration as Code — 通过**一个 YAML 文件**管理 Jenkins 所有配置（插件/凭据/节点/安全），实现**零手动配置**。

```bash
# 安装 Configuration as Code (JCasC) 插件
```

### 42. jenkins.yaml 示例

```yaml
jenkins:
  systemMessage: "由 JCasC 管理的 Jenkins"
  numExecutors: 2

  securityRealm:
    local:
      allowsSignup: false
      users:
        - id: admin; password: ${ADMIN_PASSWORD}

  authorizationStrategy:
    roleBased:
      roles:
        global:
          - name: admin; permissions: ["Overall/Administer"]
          - name: developer; permissions: ["Job/Build", "Job/Read"]

        }
```
