# Koa.js 学习指南

> 新一代 Node.js Web 框架——async/await 原生、洋葱模型极致、极简内核无限扩展。由 Express 原班人马打造。难度递进式文档。

## 第一阶段：认识 Koa（入门）

### 1. Koa 是什么？

Koa 是 Express 原班人马（TJ Holowaychuk 团队）于 2013 年启动的新一代 Node.js Web 框架。它不兼容 Express 中间件，从头设计以充分利用 ES2017 async/await。

```
Express（2010）                      │   Koa（2013 → v2 2017）
─────────────────────                │   ─────────────────────
基于回调 + next()                    │   基于 async/await
req + res 分离                       │   ctx 统一上下文
内置路由/静态/body-parser            │   极简内核——一切靠插件
错误处理需 4 参数中间件              │   错误处理 try-catch 即生效
洋葱模型——但 next() 后代码隐式执行   │   洋葱模型——显式的 await next()
```

**设计哲学：**

| Express                      | Koa                                      |
| ---------------------------- | ---------------------------------------- |
| 开箱即用——给你一架完整的厨房 | 极简内核——只给你菜刀和砧板，自由挑选食材 |
| 中间件生态极大，但质量参差   | 中间件更少但更精，每个专门解决一个问题   |
| 适合快速原型                 | 适合追求控制力的项目                     |

### 3. ctx（Context）——Koa 的核心设计

Koa 把 Node.js 原生的 `req` 和 `res` **封装成单一对象 `ctx`**，一次请求只有一个上下文。

```js
app.use(async (ctx) => {
  // ====== ctx.request —— 请求信息 ======
  ctx.request.url // 请求 URL
  ctx.request.method // HTTP 方法
  ctx.request.query // 解析后的 query string（?a=1&b=2 → {a:"1",b:"2"}）
  ctx.request.querystring // 原始 query 字符串 → "a=1&b=2"
  ctx.request.headers // 请求头
  ctx.request.get("Content-Type") // 获取指定请求头
  ctx.request.ip // 客户端 IP

  // ====== ctx —— 便捷别名（直接访问 request 上的属性） ======
  ctx.url // → ctx.request.url
  ctx.method // → ctx.request.method
  ctx.query // → ctx.request.query
  ctx.headers // → ctx.request.headers
  ctx.ip // → ctx.request.ip

  // ====== ctx.response —— 响应信息 ======
  ctx.response.status = 200
  ctx.response.body = { ok: true }
  ctx.response.type = "application/json"
  ctx.response.set("X-Custom", "value")

  // ====== ctx —— 便捷别名 ======
  ctx.status = 200
  ctx.body = { ok: true }
  ctx.type = "application/json"
  ctx.set("X-Custom", "value")

  // ====== 额外 ======
  ctx.state // 给下游中间件传递数据的命名空间 { user: {...} }
  ctx.app // 当前 Koa 应用实例
  ctx.cookies.get("token") // 读取 Cookie
  ctx.cookies.set("token", "abc", { httpOnly: true }) // 设置 Cookie
  ctx.throw(400, "参数错误") // 抛出 HTTP 错误
})
```

## 第二阶段：中间件与洋葱模型（Koa 的精髓）

### 4. async/await 中间件

每一个 Koa 中间件都是一个 **async 函数**，接收两个参数：

- `ctx`：当前请求的上下文（整个请求生命周期共享）
- `next`：调用下一个中间件的函数（返回 Promise）

```js
app.use(async (ctx, next) => {
  console.log("1: 进入")
  await next() // ⬅ await 等待所有下游中间件执行完成
  console.log("1: 离开")
})

app.use(async (ctx, next) => {
  console.log("2: 进入")
  await next()
  console.log("2: 离开")
})

app.use(async (ctx) => {
  console.log("3: 处理请求")
  ctx.body = "OK"
})

// 输出顺序：
// 1: 进入 → 2: 进入 → 3: 处理请求 → 2: 离开 → 1: 离开
```

**关键区别——Express vs Koa 的洋葱模型：**

```
Koa（真正的洋葱）                Express（不会等待异步）

await next()                     next()
  │                                │
  ├─ 上游代码                      ├─ 上游代码
  ├─ await next() ──┐              ├─ next() ──┐  ← 立即返回
  │                 │              │           │
  │      ┌──────────┘              │    ┌──────┘
  │      │ 下游中间件              │    │ 下游中间件
  │      │ 实际处理                │    │ 实际处理（异步时不可控）
  │      └──────────┐              │    └──────┐
  │                 │              │           │
  ├─ 下游完成后     │              ├─ 下游完成后? ← 可能已经返回了
  ├─ 下游代码       │              ├─ 下游代码
  ▼                 │              ▼
 结束               │              结束
```

### 5. await next() 的超级能力

```js
// Koa 可以精确测量下游执行时间
app.use(async (ctx, next) => {
  const start = Date.now()
  await next() // 等待所有下游中间件 + 处理器完成
  const duration = Date.now() - start
  ctx.set("X-Response-Time", `${duration}ms`) // 精确耗时！
})

// Koa 可以在下游完成后修改响应
app.use(async (ctx, next) => {
  await next()
  // 此时 ctx.body 已被下游设置
  if (typeof ctx.body === "object") {
    ctx.body = { data: ctx.body, timestamp: Date.now() } // 包裹一层
  }
})
```

### 6. koa-compose —— 中间件组合器

Koa 内部用 `koa-compose` 将中间件数组组合成单个执行链：

```js
const compose = require("koa-compose")
const Koa = require("koa")

// 多个中间件组合为单个
const all = compose([
  async (ctx, next) => {
    console.log("1")
    await next()
  },
  async (ctx, next) => {
    console.log("2")
    await next()
  },
  async (ctx) => {
    ctx.body = "composed"
  },
])

app.use(all)
```

**手写 koa-compose 核心原理（面试常考）：**

```js
function compose(middlewares) {
  return function (ctx, next) {
    let index = -1

    function dispatch(i) {
      if (i <= index) return Promise.reject(new Error("next() called multiple times"))
      index = i

      let fn = middlewares[i]
      if (i === middlewares.length) fn = next // 所有中间件执行完 → 执行最外层 next
      if (!fn) return Promise.resolve() // 没有下一个 → 结束

      try {
        return Promise.resolve(fn(ctx, dispatch.bind(null, i + 1)))
      } catch (err) {
        return Promise.reject(err)
      }
    }

    return dispatch(0)
  }
}
```

### 7. koa-router —— 模块化路由

Koa 不内置路由，用社区最流行的 `@koa/router`（原名 koa-router）：

```bash
npm install @koa/router
```

```js
const Koa = require("koa")
const Router = require("@koa/router")

const app = new Koa()
const router = new Router()

// 基础路由
router.get("/users", async (ctx) => {
  ctx.body = [{ id: 1, name: "Alice" }]
})

router.get("/users/:id", async (ctx) => {
  ctx.body = { id: ctx.params.id } // params 读取路由参数
})

router.post("/users", async (ctx) => {
  ctx.body = { msg: "created", data: ctx.request.body }
})

router.put("/users/:id", async (ctx) => {
  ctx.body = { msg: "updated" }
})

router.delete("/users/:id", async (ctx) => {
  ctx.body = { msg: "deleted" }
})

// 挂载到应用
app.use(router.routes())
// 允许 OPTIONS/405 等响应（推荐）
app.use(router.allowedMethods())

app.listen(3000)
```

### 12. JWT 认证

```bash
npm install jsonwebtoken bcrypt
```

```js
const jwt = require("jsonwebtoken")
const bcrypt = require("bcrypt")
const SECRET = process.env.JWT_SECRET

// ====== 登录 ======
router.post("/login", async (ctx) => {
  const { email, password } = ctx.request.body
  const user = await User.findOne({ email })

  if (!user || !(await bcrypt.compare(password, user.password))) {
    ctx.throw(401, "邮箱或密码错误")
  }

  const token = jwt.sign({ id: user.id, role: user.role }, SECRET, { expiresIn: "7d" })
  ctx.body = { token }
})

// ====== 认证中间件 ======
function auth() {
  return async (ctx, next) => {
    const authHeader = ctx.headers.authorization
    if (!authHeader?.startsWith("Bearer ")) {
      ctx.throw(401, "未提供 Token")
    }
    try {
      const payload = jwt.verify(authHeader.split(" ")[1], SECRET)
      ctx.state.user = payload // ⬅ 存入 ctx.state，下游直接取
      await next()
    } catch {
      ctx.throw(401, "Token 无效或已过期")
    }
  }
}

// ====== 授权中间件 ======
function authorize(...roles) {
  return async (ctx, next) => {
    if (!roles.includes(ctx.state.user.role)) {
      ctx.throw(403, "权限不足")
    }
    await next()
  }
}

// 使用
router.get("/admin/users", auth(), authorize("admin"), async (ctx) => {
  ctx.body = await User.findAll()
})
```

## 第五阶段：高级模式

### 15. 自定义中间件编写

```js
// ====== 模式一：函数工厂（带参数） ======
function requireRole(role) {
  return async (ctx, next) => {
    if (ctx.state.user?.role !== role) {
      ctx.throw(403, `需要 ${role} 权限`)
    }
    await next()
  }
}
router.get("/admin", requireRole("admin"), handler)

// ====== 模式二：条件中间件 ======
function unless(paths, middleware) {
  return async (ctx, next) => {
    if (paths.some((p) => ctx.path.startsWith(p))) {
      return next() // 跳过
    }
    return middleware(ctx, next)
  }
}
// 除了 /login 以外都需要认证
app.use(unless(["/login", "/register"], auth()))

// ====== 模式三：请求体大小限制中间件 ======
function bodySizeLimit(maxBytes) {
  return async (ctx, next) => {
    const length = ctx.request.get("Content-Length")
    if (length && parseInt(length) > maxBytes) {
      ctx.throw(413, "请求体过大")
    }
    await next()
  }
}
app.use(bodySizeLimit(100 * 1024))
```

### 16. 错误处理策略

Koa 的错误处理比 Express 简洁得多——`try-catch` 直接生效：

```js
// ====== 方案一：顶层 try-catch（推荐） ======
app.use(async (ctx, next) => {
  try {
    await next()
  } catch (err) {
    ctx.status = err.status || 500
    ctx.body = {
      error: {
        message: err.expose ? err.message : "服务器内部错误", // expose: 是否可以展示给客户端
        status: ctx.status,
      },
    }
    // 生产环境记录完整堆栈
    if (ctx.status === 500) console.error(err)
  }
})

// ====== 方案二：error 事件监听 ======
app.on("error", (err, ctx) => {
  console.error("server error:", err)
  // 在这里记录到日志系统、发送告警等
})

// ====== 抛出 HTTP 错误的三种方式 ======
ctx.throw(400, "参数错误")
ctx.throw(401) // 默认消息 "Unauthorized"
ctx.throw(404, "用户不存在")

// 自定义错误类
class AppError extends Error {
  constructor(message, status, code) {
    super(message)
    this.status = status
    this.code = code
    this.expose = true // 允许把消息展示给客户端
  }
}
ctx.throw(new AppError("余额不足", 400, "INSUFFICIENT_BALANCE"))
```

## 第六阶段：Express vs Koa 全面对比

### 19. Express 迁移到 Koa 对照表

| 场景           | Express                           | Koa                               |
| -------------- | --------------------------------- | --------------------------------- |
| 创建应用       | `const app = express()`           | `const app = new Koa()`           |
| 中间件         | `(req, res, next) => {}`          | `async (ctx, next) => {}`         |
| 读 Query       | `req.query`                       | `ctx.query`                       |
| 读 Body        | `req.body`（需 body-parser）      | `ctx.request.body`（需 koa-body） |
| 读 Header      | `req.get("X-Key")`                | `ctx.get("X-Key")`                |
| 读路由参数     | `req.params`                      | `ctx.params`                      |
| 设状态码       | `res.status(404)`                 | `ctx.status = 404`                |
| 设响应体       | `res.json(obj)` / `res.send(str)` | `ctx.body = obj`                  |
| 设响应头       | `res.set("X", "v")`               | `ctx.set("X", "v")`               |
| 抛出 HTTP 错误 | `res.status(400).json({})`        | `ctx.throw(400, "msg")`           |
| 错误处理       | `(err, req, res, next)` 4 参数    | `try-catch` 包裹 `await next()`   |
| 路由           | `express.Router()`                | `@koa/router`                     |
| 静态文件       | `express.static("dir")`           | `koa-static`                      |
| 模板引擎       | `app.set("view engine", "ejs")`   | `koa-views`                       |

### 20. 何时选 Koa？

| 场景                        | 推荐    | 理由                          |
| --------------------------- | ------- | ----------------------------- |
| 快速原型                    | Express | 开箱即用，中间件生态最大      |
| 新项目、追求可控            | **Koa** | async/await 原生，无历史包袱  |
| 团队熟悉 Express            | Express | 迁移成本                      |
| 需要精细的请求生命周期控制  | **Koa** | await next() 的洋葱模型更精确 |
| 已有大量 Express 中间件依赖 | Express | Koa 不兼容 Express 中间件     |
| 对接 TypeScript             | **Koa** | @types/koa 更现代             |

### 21. 常见面试问题

| 问题                            | 要点                                                      |
| ------------------------------- | --------------------------------------------------------- |
| Koa 和 Express 的最大区别？     | async/await vs 回调；ctx 统一上下文；极简内核 vs 内置功能 |
| Koa 洋葱模型如何实现？          | koa-compose：`dispatch(i)` 递归调用 + `await next()`      |
| next() 为什么必须 await？       | 不 await → 下游异步操作未完成上游就继续执行了             |
| ctx.throw 和 new Error 的区别？ | ctx.throw 会设 status + expose 属性，被错误处理中间件捕获 |
| Koa 如何做错误处理？            | 顶层 try-catch 包裹 `await next()` + `app.on("error")`    |
| ctx.state 的用途？              | 中间件之间传递数据的命名空间（如当前用户信息）            |

| `ctx.set(h, v)`        | 设置响应头            |
| `ctx.state`            | 中间件间传递数据      |
| `ctx.throw(code, msg)` | 抛出 HTTP 错误        |
| `ctx.cookies.get/set`  | Cookie 操作           |
| `ctx.redirect(url)`    | 重定向                |

**请求生命周期：**

```
请求进入
  │
  ├── 中间件 1: 进入（ctx.state 初始化、日志开始）
  │   ├── 中间件 2: 进入（认证、权限）
  │   │   ├── 中间件 3: 进入（参数校验）
  │   │   │   ├── Router Handler → ctx.body = xxx
  │   │   ├── 中间件 3: 离开
  │   ├── 中间件 2: 离开
  ├── 中间件 1: 离开（日志结束、添加响应头）
  │
  ▼ 响应发送
```
