# NestJS 学习指南

> 难度递进式 NestJS 学习文档，从概念到企业级微服务架构。

## 第一阶段：核心概念（入门）

### 1. NestJS 是什么？

借鉴 SpringBoot 的 Node.js **企业级框架**，基石是 **IoC（控制反转）+ DI（依赖注入）**。

```
请求 → Middleware → Guard → Interceptor(前) → Pipe → Controller → Service → Interceptor(后) → 响应
                                                    ↓ (任何阶段出错)
                                              ExceptionFilter
```

### 2. 核心组件

| 组件                 | 职责                         |
| -------------------- | ---------------------------- |
| **Controller**       | 处理路由、请求转发           |
| **Service/Provider** | 业务逻辑、数据访问           |
| **Module**           | 组织代码（每个功能一个模块） |
| **Middleware**       | 请求预处理（日志/CORS）      |
| **Guard**            | 鉴权/认证                    |
| **Interceptor**      | 请求响应包裹（格式化/缓存）  |
| **Pipe**             | 参数校验/转换                |
| **ExceptionFilter**  | 统一错误处理                 |

### 4. 第一个 Controller 与 Service

```ts
// users.controller.ts
import { Controller, Get, Post, Body, Param } from "@nestjs/common"
import { UsersService } from "./users.service"

@Controller("users")
export class UsersController {
  constructor(private readonly usersService: UsersService) {} // 构造函数注入

  @Get()
  findAll() {
    return this.usersService.findAll()
  }

  @Get(":id")
  findOne(@Param("id") id: string) {
    return this.usersService.findOne(+id)
  }

  @Post()
  create(@Body() dto: CreateUserDto) {
    return this.usersService.create(dto)
  }
}
```

```ts
// users.service.ts
import { Injectable } from "@nestjs/common"

@Injectable()
export class UsersService {
  private users = []

  findAll() {
    return this.users
  }
  findOne(id: number) {
    return this.users.find((u) => u.id === id)
  }
  create(dto: CreateUserDto) {
    this.users.push({ id: Date.now(), ...dto })
    return dto
  }
}
```

```ts
// users.module.ts
import { Module } from "@nestjs/common"

@Module({
  controllers: [UsersController],
  providers: [UsersService],
  exports: [UsersService], // 导出供其他模块使用
})
export class UsersModule {}
```

> **小结**：理解 NestJS 的 MVC 三层（Controller→Service→Module），会用 CLI 生成代码。

### 6. 模块间的依赖关系

```ts
@Global() // 全局模块（不需在每个 imports 中声明）
@Module({ providers: [PrismaService], exports: [PrismaService] })
export class PrismaModule {}

// 动态模块 — 运行时传参

    return {
      module: DatabaseModule,
      providers: [
        { provide: "DB_OPTIONS", useValue: options },
        { provide: "CONNECTION", useFactory: () => createConnection(options) },

      exports: ["CONNECTION"],

  }
```

```ts
import { IsString, IsEmail, MinLength, IsOptional, IsEnum } from "class-validator"

export enum Role {
  ADMIN = "admin",
  USER = "user",
}

export class CreateUserDto {
  @IsString()
  @MinLength(2)
  name: string

  @IsEmail()
  email: string

  @IsOptional()
  @IsEnum(Role)

// 全局启用
app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true, // 自动剔除未定义的属性
    forbidNonWhitelisted: true, // 有未知属性报错
    transform: true, // 自动类型转换

)
```

## 第四阶段：异常处理与拦截器

### 9. 全局异常过滤器

```ts
import {
  ExceptionFilter,
  Catch,
  ArgumentsHost,
  HttpException,
  HttpStatus,
  Logger,
} from "@nestjs/common"

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  private readonly logger = new Logger(AllExceptionsFilter.name)

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp()
    const response = ctx.getResponse()
    const request = ctx.getRequest()

    let status = HttpStatus.INTERNAL_SERVER_ERROR
    let message = "Internal Server Error"

    if (exception instanceof HttpException) {
      status = exception.getStatus()
      message = exception.message
    }

    // 处理数据库错误（TypeORM QueryFailedError）
    if (exception instanceof QueryFailedError) {
      const pgCode = exception.driverError?.code
      message = DB_ERROR_MAP[pgCode]?.message ?? "数据库操作异常"
    }

    this.logger.error({ path: request.url, status, message })
    response.status(status).json({ code: status, message, timestamp: new Date().toISOString() })
  }
}

// app.module.ts 中全局注册
providers: [{ provide: APP_FILTER, useClass: AllExceptionsFilter }]
```

### 10. 拦截器 — 响应格式统一

```ts
import { Injectable, NestInterceptor, ExecutionContext, CallHandler } from "@nestjs/common"
import { map } from "rxjs/operators"

@Injectable()
export class TransformInterceptor<T> implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler) {
    return next.handle().pipe(
      map((data) => ({
        code: 0,
        message: "success",
        data,
        timestamp: new Date().toISOString(),
      }))
    )
  }
}
```

## 第五阶段：认证与鉴权 (Guard + JWT)

### 11. JWT 认证

```bash
npm install @nestjs/jwt @nestjs/passport passport passport-jwt bcrypt
```

```ts
// auth.service.ts
import { JwtService } from "@nestjs/jwt"
import * as bcrypt from "bcrypt"

@Injectable()
export class AuthService {
  constructor(
    private jwtService: JwtService,
    private usersService: UsersService
  ) {}

  async login(email: string, password: string) {
    const user = await this.usersService.findByEmail(email)
    if (!user || !(await bcrypt.compare(password, user.password)))
      throw new UnauthorizedException("邮箱或密码错误")
    const payload = { sub: user.id, role: user.role }
    return { access_token: this.jwtService.sign(payload) }
  }
}

// jwt.strategy.ts
@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor() {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      secretOrKey: process.env.JWT_SECRET,
    })
  }
  async validate(payload: any) {
    return { id: payload.sub, role: payload.role }
  }
}
```

### 12. Guard — 路由保护

```ts
// JWT Guard
@Injectable()
export class JwtAuthGuard extends AuthGuard("jwt") {}

// 角色 Guard
@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}
  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.getAllAndOverride<string[]>(ROLES_KEY, [context.getHandler(), context.getClass()])
    if (!requiredRoles) return true
    const { user } = context.switchToHttp().getRequest()
    return requiredRoles.includes(user.role)
  }
}

// 使用
@UseGuards(JwtAuthGuard, RolesGuard)
@Roles("admin")
@Controller("admin")
```

```ts
// config/winston.ts
import { utilities, WinstonModule } from "nest-winston"
import winston from "winston"
import DailyRotateFile from "winston-daily-rotate-file"
import { IS_PROD } from "../common/utils/global"

/** 生产环境: 按小时轮转的日志文件，压缩归档，自动清理 14 天前的日志 */
const prod_opts = {
  dirname: "logger_prod",
  datePattern: "YYYY-MM-DD-HH",
  zippedArchive: true,
  maxSize: "20m",
  maxFiles: "14d",
  format: winston.format.combine(
    winston.format.timestamp(),
    utilities.format.nestLike("NestApp", { prettyPrint: true, colors: false })
  ),
}

/** 开发环境: 彩色控制台输出 */
const dev_opts = {
  format: winston.format.combine(winston.format.timestamp(), utilities.format.nestLike(undefined)),
}

/**
 * 创建 NestJS 兼容的 Winston Logger 实例
 *
 * 供 NestFactory.create 使用，替换 NestJS 默认的控制台 Logger。
 * 生产环境输出到 info/error 两个文件，开发环境输出到控制台。
 */
export const WINSTON_LOGGER = WinstonModule.createLogger({
  transports: IS_PROD
    ? [
        new DailyRotateFile({ level: "info", filename: "%DATE%.info.log", ...prod_opts }),
        new DailyRotateFile({ level: "error", filename: "%DATE%.error.log", ...prod_opts }),
      ]
    : [new winston.transports.Console({ level: "info", ...dev_opts })],
})

// main.ts 中替换默认 Logger
const app = await NestFactory.create(AppModule, { logger: WINSTON_LOGGER })
// 使用方式: 按照内置 Logger 使用即可
```

```ts
import { diskStorage } from "multer"

@Post("upload")
@UseInterceptors(FileInterceptor("file", {
  storage: diskStorage({
    destination: "./uploads",
    filename: (req, file, cb) => cb(null, `${Date.now()}-${Math.round(Math.random() * 1e9)}${extname(file.originalname)}`),
  }),
  limits: { fileSize: 5 * 1024 * 1024 },
  fileFilter: (req, file, cb) => {
    if (!file.mimetype.match(/\/(jpg|jpeg|png|gif)$/)) return cb(new BadRequestException("仅支持图片"), false)
    cb(null, true)
  },
}))
uploadFile(@UploadedFile() file: Express.Multer.File) {
  return { url: `/uploads/${file.filename}` }
}

// 多文件
@Post("uploads")
@UseInterceptors(FilesInterceptor("files", 5))
uploadFiles(@UploadedFiles() files: Express.Multer.File[]) {}
```

## 第十五阶段：缓存（Cache）

### 27. CacheModule

```ts
import { CacheModule } from "@nestjs/cache-manager"

@Module({
  imports: [CacheModule.register({ ttl: 60000, max: 100 })], // 60s 过期，最多 100 条
})

// Service 中使用
import { CACHE_MANAGER } from "@nestjs/cache-manager"
import { Cache } from "cache-manager"

@Injectable()
export class UsersService {
  constructor(@Inject(CACHE_MANAGER) private cacheManager: Cache) {}

  async findAll() {
    const cached = await this.cacheManager.get("users")
    if (cached) return cached
    const users = await this.userRepo.find()
    await this.cacheManager.set("users", users, 60000)
    return users
  }

  async create(dto) {
    const user = await this.userRepo.save(dto)
    await this.cacheManager.del("users") // 清除缓存
    return user
  }
}
```

```ts
export class DistLockService {
  constructor(@InjectRedis() private redis: Redis) {}

  async lock(key: string, ttl: number): Promise<boolean> {

}
```

## 第十九阶段：中间件 (Middleware) 详解

### 36. 中间件概念与定位

中间件在**路由匹配之前**执行，位于 NestJS 请求生命周期的**最前端**。

```
请求 → Middleware → Guard → Interceptor → Pipe → Controller
```

| 特性          | 说明                                |
| ------------- | ----------------------------------- |
| 执行时机      | 路由匹配之前（比 Guard 更早）       |
| 访问路由信息  | ❌ 不知道最终由哪个 Controller 处理 |
| 访问请求/响应 | ✅ 可修改 req/res                   |
| 终止请求      | ✅ 可直接 `res.send()` 短路         |
| 依赖注入      | ✅ 类中间件支持                     |

### 37. 三种中间件类型

```ts
// ===== 1. 函数中间件（简单场景，无 DI 依赖）=====
import { Request, Response, NextFunction } from "express"

export function simpleLogger(req: Request, res: Response, next: NextFunction) {
  console.log(`${req.method} ${req.url}`)
  next()
}

// ===== 2. 类中间件（需要 DI 注入时使用）=====
import { Injectable, Logger, NestMiddleware } from "@nestjs/common"
import { HttpAdapterHost } from "@nestjs/core"
import { NextFunction, Request, Response } from "express"
import requestIp from "request-ip"

@Injectable()
export class LogMiddleware implements NestMiddleware {
  private readonly logger = new Logger(LogMiddleware.name)

  constructor(private readonly httpAdapterHost: HttpAdapterHost) {}

  use(req: Request, res: Response, next: NextFunction) {
    const { httpAdapter } = this.httpAdapterHost
    const clientIp = requestIp.getClientIp(req) ?? "unknown"

    this.logger.log({
      clientIp,
      method: httpAdapter.getRequestMethod(req).toUpperCase(),
      path: httpAdapter.getRequestUrl(req),
      body: req.body ?? {},
      params: req.params ?? {},
      query: req.query ?? {},
      timestamp: new Date().toISOString(),
    })

    next()
  }
}

// ===== 3. 全局中间件（绕过 DI 容器，通过 app.use 注册）=====
// main.ts
import { NestFactory } from "@nestjs/core"
import { AppModule } from "./app.module"

async function bootstrap() {
  const app = await NestFactory.create(AppModule)

  // app.use 是 Express 原生 API → 绕过 NestJS DI 容器 → 中间件内无法注入 Nest 依赖
  app.use((req, res, next) => {
    console.log("全局中间件:", req.method, req.url)
    next()
  })

  await app.listen(3000)
}
```

### 38. MiddlewareConsumer 注册策略

```ts
// app.module.ts
import { MiddlewareConsumer, Module, NestModule, RequestMethod } from "@nestjs/common"

export class AppModule implements NestModule {
  configure(consumer: MiddlewareConsumer) {
    consumer
      // ===== 方式 1: 路径匹配 =====
      .apply(LogMiddleware)
      .forRoutes("api/*") // 匹配 /api 开头的所有路径

      // ===== 方式 2: 按 Controller 注册 =====
      .apply(LogMiddleware)
      .forRoutes(UsersController, PostsController)

      // ===== 方式 3: 排除特定路径 =====
      .apply(LogMiddleware)
      .exclude(
        { path: "api/health", method: RequestMethod.GET },
        { path: "api/metrics", method: RequestMethod.ALL }
      )
      .forRoutes("*")

      // ===== 方式 4: 路径 + 方法过滤 =====
      .apply(CorsMiddleware)
      .forRoutes({ path: "api/users", method: RequestMethod.POST })
  }
}
```

```
1. 全局中间件 (app.use)        — 最早执行
2. 模块中间件 (consumer.apply) — 按注册顺序
3. Guard                       — 鉴权
```

#### IP 白名单中间件

```ts
@Injectable()
export class IpWhitelistMiddleware implements NestMiddleware {
  private readonly allowed = ["127.0.0.1", "192.168.1.0/24"]

  use(req: Request, res: Response, next: NextFunction) {
    const ip = req.ip || req.socket.remoteAddress
    if (!this.isAllowed(ip)) {
      return res.status(403).json({ message: "IP 不在白名单中" })
    }
    next()
  }

  private isAllowed(ip: string): boolean {
    return this.allowed.some((allowedIp) => {
      if (allowedIp.includes("/")) {
        // CIDR 子网匹配简化的 — 生产环境用 ip-range-check 库
        const [network, bits] = allowedIp.split("/")
        return ip.startsWith(network.substring(0, network.lastIndexOf(".")))
      }
      return ip === allowedIp || ip === `::ffff:${allowedIp}`
    })
  }
}
```

### 42. Middleware 与 Guard / Interceptor 选型

| 维度         | Middleware            | Guard                    | Interceptor         |
| ------------ | --------------------- | ------------------------ | ------------------- |
| 执行时机     | 路由匹配前            | 路由匹配后               | Guard 之后          |
| 知道路由信息 | ❌                    | ✅ (getHandler/getClass) | ✅                  |
| 访问请求体   | ✅                    | ✅                       | ✅                  |
| 短路请求     | ✅                    | ✅                       | ✅                  |
| 修改响应     | ❌                    | ❌                       | ✅ (map 包装)       |
| 依赖注入     | 类中间件 ✅           | ✅                       | ✅                  |
| 适用场景     | 日志/CORS/body-parser | 鉴权/角色检查            | 响应格式化/缓存测量 |

## 第二十一阶段：请求生命周期全景（完整串联）

### 43. 完整生命周期时序图

```
请求进入
  │
  ├── 1. Middleware（中间件）
  │       ├── 全局中间件 (app.use)
  │       └── 模块中间件 (consumer.apply)
  │       能做什么: 日志/CORS/body-parser/IP 过滤/请求预处理
  │       不能: 访问具体路由信息(getHandler/getClass 不可用)
  │
  ├── 2. Guard（守卫）
  │       鉴权/角色检查/权限校验
  │       能做什么: throw UnauthorizedException 阻断请求; 设置 request.user
  │       优势: 可通过 Reflector 获取路由元数据(角色/权限)
  │
  ├── 3. Interceptor（拦截器）— Before
  │       包裹请求: 日志/缓存检查/性能测量开始
  │       能做什么: 修改请求、决定是否继续
  │
  ├── 4. Pipe（管道）
  │       参数校验/类型转换/默认值
  │       能做什么: throw BadRequestException 阻断; 转换后的值传给 Controller
  │
  ├── 5. Controller（控制器）
  │       路由处理、参数接收、调用 Service
  │
  ├── 6. Service（服务层）
  │       业务逻辑、数据库操作
  │
  ├── 7. Interceptor（拦截器）— After
  │       map() 包装返回值; 统一响应格式; 性能测量结束
  │
  └── 8. ExceptionFilter（异常过滤器）
          任何阶段抛出的异常 → 都会被最近的匹配 Filter 捕获
          能做什么: 统一错误响应格式; 日志记录; Postgres 错误码翻译
```

| 层级            | 装饰器            | 可访问路由信息           | 可短路            | 可修改响应      | 注入方式                       |
| --------------- | ----------------- | ------------------------ | ----------------- | --------------- | ------------------------------ |
| **Middleware**  | `NestMiddleware`  | ❌                       | ✅ `res.send()`   | ❌              | `consumer.apply()`             |

### 48. Guard 实战 — 多条件组合鉴权

```ts
import { Injectable, CanActivate, ExecutionContext } from "@nestjs/common"
import { Reflector } from "@nestjs/core"

// 自定义元数据 key
export const ROLES_KEY = "roles"
export const Roles = (...roles: string[]) => SetMetadata(ROLES_KEY, roles)

export const IS_PUBLIC_KEY = "isPublic"
export const Public = () => SetMetadata(IS_PUBLIC_KEY, true)

@Injectable()
export class AuthGuard implements CanActivate {
  constructor(
    private jwtService: JwtService,
    private reflector: Reflector
  ) {}

  canActivate(context: ExecutionContext): boolean {
    // 1. 检查是否是公开路由（跳过认证）
    const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [
      context.getHandler(),
      context.getClass(),
    ])
    if (isPublic) return true

    // 2. 验证 JWT
    const request = context.switchToHttp().getRequest()
    const token = this.extractToken(request)
    if (!token) throw new UnauthorizedException("未提供 token")

    try {
      request.user = this.jwtService.verify(token)
    } catch {
      throw new UnauthorizedException("token 无效或已过期")
    }

    // 3. 检查角色
    const requiredRoles = this.reflector.getAllAndOverride<string[]>(ROLES_KEY, [
      context.getHandler(),
      context.getClass(),
    ])
    if (requiredRoles && !requiredRoles.includes(request.user.role)) {
      throw new ForbiddenException("权限不足")
    }

    return true
  }

  private extractToken(request: any): string | undefined {
    return request.headers.authorization?.replace("Bearer ", "")
  }
}

// 使用
@Controller("users")
export class UsersController {
  @Public() @Get() findAll() {} // 公开接口
  @Roles("admin") @Delete(":id") remove() {} // 仅 admin
}
```

```ts
// 1. 统一响应格式拦截器
@Injectable()
export class TransformInterceptor<T> implements NestInterceptor<T, Response<T>> {
  intercept(context: ExecutionContext, next: CallHandler): Observable<Response<T>> {
    return next
      .handle()
      .pipe(
        map((data) => ({ code: 0, message: "success", data, timestamp: new Date().toISOString() }))
      )
  }
}

// 2. 性能测量拦截器
@Injectable()
export class PerformanceInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const start = Date.now()
    const handler = context.getHandler().name
    const controller = context.getClass().name
    return next
      .handle()
      .pipe(tap(() => console.log(`${controller}.${handler} — ${Date.now() - start}ms`)))
  }
}

// 3. 缓存拦截器（简化实现）
@Injectable()
export class CacheInterceptor implements NestInterceptor {
  private cache = new Map<string, { data: any; expiry: number }>()

  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const request = context.switchToHttp().getRequest()
    const key = `${request.method}:${request.url}`
    const cached = this.cache.get(key)

    if (cached && cached.expiry > Date.now()) {
      return of(cached.data) // 直接返回缓存数据，不等 Service
    }

    return next
      .handle()
      .pipe(tap((data) => this.cache.set(key, { data, expiry: Date.now() + 60000 })))
  }
}
```

### 50. ExceptionFilter 实战 — 分层分类错误处理

```ts
import {
  ExceptionFilter,
  Catch,
  ArgumentsHost,
  HttpException,
  HttpStatus,
  Logger,
} from "@nestjs/common"
import { QueryFailedError } from "typeorm"

// Postgres 错误码映射
const DB_ERROR_MAP: Record<string, { status: number; message: string }> = {
  "23505": { status: HttpStatus.CONFLICT, message: "数据已存在，违反唯一约束" },
  "23503": { status: HttpStatus.BAD_REQUEST, message: "数据关联异常，违反外键约束" },
  "23502": { status: HttpStatus.BAD_REQUEST, message: "必填字段缺失" },
  "23514": { status: HttpStatus.BAD_REQUEST, message: "数据校验失败" },
  "22001": { status: HttpStatus.BAD_REQUEST, message: "字段值超出最大长度限制" },
}

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  private readonly logger = new Logger(AllExceptionsFilter.name)

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp()
    const response = ctx.getResponse()
    const request = ctx.getRequest()

    let status = HttpStatus.INTERNAL_SERVER_ERROR
    let message = "服务器内部错误"

    // 1. NestJS HttpException → 直接取状态码和消息
    if (exception instanceof HttpException) {
      status = exception.getStatus()
      message = exception.message
    }

    // 2. TypeORM QueryFailedError → Postgres 错误码翻译
    if (exception instanceof QueryFailedError) {
      const pgCode = (exception.driverError as any)?.code
      const mapping = DB_ERROR_MAP[pgCode]
      if (mapping) {
        status = mapping.status
        message = mapping.message
      } else message = `数据库操作异常 [${pgCode}]`
    }

    // 3. 未知错误 → 500
    if (status >= 500) {
      this.logger.error({
        path: request.url,
        status,
        message,
        stack: exception instanceof Error ? exception.stack : String(exception),
        timestamp: new Date().toISOString(),
      })
    }

    const responseBody: any = { code: status, message, timestamp: new Date().toISOString() }

    // HttpException 的响应可能包含额外数据（如 ValidationPipe 的详细错误）
    if (exception instanceof HttpException) {
      const res = exception.getResponse()
      if (typeof res === "object" && res !== null) {
        responseBody.detail = (res as any).message ?? res
      }
    }

    response.status(status).json(responseBody)
  }
}
```

## 生命周期总结速查

```
请求到达 NestJS
    │
    ├── Middleware ────────── 日志/CORS/IP过滤/body解析 (app.use / consumer.apply)
    │     └ 可短路: res.send() 直接返回
    │
    ├── Guard ─────────────── 鉴权/角色/权限 (CanActivate)
    │     └ 可短路: return false → 403 / throw UnauthorizedException
    │     └ 优势: Reflector 读取路由元数据(@Roles/@Public)
    │
    ├── Interceptor (Before) ── 请求前处理 / 缓存检查
    │
    ├── Pipe ──────────────── 参数校验/类型转换 (PipeTransform)
    │     └ 可短路: throw BadRequestException
    │
    ├── Controller ────────── 路由处理 / 调用 Service
    │
    ├── Service ───────────── 业务逻辑
    │
    ├── Interceptor (After) ── map() 统一格式 / 性能测量 / 缓存存储
    │
    └── ExceptionFilter ────── 捕获所有未处理异常 (Catch)
          └ HttpException / QueryFailedError / 未知错误
          └ 统一错误响应 { code, message, timestamp }
```
