# CC-Switch 使用指南（以 Claude Code CLI 为例）

> 难度递进式学习文档：从配置原理到 GUI/CLI 切换器实操，覆盖安装、供应商配置、切换验证与常见问题排查。

---

## 第一阶段：背景与原理（入门）

### 1. 为什么需要 ccswitch？

Claude Code 官方版默认只能连接 **Anthropic 官方 API**（`https://api.anthropic.com`），需要海外网络与官方账号。国内开发者通常有以下需求：

```
需求 1：接入第三方中转/聚合供应商（DeepSeek、OfoxAI、OpenRouter 等）省钱省事
需求 2：在不同供应商之间来回切换（官方 ↔ DeepSeek ↔ 中转站）
需求 3：不同项目使用不同供应商（A 项目用官方、B 项目用中转）
```

**手改配置的痛点**：Claude Code 的供应商配置写在 `~/.claude/settings.json` 中，手动编辑容易出错（JSON 语法、Key 复制不完整、Base URL 末尾斜杠等），切换不灵活。

```
┌─────────────────────────────────────────────┐
│            ccswitch 解决的问题              │
│                                             │
│   手动编辑 settings.json  ──▶  一键切换     │
│   ❌ 容易写错 JSON          ✅ 模板化写入   │
│   ❌ 切换麻烦               ✅ 多配置保存   │
│   ❌ 没有备份               ✅ 自动备份     │
└─────────────────────────────────────────────┘
```

### 2. 核心原理：Claude Code 如何读取供应商配置？

ccswitch 类工具的本质都是**读写 `~/.claude/settings.json` 中的 `env` 字段**。理解这个文件是掌握所有切换器的基础。

```json
// ~/.claude/settings.json —— Claude Code 全局配置文件
{
  "env": {
    // ── 供应商端点（最关键的两个字段）──
    "ANTHROPIC_BASE_URL": "https://api.deepseek.com/anthropic",
    "ANTHROPIC_AUTH_TOKEN": "sk-xxxxxxxxxxxxxxxx",

    // ── 可选的认证方式（二选一）──
    // "ANTHROPIC_API_KEY": "sk-ant-xxx",   // 官方 API Key 认证

    // ── 模型配置（可选）──
    "ANTHROPIC_MODEL": "deepseek-chat",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "deepseek-chat",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "deepseek-chat",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "deepseek-chat"
  }
}
```

**字段说明**：

| 环境变量                         | 作用                              | 典型值示例                            |
| -------------------------------- | --------------------------------- | ------------------------------------- |
| `ANTHROPIC_BASE_URL`             | API 请求地址（供应商入口）        | `https://api.deepseek.com/anthropic`  |
| `ANTHROPIC_AUTH_TOKEN`           | 认证令牌（中转站/自定义端点常用） | `sk-xxx`                              |
| `ANTHROPIC_API_KEY`              | 官方 API Key（`sk-ant-` 开头）    | `sk-ant-xxxxxxxx`                     |
| `ANTHROPIC_MODEL`                | 默认模型                          | `deepseek-chat` / `claude-sonnet-4-6` |
| `ANTHROPIC_DEFAULT_HAIKU_MODEL`  | 快模型（Haiku 档位）              | `deepseek-chat`                       |
| `ANTHROPIC_DEFAULT_SONNET_MODEL` | 主力模型（Sonnet 档位）           | `claude-sonnet-4-6`                   |
| `ANTHROPIC_DEFAULT_OPUS_MODEL`   | 最强模型（Opus 档位）             | `claude-opus-4-8`                     |

**配置读取优先级**（从高到低）：

```
1. 命令行环境变量（shell 里 export）
2. 项目级配置 .claude/settings.json（当前项目目录下）
3. 全局配置 ~/.claude/settings.json（ccswitch 主要修改这里）
4. 系统环境变量 / 默认值
```

**关键认知**：ccswitch 修改的是**全局配置**（第 3 层）。如果 shell 里手动 export 了 `ANTHROPIC_BASE_URL`，ccswitch 的切换会被覆盖——排查"切换不生效"时先查这一条。

### 3. 手动配置验证（不装工具也能用）

```json
// 示例：切换到一个 DeepSeek 中转端点
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.deepseek.com/anthropic",
    "ANTHROPIC_AUTH_TOKEN": "sk-你的密钥",
    "ANTHROPIC_MODEL": "deepseek-chat"
  }
}
```

保存后**重启 Claude Code**（已启动的会话不会重读配置），在会话中输入 `/status` 验证：

```
/status 输出示例：

───────────────────────────
Claude Code
───────────────────────────
Version: 2.x.x (Claude Code CLI)
Model: deepseek-chat
API: https://api.deepseek.com/anthropic   ← 看这里！确认 base URL
───────────────────────────
```

`/status` 中显示正确的 Base URL 即表示切换成功。**这是验证任何切换操作是否生效的标准方法。**

## 第二阶段：工具家族概览（进阶）

### 4. ccswitch 系列工具对比

市面上存在多个同名/同族工具，先看清区别再选型：

| 工具                             | 类型     | 安装方式                                 | 特点                                         |
| -------------------------------- | -------- | ---------------------------------------- | -------------------------------------------- |
| **CC-Switch（GUI 版）**          | 图形界面 | `.msi` / `brew --cask` / `.deb` / `.rpm` | 官方推荐、可视化操作、零门槛、多供应商管理   |
| **@aravhawk/cc-switch**          | CLI      | `npm i -g @aravhawk/cc-switch`           | profile 配置管理、支持模板（kimi/glm 等）    |
| **ccswitch-tui**                 | TUI      | `npm i -g ccswitch-tui`                  | 内置 55+ 供应商预设、交互式菜单              |
| **@wcldyx/claude-code-switcher** | CLI      | `npm i -g @wcldyx/claude-code-switcher`  | `cc` 命令、API Key/Auth Token/OAuth 三种认证 |
| **@olayemii/ccswitch**           | CLI      | `npm i -g @olayemii/ccswitch`            | 支持 per-shell 切换、doctor 诊断             |
| **@xwm111/ccs**                  | CLI      | `npm i -g @xwm111/ccs`（或 npx）         | 中英文界面、附带 Claude Code 更新检查        |

**选型建议**：

```
新手 / 怕命令行     → CC-Switch（GUI 版）⭐ 推荐
想要内置大量预设   → ccswitch-tui
深度 CLI 用户      → @aravhawk/cc-switch 或 @wcldyx
多账号并行        → @olayemii/ccswitch（per-shell 切换）
```

> ⚠️ 注意：所有工具写入的底层文件都是同一个 `~/.claude/settings.json`，**不要同时安装多个切换器**混用，会互相覆盖。

## 第三阶段：GUI 版 CC-Switch 实操（主推）

### 5. 安装

| 系统        | 安装方法                                                                                                                                                   |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Windows** | 下载 `.msi` 安装包（支持 Win 10/11）                                                                                                                       |
| **macOS**   | `brew install --cask cc-switch` 或下载 `.dmg`（需 macOS 12+）                                                                                              |
| **Linux**   | Debian/Ubuntu：`sudo dpkg -i CC-Switch-*.deb`；Fedora/RHEL：`sudo rpm -i CC-Switch-*.rpm`；通用：`chmod +x CC-Switch-*.AppImage && ./CC-Switch-*.AppImage` |

### 6. 添加供应商（以 OfoxAI 为例）

打开 CC-Switch → 进入**供应商管理页** → 点右上角 **「+ 添加供应商」**：

| 字段       | 填写内容（示例）                | 说明                                  |
| ---------- | ------------------------------- | ------------------------------------- |
| 供应商名称 | `ofoxai-claude`                 | 自定义名称，用于列表区分              |
| 官网链接   | `https://ofox.ai`               | 可留空                                |
| API Key    | 在供应商后台生成并**完整复制**  | 注意不要带空格/换行                   |
| 请求地址   | `https://api.ofox.ai/anthropic` | **末尾不要加斜杠**，用 anthropic 后缀 |
| API 格式   | Anthropic Messages（原生）      | 保持默认                              |
| 认证字段   | `ANTHROPIC_AUTH_TOKEN`          | 保持默认                              |
| 模型配置   | 可留空，或指定默认模型          | 按供应商文档填写                      |

点「+ 添加」保存 → 回到列表 → **选中该供应商 → 点「使用」** → 提示「切换成功」即完成。

工具会自动把配置写入 `~/.claude/settings.json`：

```json
// 切换后的实际效果
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.ofox.ai/anthropic",
    "ANTHROPIC_AUTH_TOKEN": "sk-xxxxxxxx"
  }
}
```

### 7. 常用供应商配置速查

| 供应商               | 请求地址（Base URL）                 | API Key 获取处        | 备注                                                      |
| -------------------- | ------------------------------------ | --------------------- | --------------------------------------------------------- |
| **Anthropic 官方**   | `https://api.anthropic.com`          | console.anthropic.com | Key 以 `sk-ant-` 开头                                     |
| **DeepSeek**         | `https://api.deepseek.com/anthropic` | platform.deepseek.com | 模型填 `deepseek-chat`/`deepseek-coder`，**不要填产品名** |
| **OfoxAI**           | `https://api.ofox.ai/anthropic`      | ofox.ai               | 聚合站，可路由 Claude/GPT/Gemini/DeepSeek                 |
| **Moonshot（Kimi）** | 见供应商文档                         | platform.moonshot.cn  | 模板 `moonshot`                                           |
| **智谱 ZAI（GLM）**  | 见供应商文档                         | open.bigmodel.cn      | 模板 `zai`                                                |
| **OpenRouter**       | `https://openrouter.ai/api/v1`       | openrouter.ai         | 注意确认是否为 Anthropic 兼容端点                         |
| **自定义中转站**     | 按中转站文档填写                     | 中转站后台            | 一般用 `https://你的域名/anthropic` 格式                  |

> 通用规则：中转站端点通常是 **`https://域名/anthropic`**（Anthropic Messages 格式）。如果供应商只提供 OpenAI 格式的 `/v1` 端点，Claude Code 无法直接使用。

### 8. 全局 vs 项目级配置

| 配置层级 | 文件位置                         | 生效范围   | ccswitch 管理 |
| -------- | -------------------------------- | ---------- | ------------- |
| 全局     | `~/.claude/settings.json`        | 所有项目   | ✅ 主要管理   |
| 项目级   | `项目目录/.claude/settings.json` | 仅当前项目 | ❌ 需手写     |

**项目级覆盖示例**（某项目固定用官方模型）：

```json
// 项目根目录/.claude/settings.json
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.anthropic.com",
    "ANTHROPIC_API_KEY": "sk-ant-xxx"
  }
}
```

项目级配置优先级高于全局，适合"特定项目用特定供应商"的场景。

## 第四阶段：CLI 版实操（进阶）

### 9. @aravhawk/cc-switch（profile 管理型）

**安装**：

```bash
npm install -g @aravhawk/cc-switch
# 或
pnpm add -g @aravhawk/cc-switch
```

**工作原理**：以「配置档案（profile）」为单位管理，切换 = 复制档案内容到 `~/.claude/settings.json`。

```
~/.cc-switch/
├── profiles/                  # 所有已保存的配置档案
│   ├── default/settings.json
│   ├── work/settings.json     # 工作环境配置
│   └── personal/settings.json # 个人环境配置
└── state.json                 # 记录当前激活的 profile
```

**命令速查**：

```bash
cc-switch                                # 交互模式（列表/切换/创建/删除/重命名）
cc-switch <profile-name>                 # 快速切换
cc-switch --create <profile-name>        # 从当前 ~/.claude/settings.json 创建档案
cc-switch --create <profile-name> --template moonshot --api-key <key>  # 用模板创建
cc-switch --list                         # 列出所有档案
```

**内置模板**：`anthropic`（官方）、`moonshot`（Kimi）、`zai`（GLM）、`minimax`。使用模板创建时会自动填入对应的 Base URL 字段。

### 10. ccswitch-tui（预设最多的 TUI 版）

```bash
npm install -g ccswitch-tui
ccswitch-tui
```

- 内置 **55+ Claude Code 供应商预设**（Anthropic、OpenRouter、DeepSeek、智谱 GLM、Kimi、硅基流动、火山引擎等）
- 快捷键：`↑/↓` 导航、`Enter` 选择、`a` 添加、`e` 编辑、`d` 删除、`q/Esc` 退出
- 配置写入 `~/.claude/settings.json` 的 env 区；自定义配置存于 `~/.ccswitch-cli/providers.json`

### 11. @wcldyx/claude-code-switcher（`cc` 命令）

```bash
npm install -g @wcldyx/claude-code-switcher

cc                  # 打开供应商选择界面
cc <供应商名>        # 直接切换
cc add              # 添加供应商（引导式）
cc list             # 列出所有供应商
cc current          # 查看当前生效的供应商
cc edit             # 编辑供应商
cc remove           # 删除供应商
```

- 支持 **API Key / Auth Token / OAuth Token** 三种认证方式
- 可配置 Opus/Sonnet/Haiku 模型别名
- 配置存于 `~/.cc-config.json`
- 切换时自动检测环境变量冲突并备份（`settings.backup-YYYYMMDD_HHmmss.json`）

### 12. @olayemii/ccswitch（多账号/多 shell 型）

```bash
npm install -g @olayemii/ccswitch   # 需 Node ≥ 18

ccswitch add          # 引导式添加供应商
ccswitch <name>       # 全局切换（整机生效）
ccswitch env <name>   # 导出当前 shell 环境变量（per-shell 切换）
ccswitch list         # 列出所有供应商
ccswitch current      # 查看当前配置
ccswitch doctor       # 诊断配置问题
ccswitch token        # 捕获 OAuth token
```

- 支持 `login`（官方登录）/ `api-key` / `bedrock` / `bedrock-key` / `custom`（自定义 Anthropic 兼容端点）五种类型
- **per-shell 切换**：不同终端可以并行使用不同供应商/账号，互不影响

### 13. @xwm111/ccs（附带更新检查）

```bash
npm i -g @xwm111/ccs
# 或免安装：npx @xwm111/ccs

ccs                              # 交互菜单
ccs cs --list                    # 列出端点配置
ccs cs <name>                    # 直接切换
ccs check-updates                # 检查 Claude Code 和 ccs 的更新
ccs uninstall                    # 卸载
ccs --lang zh-CN                 # 中文界面
```

配置存于 `~/.ccs`。

### 14. 从零到切换成功（全流程）

```
目标：安装 Claude Code → 通过 CC-Switch 切换到 DeepSeek → 验证生效
```

**Step 1：安装 Claude Code**

```bash
npm install -g @anthropic-ai/claude-code
# 或使用官方安装脚本 / 桌面版（Windows 可用 claude.ai/code 下载）
```

- 首次打开会提示选择供应商管理页面

**Step 3：添加 DeepSeek 供应商**

```
供应商名称：DeepSeek

请求地址：  https://api.deepseek.com/anthropic   ← 注意 anthropic 后缀
模型：      deepseek-chat
→ 点「添加」
```

**Step 4：切换并验证**

```bash
# 回到项目目录，启动 Claude Code
cd my-project
claude

# 会话中输入：
/status
# 看到 "API: https://api.deepseek.com/anthropic" 即切换成功

# 测试一次对话验证连通性
> 你好，请回复"连接成功"
```

**Step 5：多供应商自由切换**

```
需要切回官方时：
打开 CC-Switch → 选中「Anthropic 官方」→ 点「使用」
→ 关闭当前 claude 会话 → 重新运行 claude → /status 验证
```

### 15. 验证「切换生效」的完整清单

| 检查项           | 方法                                         | 不通过的常见原因                   |
| ---------------- | -------------------------------------------- | ---------------------------------- |
| Base URL 正确    | `/status` 查看 API 字段                      | 末尾多了 `/`、用错端点格式         |
| 认证令牌完整     | 检查 settings.json 中 Key 无空格/换行        | 复制时截断                         |
| 会话已重启       | 切换后重新运行 `claude`                      | 旧会话不重读配置                   |
| 无环境变量覆盖   | `echo $ANTHROPIC_BASE_URL`（shell）          | shell 中 export 过，覆盖了全局配置 |
| 项目级配置未覆盖 | 检查项目 `.claude/settings.json`             | 项目级优先级更高                   |
| 模型名有效       | 对话测试 / 供应商文档核对                    | 填了供应商不认的模型名             |
| 网络可达         | `curl -I https://api.deepseek.com/anthropic` | 网络/防火墙问题                    |

## 第六阶段：常见问题排查（实战）

### Q1: 401 / Authentication error（认证失败）

```
症状：切换后所有请求都返回 401
原因排查：
1. API Key 复制不完整（最常见的：尾部带换行/空格被截断）
   → 重新在供应商后台复制完整 Key，粘贴时检查首尾
2. Key 已失效/过期
   → 去供应商后台重新生成
3. 认证方式不对（用 API_KEY 的位置填了 AUTH_TOKEN，或反之）
   → 中转站一般用 ANTHROPIC_AUTH_TOKEN，官方用 ANTHROPIC_API_KEY
```

### Q2: 连接超时 / 请求失败

```
原因排查：
1. 请求地址末尾多了斜杠
   ❌ https://api.ofox.ai/anthropic/
   ✅ https://api.ofox.ai/anthropic
2. 误用 OpenAI 协议端点（/v1）
   ❌ https://api.deepseek.com/v1        ← 这是 OpenAI 格式
   ✅ https://api.deepseek.com/anthropic ← Anthropic 格式
3. 网络不通（公司代理、防火墙）
   → curl 测试连通性；配置代理环境变量
```

### Q3: 切换了但 /status 显示还是旧地址

```
原因：
1. Claude Code 会话未重启
   → 退出 claude 重新运行
2. shell 环境变量覆盖了全局配置
   → 检查 export | grep ANTHROPIC
   → unset ANTHROPIC_BASE_URL 或关闭对应 shell
3. 项目级 settings.json 覆盖
   → 检查项目 .claude/settings.json
4. 多个切换器混用互相覆盖
   → 只保留一个切换工具
```

### Q4: 模型不存在 / Model not found

```
原因：填了供应商不支持的模型名
示例：
❌ "deepseek-v3.1"        ← DeepSeek API 不认产品名
✅ "deepseek-chat"        ← 认 API 模型名
❌ "claude-sonnet-4-6" 在 DeepSeek 端点上
✅ 按供应商文档填对应模型

解决：查看供应商的模型列表文档，或在 /status 后测试对话
```

### Q5: VSCode 集成下不生效

```
原因：VSCode 中 Claude Code 扩展的会话同样不重读配置
解决：
1. 切换后关闭并重新打开 VSCode 终端中的 claude 会话
2. 或完全重启 VSCode
3. 无需安装任何插件 —— ccswitch 改的是全局 settings.json
```

### Q6: 切换器工具本身报错

```
1. 权限问题（Linux/macOS）
   → 检查 ~/.claude/settings.json 权限：chmod 600
2. 配置文件损坏
   → 用工具自带 backup/restore 恢复（各工具都支持）
   → 或手动修复 settings.json 的 JSON 语法
3. Node 版本过低
   → @olayemii/ccswitch 需要 Node ≥ 18
```

## 第七阶段：安全与最佳实践（高级）

### 16. API Key 安全

| 风险     | 防护措施                                                                |
| -------- | ----------------------------------------------------------------------- |
| Key 泄露 | 不要把 settings.json 提交到 Git；`.claude/` 加入 `.gitignore`           |
| 误传     | 中转站 Key 只在可信供应商间使用，聚合站留意隐私条款                     |
| 团队共享 | 个人 Key 不要共享；团队场景用管理员统一签发的中转站 Key                 |
| 文件权限 | Linux/macOS：`chmod 600 ~/.claude/settings.json`                        |
| 余额监控 | 定期查看供应商后台用量；可配合仓库内 `deepseek-balance.js` 脚本查询余额 |

### 17. 配置管理最佳实践

```
1. 只用一个切换工具
   多工具混用会互相覆盖 settings.json，导致配置漂移

2. 切换前先备份
   大部分切换器自动备份（@wcldyx 自动生成 backup 文件）
   手动备份：cp ~/.claude/settings.json ~/.claude/settings.json.bak

3. 命名规范
   供应商档案名用「用途_供应商」格式：work-deepseek / personal-anthropic

4. 切换后立即验证
   养成习惯：切换 → 重启 claude → /status → 测试对话 → 确认无误再继续

5. 保留官方配置档案
   永远保留一个 Anthropic 官方 profile，出问题时一键切回

6. 项目级配置最小化
   只有确实需要固定供应商的项目才写项目级 settings.json
```

### 18. 进阶：直接脚本化切换（脱离 GUI）

```bash
# 自定义 shell 函数快速切换（示例）
ccs() {
  case "$1" in
    deepseek)
      cat > ~/.claude/settings.json <<'EOF'
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.deepseek.com/anthropic",
    "ANTHROPIC_AUTH_TOKEN": "$DEEPSEEK_API_KEY",
    "ANTHROPIC_MODEL": "deepseek-chat"
  }
}
EOF
      ;;
    official)
      cat > ~/.claude/settings.json <<'EOF'
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.anthropic.com",
    "ANTHROPIC_API_KEY": "$ANTHROPIC_API_KEY"
  }
}
EOF
      ;;
    *)
      echo "用法: ccs deepseek | official"
      ;;
  esac
  echo "已切换，请重启 claude 并运行 /status 验证"
}
```

```bash
# 验证脚本：查看当前生效的供应商
cat ~/.claude/settings.json | grep -E "ANTHROPIC_BASE_URL|ANTHROPIC_AUTH_TOKEN|ANTHROPIC_API_KEY"
```
