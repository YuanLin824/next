# Claude Code 学习指南

> Anthropic 官方 CLI 编程智能体——终端原生的代码生成、重构、调试与自动化工具。难度递进式学习文档。

## 第一阶段：认识 Claude Code（入门）

### 1. Claude Code 是什么？

Claude Code 是 Anthropic 推出的**终端 AI 编程智能体**（Coding Agent），运行在命令行中，本质上是一个拥有完整文件系统读写权限和 Shell 执行能力的 Claude 模型。

```
Claude Code 的能力模型：

  自然语言输入
       │
       ▼
  ┌─────────────┐
  │ Claude Code │
  └──────┬──────┘
         │
    ┌────┼────┬────────┐
    ▼    ▼    ▼        ▼
  Read  Edit Write  Shell/Git   ← 四种核心工具
    │    │    │        │
    └────┴────┴────────┘
         ▼
    修改项目文件 + 执行命令 + git 操作
```

**核心特征：**

| 特征               | 说明                                        |
| ------------------ | ------------------------------------------- |
| **Anthropic 官方** | 由 Claude 模型团队开发维护，与 API 同步更新 |
| **终端原生**       | 全文件系统访问 + Shell 执行 + Git 集成      |
| **多模型支持**     | 支持 Claude Opus/Sonnet/Haiku/Fable 全系列  |
| **CLAUDE.md**      | 项目级 AI 指令文件，定义规范与上下文        |
| **权限系统**       | 四级安全模式，细粒度工具管控                |
| **MCP 扩展**       | 通过 MCP 协议接入外部工具与数据源           |
| **Hooks 系统**     | 在工具执行前后触发自定义脚本                |
| **跨平台**         | macOS / Linux / Windows（WSL 或 Git Bash）  |

**与其他工具的对比：**

| 工具            | 特点                                        | 适合            |
| --------------- | ------------------------------------------- | --------------- |
| **Claude Code** | Anthropic 官方、Claude 模型最强、权限细粒度 | 深度编码任务    |
| Reasonix        | DeepSeek 原生、前缀缓存降本                 | DeepSeek 用户   |
| Cursor          | 图形 IDE、补全体验好                        | 偏好 IDE 的用户 |
| GitHub Copilot  | 代码补全、多 IDE 支持                       | 轻量辅助编码    |

### 2. 安装

**前置环境：**

| 环境         | 下载                                | 说明                |
| ------------ | ----------------------------------- | ------------------- |
| Node.js ≥ 18 | [nodejs.org](https://nodejs.org/)   | 选择 LTS 版本       |
| Git          | [git-scm.com](https://git-scm.com/) | Windows 需 Git Bash |

```bash
# 验证环境
node --version    # ≥ v18
git --version     # 任意版本

# Windows：如遇 PowerShell 脚本执行限制
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# 安装 Claude Code
npm install -g @anthropic-ai/claude-code@stable

# 验证
claude --version
```

### 3. 启动与第一组对话

```bash
# 进入项目目录启动
cd ~/my-project
claude

# → 首次启动需登录 Anthropic 账号（浏览器 OAuth）
# → 或通过 API Key（见下文）

# 交互示例
# ▶ "这个项目是做什么的？"（分析项目结构）
# ▶ "帮我创建一个 Express 服务器"
# ▶ "运行 npm test 并修复失败的测试"
```

**API Key 方式（无需浏览器登录）：**

```bash
export ANTHROPIC_API_KEY=sk-ant-xxx...
claude
```

## 第二阶段：交互模式与日常工作流

### 4. 交互式对话（默认模式）

```bash
claude                  # 在当前目录启动
claude path/to/project  # 在指定目录启动
```

**日常交互示例：**

```
▶ 解释一下 src/utils.js 的设计思路
→ Read 文件 → 分析结构 → 给出解释

▶ 给 calculateTotal 函数写单元测试
→ Read 文件 → 识别函数签名 → 创建测试文件 → 运行 npm test

▶ 把所有 var 改成 const/let，跑一下测试确保没坏
→ Grep 搜索 var → 逐个替换 → 运行测试 → 修复 → 报告
```

**与 Agent 对话的技巧：**

- **说清楚预期产物**："建一个文件叫 xxx.js，内容是..."
- **给出约束**："不要修改任何测试文件""风格参考 src/ 下的现有代码"
- **分步推进**：先让它理解问题，再让它制定方案，最后执行
- **善用上下文**：`@文件名` 可以显式引用文件，`!命令` 可以内联执行 Shell

### 5. @-提及 —— 上下文引入

在对话中使用 `@` 引入文件、目录、URL：

```
▶ @src/components/Button.tsx 解释这个组件
→ 读取文件 → 分析结构 → 解释

▶ @src/app/ @package.json 分析项目架构
→ 读取目录下所有文件 + package.json → 综合分析

▶ @https://react.dev/reference/useEffect 按这个文档的建议修改我的代码
→ 获取网页内容 → 对照代码 → 给出建议
```

### 6. 权限系统与安全模式

Claude Code 有四级权限模式，启动时指定：

| 模式                  | 标志                             | 行为                                   |
| --------------------- | -------------------------------- | -------------------------------------- |
| **default**（默认）   | 默认                             | 大部分操作需确认，同一会话中可记忆选择 |
| **acceptEdits**       | `--permission-mode acceptEdits`  | 读文件自动放行，写/命令需确认          |
| **plan**              | `--permission-mode plan`         | 只读不写，无法执行 Shell 命令          |
| **bypassPermissions** | `--dangerously-skip-permissions` | ⚠️ 全自动不询问（仅限受控沙盒）        |

**细化工具权限：**

```bash
# 启动时只允许特定工具
claude --allowed-tools Read,Grep,Glob         # 只读模式

# 禁用高风险工具
claude --disallowed-tools Bash,Write           # 禁用写和执行
claude --disallowed-tools "Bash(npm publish)"  # 禁止发布

# CI 环境安全绕过
claude -p "审查代码" --dangerously-skip-permissions
```

### 7. 非交互模式（-p / --print）

`-p` 模式适合脚本、CI、管道场景：

```bash
# 基础用法
claude -p "src/ 下最大的 5 个文件是哪些？"

# 管道输入
cat main.ts | claude -p "解释这段代码在做什么"
git diff HEAD~1 | claude -p "审查这次变更，列出潜在 bug"

# JSON 输出（程序化消费）
git diff HEAD~1 | claude -p "列出所有破坏性变更" --output-format json

# 限制会话轮数
claude -p "修复所有 lint 错误" --max-turns 5

# 指定模型
claude -p "重构代码" --model claude-opus-4-8

# 添加额外上下文
claude -p "总结项目" --context "$(cat NOTES.md)"

# 注入一次性系统提示
claude -p "审查" --system-prompt "你是资深安全审计专家，只关注 OWASP Top 10"
```

### 8. 会话管理

| 命令               | 功能                 | 使用场景                |
| ------------------ | -------------------- | ----------------------- |
| `/clear`           | 清空对话上下文       | 话题切换、上下文过长    |
| `/compact [focus]` | 压缩会话保留关键信息 | Token 窗口逼近上限时    |
| `/context`         | 查看上下文窗口使用率 | 判断是否需要 `/compact` |
| `/cost`            | Token 消耗和费用     | 监控成本                |
| `/rename <name>`   | 重命名会话           | 给重要会话命名          |
| `/resume [name]`   | 恢复之前保存的会话   | 断联后继续              |
| `/rewind`          | 回退到上一个检查点   | 撤销 AI 的变更          |
| `/export`          | 导出对话为 Markdown  | 存档、分享              |
| `/branch [name]`   | 分支当前对话         | 尝试不同方案            |

## 第三阶段：配置与项目定制

### 9. CLAUDE.md —— 项目 AI 说明书

CLAUDE.md 是 Claude Code 最核心的项目配置机制——相当于给 AI 的"入职手册"。

```bash
/init        # 自动分析项目结构 → 生成 CLAUDE.md
```

**CLAUDE.md 样例：**

```markdown
# CLAUDE.md

## 项目概述

- Next.js 14 + TypeScript 全栈应用
- 数据库 PostgreSQL + Prisma ORM
- 部署在 Vercel

## 常用命令

npm run dev → 启动开发服务器
npm run test → 运行 vitest 测试
npx prisma generate → 生成 Prisma 客户端

## 代码规范

- 组件函数式 + Hooks，禁止 class
- 文件名 kebab-case，组件 PascalCase
- API 路由放在 src/app/api/
- 所有数据库操作通过 Prisma，禁止原始 SQL
- 每个函数必须有 JSDoc

## 禁止事项

- ❌ 不要引入 Redux（我们已用 zustand）
- ❌ 不要使用 any 类型
- ❌ 不要修改 .eslintrc
- ❌ 不要直接操作 production 数据库
```

> CLAUDE.md 提交到 Git，团队所有成员的 Claude Code 实例共享同一份指令。

### 10. settings.json —— 全局与项目配置

**配置层级（优先级从高到低）：**

1. 命令行 `--config` 指定的文件
2. 项目本地 `.claude/settings.local.json`
3. 项目 `.claude/settings.json`
4. 用户全局 `~/.claude.json`
5. 内置默认值

```json
{
  // ~/.claude.json —— 全局用户配置
  "model": "claude-sonnet-4-6",
  "theme": "dark"
}
```

```json
{
  // .claude/settings.json —— 项目共享配置（提交到 Git）
  "permissions": {
    "allow": ["Bash(npm test)", "Bash(npm run *)", "Bash(git:status)", "Bash(git:diff)"],
    "deny": ["Bash(rm -rf *)", "Bash(git push --force *)"]
  }
}
```

```json
{
  // .claude/settings.local.json —— 个人本地配置（不提交 Git）
  "model": "claude-opus-4-8",
  "permissions": {
    "allow": ["Bash(npm run dev)"]
  }
}
```

### 11. Hooks 系统 —— 工具前后自动执行

Hooks 是 Claude Code 最强大的自动化机制——在工具执行前后触发自定义命令：

```json
{
  // .claude/settings.local.json
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "command": "npm run format \"$FILE_PATH\""
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Bash(git commit *)",
        "command": "npm test && npm run lint"
      }
    ],
    "Notification": [
      {
        "matcher": "",
        "command": "osascript -e 'display notification \"Claude 任务完成\"'"
      }
    ]
  }
}
```

| Hook 类型      | 触发时机      | 典型用途            |
| -------------- | ------------- | ------------------- |
| `PreToolUse`   | 工具执行前    | 运行测试、lint 检查 |
| `PostToolUse`  | 工具执行后    | 自动格式化、通知    |
| `Notification` | 会话暂停/恢复 | 桌面推送            |
| `Stop`         | 会话结束      | 清理临时文件        |
| `SessionStart` | 会话开始      | 加载环境变量        |

## 第四阶段：扩展与集成

### 14. MCP 服务器 —— 连接外部工具

MCP（Model Context Protocol）是 Anthropic 定义的工具集成标准：

```bash
# 添加 MCP 服务器
claude mcp add playwright npx @playwright/mcp           # 浏览器自动化
claude mcp add github npx @anthropic/mcp-server-github  # GitHub API
claude mcp add filesystem npx @anthropic/mcp-server-filesystem /data  # 外部文件

# 管理
/mcp                                                  # 交互式管理界面
claude mcp list                                       # 列出所有 MCP
claude mcp remove playwright                          # 移除
```

**常用 MCP 服务器：**

| MCP Server                       | 能力                                   |
| -------------------------------- | -------------------------------------- |
| `@playwright/mcp`                | 浏览器自动化——打开网页、截图、操作 DOM |
| `@anthropic/mcp-server-github`   | GitHub Issue/PR 管理                   |
| `@anthropic/mcp-server-postgres` | 直接查询 PostgreSQL                    |
| `filesystem`                     | 访问项目外的文件目录                   |
| `docker`                         | 管理 Docker 容器                       |

### 15. 技能（Skills）系统

技能是预定义的专用工作流，通过 `/skill-name` 或 `/skill-name` 触发：

```bash
# 查看所有可用技能
/skills

# 内置技能示例
/init             # 生成 CLAUDE.md

/verify           # 验证变更是否按预期工作
```

**在 CLAUDE.md 中注册自定义技能：**

```markdown
## 自定义技能

- `/deploy` 依次执行: npm run build → scp dist/ → curl healthcheck
- `/changelog` 生成自上一 tag 以来的变更日志
```

### 16. 子代理（Subagents）—— 并行执行

Claude Code 可以启动子代理并行处理多个独立任务：

```bash
/agents              # 管理子代理

# 在对话中，Agent 自动判断是否需要启动子代理：
# ▶ "并行搜索这三个文件中的安全漏洞"
# → 启动 3 个子代理，各自分析一个文件 → 汇总结果
```

子代理适合：

- 并行搜索/分析多个文件
- 独立维度的审查（性能 vs 安全 vs 代码风格）
- 大规模重构中的并行任务

## 第五阶段：高级工作流

### 18. 代码审查（/review）

```bash
# 审查当前未提交的变更
/review

# 审查特定 commit
/review HEAD~3..HEAD

# 非交互式审查（CI）
git diff origin/main | claude -p "审查变更，输出 JSON 格式的发现列表" --output-format json
```

审查维度：

- **正确性**：逻辑错误、边界条件、空指针
- **安全性**：XSS、注入、敏感信息泄露
- **性能**：不必要的循环、大对象分配
- **可维护性**：命名、重复代码、函数长度

### 19. Plan 模式 —— 先规划后执行

```bash
claude --permission-mode plan       # 进入 plan 模式
```

Plan 模式下的工作流：

```
▶ "用 TypeScript 重构 src/utils.js"

Claude：
1. 分析文件依赖 → 列出影响范围
2. 制定迁移步骤：
   (a) 创建 tsconfig.json
   (b) 重命名 .js → .ts，添加类型注解
   (c) 更新 import 路径
   (d) 运行 tsc 类型检查
3. 等待你确认 → 逐步执行
```

> Plan 模式适合：大规模重构、新手不熟悉的代码库、需要审批的变更。

### 20. CI/CD 集成

```bash
# ====== GitHub Actions 示例 ======
- name: Claude Code Review
  run: |
    git diff origin/main...HEAD | \
    claude -p "审查这次 PR，列出所有正确性和安全性问题，JSON 格式输出" \
      --output-format json \
      --dangerously-skip-permissions \
      --max-turns 3
  env:
    ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}

# ====== 生成 CHANGELOG ======
git log --oneline v1.0..HEAD | claude -p "生成 CHANGELOG.md"

# ====== Pre-commit Hook ======
# .git/hooks/pre-commit
claude -p "审查暂存的变更是否安全" --dangerously-skip-permissions --max-turns 2
```

### 22. 提示前缀（Prompt Prefixes）

在对话开头添加前缀可以改变 Claude 的响应风格：

| 前缀              | 效果                          |
| ----------------- | ----------------------------- |
| `ULTRATHINK`      | 最长推理链（800-1200 字分析） |
| `L99`             | 更坚定、减少模棱两可          |
| `/skeptic`        | 先质疑前提，再回答            |
| `/ghost`          | 去除 AI 痕迹，更像人类写作    |
| `PERSONA: <角色>` | 扮演特定角色                  |

```
PERSONA: 资深后端 DBA L99 为什么我的查询变慢了？
/skeptic ULTRATHINK 微服务真的优于单体吗？
```

## 第六阶段：工程实践

### 23. 团队协作配置规范

```
项目仓库/
├── CLAUDE.md                  # ← 提交 Git，项目 AI 指令
├── .claude/
│   ├── settings.json          # ← 提交 Git，共享权限配置
│   ├── settings.local.json    # ← .gitignore，个人配置
│   └── memory/
│       ├── MEMORY.md          # ← 可选提交，共享记忆
│       └── ...
```

### 24. 最佳实践清单

| 实践                         | 说明                                       |
| ---------------------------- | ------------------------------------------ |
| 先 `/init` 再开始            | 生成 CLAUDE.md 让 AI 理解项目              |
| CLAUDE.md 要精要准           | 只写非默认、与常规做法不同的信息           |
| 小任务一步到位               | "修复这个 bug"而非"重写整个模块"           |
| 大任务先 plan                | 用 `--permission-mode plan` 让 AI 先出方案 |
| 善用 `@` 提及                | 显式引入文件/URL 减少歧义                  |
| CI 中用 `-p` + `--max-turns` | 限制轮数和输出格式                         |
| Solo 模式跑流程              | `--disallowed-tools "Bash(git push*)"`     |
| 定期 `/cost`                 | 关注 Token 消耗                            |
| settings.local.json 不入库   | 个人配置（API Key、本地路径）放 local      |
| 安全第一                     | 不确定时保持 review 模式，不盲目 bypass    |

### 25. 常见问题速查

| 问题                        | 原因                         | 解决方案                                  |
| --------------------------- | ---------------------------- | ----------------------------------------- |
| `claude: command not found` | npm 全局 bin 不在 PATH       | 检查 `npm root -g` 是否在 PATH 中         |
| 网络连接失败                | 需科学上网访问 Anthropic API | 配置 HTTPS_PROXY 或 API 代理              |
| 响应截断                    | Token 窗口已满               | `/compact` 压缩，或 `/clear` 重启         |
| 权限提示过多                | 未配置 allow 规则            | 设 `settings.json` 中 `permissions.allow` |
| CLAUDE.md 没被读取          | AI 未 detect 到              | 确保在项目根目录或显式 `@CLAUDE.md`       |
| MCP 连接失败                | MCP Server 未安装或路径错误  | `claude mcp list` 检查状态                |

| `claude --output-format json`   | JSON 格式输出                       |
| `claude mcp add`                | 添加 MCP 服务器                     |
| `claude --version`              | 版本信息                            |
