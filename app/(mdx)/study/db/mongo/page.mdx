## 第一阶段：认识 MongoDB（入门）

### 1. 什么是 MongoDB？

MongoDB 是一个**面向文档的 NoSQL 数据库**，2009 年首次发布。它将数据存储为类似 JSON 的 BSON（Binary JSON）文档，天然支持嵌套结构和数组。

```
MySQL 思维：               │     MongoDB 思维：
┌─────────────────────┐    │    {
│ users 表            │    │      "_id": ObjectId("..."),
│ id │ name │ email   │    │      "name": "Alice",
│ 1  │ Alice│ a@x.com │    │      "email": "alice@x.com",
└─────────────────────┘    │      "address": {              ← 嵌套文档
│ orders 表           │    │        "city": "Beijing",
│ id │ user_id│ total │    │        "zip": "100000"
│ 1  │ 1      │ 99    │    │      },
└─────────────────────┘    │      "tags": ["vip", "dev"]    ← 数组
                           │    }
```

### 2. 核心概念对照

| RDBMS（MySQL/PostgreSQL） | MongoDB                | 说明                           |
| ------------------------- | ---------------------- | ------------------------------ |
| Database                  | Database               | 数据库，一个实例可有多个       |
| Table                     | **Collection**（集合） | 存放文档的容器，无 Schema 约束 |
| Row                       | **Document**（文档）   | 一条记录，BSON 格式            |
| Column                    | **Field**（字段）      | 文档中的键值对                 |
| Primary Key               | `_id`                  | 自动生成 ObjectId，保证唯一    |
| JOIN                      | `$lookup` / 嵌入       | 不推荐频繁 JOIN                |
| Transaction               | Transaction            | 4.0+ 支持多文档事务            |

## 第二阶段：CRUD 操作（核心技能）

### 6. 文档与 BSON

MongoDB 内部使用 BSON（Binary JSON）存储，相比 JSON 多了更多数据类型：

| 类型                                      | 说明                      | 示例                                     |
| ----------------------------------------- | ------------------------- | ---------------------------------------- |
| ObjectId                                  | 12 字节唯一标识，自动生成 | `ObjectId("669abc...")`                  |
| String                                    | UTF-8 字符串              | `"hello"`                                |
| Number (int / double / Long / Decimal128) | 精确数值                  | `42`、`3.14`、`NumberLong("9999999999")` |
| Date                                      | UTC 时间                  | `new Date()`、`ISODate("2026-07-30")`    |
| Boolean                                   | 布尔值                    | `true`、`false`                          |
| Array                                     | 数组                      | `["a", "b"]`                             |
| Object / Null                             | 嵌套文档 / 空值           | `{ city: "BJ" }`、`null`                 |
| Binary Data                               | 二进制（文件/加密数据）   | `BinData(0, "...")`                      |

### 7. Insert —— 插入

```js
// 插入单条 → 返回 { acknowledged: true, insertedId: ... }
db.users.insertOne({
  name: "Alice",
  email: "alice@example.com",
  age: 25,
  tags: ["dev", "vue"],
  address: { city: "Beijing", zip: "100000" },
  createdAt: new Date(),
})

// 插入多条
db.users.insertMany([
  { name: "Bob", email: "bob@example.com", age: 30, tags: ["dev", "react"] },
  { name: "Charlie", email: "charlie@example.com", age: 28, tags: ["design"] },
])

// insert() 兼容单条 + 多条（已不推荐，用 insertOne/insertMany 更语义化）
db.users.insert({ name: "David", age: 35 })
```

**`_id` 策略：**

```js
// 不传 _id → MongoDB 自动生成 ObjectId（推荐）
db.users.insertOne({ name: "Eve" })
// → _id: ObjectId("669abc123def456789012345")

// 手动指定 _id → 任意类型均可，但必须唯一
db.users.insertOne({ _id: "user_001", name: "Frank" })

// ObjectId 天然包含时间戳
const oid = ObjectId("669abc123def456789012345")
oid.getTimestamp() // → ISODate("2026-07-20T10:30:00Z")
```

### 8. Find —— 查询

```js
// ========== 基础查询 ==========

// 查全部（返回游标，默认显示 20 条；输入 it 翻页）
db.users.find()
db.users.find().pretty() // 格式化输出

// 等值条件
db.users.find({ name: "Alice" })
db.users.find({ age: 25 })

// 比较操作符
db.users.find({ age: { $gte: 18 } }) // >= 18
db.users.find({ age: { $gt: 18, $lt: 30 } }) // 18 < age < 30
db.users.find({ status: { $ne: "banned" } }) // !=
db.users.find({ age: { $in: [25, 30, 35] } }) // IN
db.users.find({ age: { $nin: [25, 30] } }) // NOT IN

// 逻辑操作符
db.users.find({
  // AND（默认）
  status: "active",
  age: { $gte: 18 },
})
db.users.find({
  // OR
  $or: [{ status: "active" }, { age: { $lt: 18 } }],
})
db.users.find({
  // NOT
  age: { $not: { $gte: 18 } }, // 等价于 $lt 18
})

// 字段存在性
db.users.find({ email: { $exists: true } })
db.users.find({ phone: { $exists: false } })

// 类型匹配
db.users.find({ age: { $type: "int" } })

// 正则
db.users.find({ name: /^A/ }) // 以 A 开头
db.users.find({ name: /@example\.com$/i }) // 忽略大小写
```

**嵌套文档与数组查询：**

```js
// 嵌套文档（用点语法）
db.users.find({ "address.city": "Beijing" })

// 数组包含某值
db.users.find({ tags: "dev" })

// 数组包含全部指定值
db.users.find({ tags: { $all: ["dev", "vue"] } })

// 数组按索引匹配
db.users.find({ "tags.0": "dev" }) // 第一个元素是 "dev"

// 数组长度
db.users.find({ tags: { $size: 2 } })

// 数组中至少一个元素满足条件
db.users.find({ tags: { $elemMatch: { $in: ["dev", "ops"] } } })
```

**投影、分页与排序：**

```js
// 只返回指定字段（1=包含，0=排除；_id 默认包含需显式排除）
db.users.find({}, { name: 1, email: 1, _id: 0 })

// 分页
db.users.find().limit(10) // 前 10 条
db.users.find().skip(20).limit(10) // 跳过 20 条，取 10 条（第 3 页）

// 排序（1=升序，-1=降序）
db.users.find().sort({ age: -1 })
db.users.find().sort({ status: 1, age: -1 }) // 先按 status 升序，再按 age 降序

// 计数
db.users.countDocuments({ status: "active" }) // 精准（有 filter 时推荐）
db.users.estimatedDocumentCount() // 全表估算（快，可能不准）

// 去重
db.users.distinct("tags")
```

### 9. Update —— 更新

```js
// ========== 更新一条（匹配的第一条） ==========
db.users.updateOne(
  { name: "Alice" }, // filter
  { $set: { age: 26, email: "alice@new.com" } } // update
)

// ========== 更新多条（所有匹配的） ==========
db.users.updateMany({ status: "inactive" }, { $set: { status: "archived" } })

// ========== 替换整个文档（除 _id 外全部替换） ==========
db.users.replaceOne(
  { name: "Alice" },
  { name: "Alice", email: "new@x.com", age: 26, status: "active" }
)
```

**常用更新操作符：**

| 操作符          | 作用                           | 示例                                    |
| --------------- | ------------------------------ | --------------------------------------- |
| `$set`          | 设置字段值（字段不存在则创建） | `{ $set: { age: 30 } }`                 |
| `$unset`        | 删除字段                       | `{ $unset: { tmp: "" } }`               |
| `$inc`          | 数值递增/递减                  | `{ $inc: { score: 5, retries: -1 } }`   |
| `$rename`       | 重命名字段                     | `{ $rename: { "old": "new" } }`         |
| `$min` / `$max` | 只在小于/大于当前值时更新      | `{ $min: { lowScore: 50 } }`            |
| `$mul`          | 数值相乘                       | `{ $mul: { price: 1.1 } }`              |
| `$currentDate`  | 设为当前时间                   | `{ $currentDate: { updatedAt: true } }` |

**数组更新操作符：**

| 操作符            | 作用              | 示例                                        |
| ----------------- | ----------------- | ------------------------------------------- |
| `$push`           | 数组末尾追加      | `{ $push: { tags: "new" } }`                |
| `$push` + `$each` | 批量追加          | `{ $push: { tags: { $each: ["a","b"] } } }` |
| `$pull`           | 移除匹配元素      | `{ $pull: { tags: "old" } }`                |
| `$addToSet`       | 去重追加          | `{ $addToSet: { tags: "unique" } }`         |
| `$pop`            | 移除首(-1)或尾(1) | `{ $pop: { tags: 1 } }`                     |
| `$pullAll`        | 移除所有指定值    | `{ $pullAll: { tags: ["a","b"] } }`         |

```js
// upsert：匹配则更新，不匹配则插入
db.users.updateOne(
  { email: "new@example.com" }, // 按此条件查找
  { $set: { name: "NewUser", age: 25 } }, // 更新/插入的内容
  { upsert: true } // 开启 upsert
)
```

### 10. Delete —— 删除

```js
db.users.deleteOne({ name: "Alice" }) // 删一条（匹配的第一条）
db.users.deleteMany({ status: "inactive" }) // 删所有匹配的
db.users.deleteMany({}) // 删所有文档（保留集合与索引）
db.users.drop() // 直接删集合（更快，索引也会删掉）
db.dropDatabase() // 删整个数据库
```

> `deleteMany({})` vs `drop()`：deleteMany 逐条删除并触发监听器，慢但精细。drop 直接删除元数据，快但粗暴。

> **小结**：掌握以上 Insert / Find / Update / Delete 即可覆盖 80% 日常 CRUD 场景。

## 第三阶段：数据建模（设计决策）

### 11. MongoDB 数据建模的核心问题

关系型数据库教你"分开表 + JOIN"；MongoDB 问你：**嵌入还是引用？**

```
场景：用户 → 收货地址（一个用户有多个地址）

方案 A：嵌入（Embedded）             │  方案 B：引用（Reference）
{                                    │    {
  _id: 1,                            │      _id: 1,
  name: "Alice",                     │      name: "Alice",
  addresses: [                       │      address_ids: [101, 102]
    { city: "BJ", zip: "100000" },   │    }
    { city: "SH", zip: "200000" }    │
  ]                                  │
}                                    │
```

| 维度           | 嵌入                                      | 引用                                |
| -------------- | ----------------------------------------- | ----------------------------------- |
| **读性能**     | ✅ 一次查询拿全部数据                     | ❌ 可能需要多次查询（或 `$lookup`） |
| **写性能**     | ✅ 单次原子写入                           | ✅ 各自独立更新                     |
| **数据一致性** | ✅ 嵌入在一篇文档内天然原子               | ❌ 需跨文档事务                     |
| **数据冗余**   | ❌ 数据重复（如多个订单嵌入相同地址快照） | ✅ 无冗余                           |
| **扩展性**     | ❌ 文档不能超过 16MB                      | ✅ 不受限                           |
| **适用**       | 子数据不会独立查询、数量小且稳定          | 子数据会独立查询、数量大或多方共享  |

**决策口诀：**

- 一起读、一起写、不会无限增长 → **嵌入**
- 独立查询、多方关联、会无限增长 → **引用**

### 12. 常见关系建模

```js
// ===== 一对多（少的一方包含"多"的列表） =====
// 博客作者 → 文章 ID 列表
{
  _id: 1,
  name: "张坤杰",
  article_ids: [ObjectId("..."), ObjectId("...")]  // 引用式
}

// ===== 一对多（"多"的记录很少 & 嵌入） =====
// 用户 → 地址（一般就 2-5 个）
{
  _id: 1,
  name: "Alice",
  addresses: [                                      // 嵌入式
    { type: "home", city: "Beijing" },
    { type: "work", city: "Shanghai" }
  ]
}

// ===== 多对多 =====
// 学生 ↔ 课程（双向引用或中间集合）
// students: { _id, name, course_ids: [...] }
// courses: { _id, title, student_ids: [...] }
```

### 13. 文档大小限制

- 单文档最大 **16 MB**
- BSON 嵌套深度最多 **100 层**
- 数组理论上无上限，但索引每个数组元素 → 超大数组会严重影响写入性能

## 第四阶段：聚合管道（数据分析）

### 14. 聚合管道的概念

聚合管道（Aggregation Pipeline）是 MongoDB 做数据分析的核心工具。数据流经一系列**阶段**（stage），每个阶段对数据进行一次加工，最终输出结果。

```
集合 → [$match] → [$group] → [$sort] → [$project] → 结果
     过滤       分组聚合     排序       字段裁剪
```

```js
// 示例：统计每个城市的活跃用户数和平均年龄
db.users.aggregate([
  // 阶段 1: 只保留活跃用户
  { $match: { status: "active" } },

  // 阶段 2: 按城市分组
  {
    $group: {
      _id: "$address.city", // 分组键
      count: { $sum: 1 }, // 计数
      avgAge: { $avg: "$age" }, // 平均年龄
      names: { $push: "$name" }, // 收集名字
    },
  },

  // 阶段 3: 按人数降序
  { $sort: { count: -1 } },

  // 阶段 4: 裁剪输出字段
  {
    $project: {
      _id: 0,
      city: "$_id",
      count: 1,
      avgAge: { $round: ["$avgAge", 1] },
    },
  },

  // 阶段 5: 只看前 10 个城市
  { $limit: 10 },
])
```

### 15. 常用管道阶段速览

| 阶段         | 作用                 | SQL 类比                 |
| ------------ | -------------------- | ------------------------ |
| `$match`     | 过滤文档             | `WHERE`                  |
| `$group`     | 分组聚合             | `GROUP BY`               |
| `$sort`      | 排序                 | `ORDER BY`               |
| `$project`   | 字段选择/计算/重命名 | `SELECT`                 |
| `$limit`     | 取前 N 条            | `LIMIT`                  |
| `$skip`      | 跳过前 N 条          | `OFFSET`                 |
| `$lookup`    | 左外关联另一集合     | `LEFT JOIN`              |
| `$unwind`    | 数组展开为多行       | `UNNEST`                 |
| `$addFields` | 添加新字段           | 计算列                   |
| `$count`     | 计数输出             | `COUNT`                  |
| `$facet`     | 多维度并行聚合       | 多个 `GROUP BY` 一次完成 |
| `$bucket`    | 按区间分桶           | `CASE WHEN` 区间分组     |

### 16. 常用聚合操作符

```js
// 在 $group 中使用：
{
  $sum: 1
} // 计数
{
  $sum: "$price"
} // 求和
{
  $avg: "$score"
} // 平均
{
  $min: "$price"
} // 最小值
{
  $max: "$price"
} // 最大值
{
  $first: "$name"
} // 每组第一个
{
  $last: "$name"
} // 每组最后一个
{
  $push: "$name"
} // 收集为数组
{
  $addToSet: "$tag"
} // 去重收集
{
  $stdDevPop: "$score"
} // 标准差
```

### 17. $lookup —— 关联查询

```js
// 订单关联用户信息（类似 LEFT JOIN）
db.orders.aggregate([
  {
    $lookup: {
      from: "users", // 被关联的集合
      localField: "user_id", // orders 中的关联字段
      foreignField: "_id", // users 中的关联字段
      as: "user", // 结果存入的字段（数组）
    },
  },
  // user 字段是数组 → 展开为对象（一对一场景）
  { $unwind: "$user" },

  // 裁剪字段
  {
    $project: {
      _id: 1,
      total: 1,
      "user.name": 1,
      "user.email": 1,
    },
  },
])

// 带条件的 $lookup（管道式，MongoDB 5.0+）
db.orders.aggregate([
  {
    $lookup: {
      from: "users",
      let: { uid: "$user_id" },
      pipeline: [
        {
          $match: {
            $expr: { $eq: ["$_id", "$$uid"] },
            status: "active", // 只关联活跃用户
          },
        },
        { $project: { name: 1, email: 1 } },
      ],
      as: "user",
    },
  },
])
```

### 18. $facet —— 多维度并行聚合

```js
// 一次请求返回多个统计维度
db.products.aggregate([
  {
    $facet: {
      // 维度 1：按类目统计
      byCategory: [
        { $group: { _id: "$category", count: { $sum: 1 }, avgPrice: { $avg: "$price" } } },
        { $sort: { count: -1 } },
      ],
      // 维度 2：价格区间分布
      priceRanges: [
        {
          $bucket: {
            groupBy: "$price",
            boundaries: [0, 50, 100, 500, 1000, 10000],
            default: "10000+",
            output: { count: { $sum: 1 } },
          },
        },
      ],
      // 维度 3：总览
      overview: [
        {
          $group: {
            _id: null,
            totalProducts: { $sum: 1 },
            avgPrice: { $avg: "$price" },
            minPrice: { $min: "$price" },
            maxPrice: { $max: "$price" },
          },
        },
      ],
    },
  },
])
```

## 第五阶段：索引与性能优化

### 19. 索引基础

```js
// 创建索引
db.users.createIndex({ email: 1 }) // 单字段（1=升序）
db.users.createIndex({ email: 1 }, { unique: true }) // 唯一索引
db.users.createIndex({ status: 1, age: -1 }) // 复合索引
db.users.createIndex({ "address.city": 1 }) // 嵌套字段索引
db.users.createIndex({ tags: 1 }) // 数组字段索引（多键索引）

// 查看索引
db.users.getIndexes()

// 删除索引
db.users.dropIndex("email_1") // 按名称删
db.users.dropIndexes() // 删全部非 _id 索引
```

**复合索引的 ESR 规则（设计索引最关键的一条）：**

```
创建复合索引时，字段顺序应为：
E (Equality)  →  S (Sort)  →  R (Range)
等值查询字段  →  排序字段  →  范围查询字段
```

```js
// 查询：{ city: "BJ", age: { $gte: 18 } }  排序：{ createdAt: -1 }
// 最优索引：
db.users.createIndex({ city: 1, createdAt: -1, age: 1 })
//                      └─ E ─┘  └── S ────┘  └─ R ─┘
```

### 20. 特殊索引

```js
// TTL 索引：文档到期自动删除（适合 session、验证码、临时数据）
db.sessions.createIndex(
  { createdAt: 1 },
  { expireAfterSeconds: 3600 } // 1 小时后自动删除
)

// 全文索引
db.posts.createIndex({ title: "text", content: "text" })
db.posts.find({ $text: { $search: "MongoDB 性能优化" } })

// 地理空间索引
db.places.createIndex({ location: "2dsphere" })
db.places.find({
  location: {
    $near: {
      $geometry: { type: "Point", coordinates: [116.4, 39.9] },
      $maxDistance: 5000, // 5km 内
    },
  },
})
```

### 21. explain() —— 查询计划分析

```js
// 查看查询是否用了索引
db.users.find({ email: "alice@example.com" }).explain("executionStats")

// 关键指标解读：
// "stage": "IXSCAN"         ← ✅ 用了索引扫描
// "stage": "COLLSCAN"       ← ❌ 全表扫描，需要优化
// "totalDocsExamined": 0    ← 扫描的文档数，越小越好
// "nReturned": 100           ← 返回的文档数
// "executionTimeMillis": 5   ← 执行时间（毫秒）
```

**索引优化黄金法则：totalDocsExamined ≈ nReturned 最佳；totalDocsExamined >> nReturned 则索引不够精准。**

## 第六阶段：安全、备份与运维

### 22. 用户与权限管理

MongoDB 的角色体系：

| 角色                                 | 作用域      | 权限                 |
| ------------------------------------ | ----------- | -------------------- |
| `root`                               | 所有数据库  | 超级管理员           |
| `userAdmin` / `userAdminAnyDatabase` | 单库 / 全库 | 管理用户和角色       |
| `readWrite`                          | 单库        | 读写数据             |
| `read`                               | 单库        | 只读数据             |
| `dbAdmin`                            | 单库        | 索引管理、统计、清理 |
| `clusterAdmin`                       | 集群        | 副本集/分片管理      |
| `backup` / `restore`                 | 全库        | 备份 / 恢复          |

```js
// 查看所有用户
db.getUsers()                // 当前库
show users                   // 同上

// 创建用户
db.createUser({
  user: "app_user",
  pwd: "strong_password",
  roles: [
    { role: "readWrite", db: "my_app" },
    { role: "dbAdmin", db: "my_app" }
  ]
})

// 更新密码
db.updateUser("app_user", { pwd: "new_password" })

// 授予/撤销角色
db.grantRolesToUser("app_user", [{ role: "read", db: "analytics" }])
db.revokeRolesFromUser("app_user", [{ role: "dbAdmin", db: "my_app" }])

// 删除用户
db.dropUser("app_user")
```

### 23. 备份与恢复

```bash
# 全量备份（二进制 BSON，恢复最快）
mongodump --uri="mongodb://admin:pass@localhost:27017" --out=/backup/$(date +%Y%m%d)
mongodump --uri="mongodb://localhost:27017" --db=my_app --out=/backup/

# 恢复

mongorestore --uri="mongodb://localhost:27017" --db=my_app --drop /backup/my_app/
# --drop：恢复前删除已有数据（保证和备份时一致）

# JSON 导入导出
mongoexport --uri="mongodb://localhost:27017/my_app" --collection=users --out=users.json
mongoimport --uri="mongodb://localhost:27017/my_app" --collection=users --file=users.json
```

### 24. 副本集（Replica Set）概念

副本集是 MongoDB 的高可用方案：多个节点保存相同数据，主节点故障时自动选举新主。

```
┌──────────────────────────────────────┐
│           Replica Set "rs0"          │
│                                      │
│  ┌─────────┐     ┌────────────┐      │
│  │ Primary │────▶│Secondary   │      │
│  │ (读写)  │     │ (只读备份) │      │
│  └─────────┘     └────────────┘      │
│       │                              │
│       │          ┌─────────┐         │
│       └─────────▶│ Arbiter │         │
│                  │(仅投票) │         │
│                  └─────────┘         │
└──────────────────────────────────────┘
```

> 生产环境最小配置：1 Primary + 2 Secondary（或 1 Primary + 1 Secondary + 1 Arbiter）。

## 第七阶段：应用开发与最佳实践

### 26. Node.js 中使用 MongoDB

```js
// Native Driver —— 最贴近数据库，性能最优
const { MongoClient } = require("mongodb")

const client = new MongoClient("mongodb://app_user:pass@localhost:27017/my_app")

async function main() {
  await client.connect()
  const db = client.db("my_app")
  const users = db.collection("users")

  // CRUD
  await users.insertOne({ name: "Alice", email: "alice@x.com", age: 25 })
  const result = await users
    .find({ age: { $gte: 18 } })
    .sort({ age: -1 })
    .limit(10)
    .toArray()

  console.log(result)
}
main().finally(() => client.close())

// Mongoose ODM —— 提供 Schema、校验、中间件
const mongoose = require("mongoose")

const userSchema = new mongoose.Schema({
  name: { type: String, required: true },
  email: { type: String, required: true, unique: true },
  age: { type: Number, min: 0, max: 150 },
  tags: [String],
  address: {
    city: String,
    zip: String,
  },
  createdAt: { type: Date, default: Date.now },
})

const User = mongoose.model("User", userSchema)

// 连接
await mongoose.connect("mongodb://app_user:pass@localhost:27017/my_app")

// 查询（Mongoose 风格，比 Native Driver 更简洁）
const activeUsers = await User.find({ age: { $gte: 18 } })
  .select("name email")
  .sort({ createdAt: -1 })
  .limit(10)
```

### 27. 事务

MongoDB 4.0+ 支持多文档事务（仅在副本集中可用）：

```js
// Mongoose
const session = await mongoose.startSession()
session.startTransaction()

try {
  // 从 A 账户扣款
  await Account.updateOne({ _id: "A" }, { $inc: { balance: -100 } }, { session })
  // 向 B 账户转入
  await Account.updateOne({ _id: "B" }, { $inc: { balance: 100 } }, { session })

  await session.commitTransaction()
  console.log("转账成功")
} catch (err) {
  await session.abortTransaction()
  console.log("转账失败，已回滚")
} finally {
  session.endSession()
}
```

> **注意**：事务有性能代价。优先通过文档设计（嵌入）避免跨文档事务；只有确实需要 ACID 时才使用。

### 28. 常见陷阱与最佳实践

| 陷阱                           | 说明                                     | 正确做法                                       |
| ------------------------------ | ---------------------------------------- | ---------------------------------------------- |
| 所有查询都不建索引             | 全表扫描（COLLSCAN），千万级数据慢到超时 | 按查询模式建立索引，定期 `explain`             |
| 超大数组（10万+ 元素）         | 每次更新数组可能移动整个文档             | 用引用式建模，把大数组拆到独立集合             |
| 无限制的 `find()`              | 默认返回全部文档到内存，OOM              | 始终 `.limit()`，或用游标逐批处理              |
| 忘记 `_id` 的索引              | `_id` 已自带了唯一索引——创建其他索引即可 | 不要为 `_id` 重复创建索引                      |
| 嵌入文档无限增长               | 单文档 16MB 限制                         | 预估大小，超过 1MB 考虑引用                    |
| 开发环境没有认证               | 所有人无密码连接                         | Docker 启动时启用 `MONGO_INITDB_ROOT_USERNAME` |
| 应用中使用 `find()` 不加 limit | 可能导致内存溢出                         | 永远 `.limit(N)`                               |

### 29. 速查表

**CRUD：**

| 操作     | 命令                                       |
| -------- | ------------------------------------------ |
| 插入一条 | `db.coll.insertOne({...})`                 |
| 插入多条 | `db.coll.insertMany([...])`                |
| 查询     | `db.coll.find({...})`                      |
| 查一条   | `db.coll.findOne({...})`                   |
| 更新一条 | `db.coll.updateOne({...}, {$set: {...}})`  |
| 更新多条 | `db.coll.updateMany({...}, {$set: {...}})` |
| 删除一条 | `db.coll.deleteOne({...})`                 |
| 删除多条 | `db.coll.deleteMany({...})`                |
| 删集合   | `db.coll.drop()`                           |

**查询操作符：**

| 操作符         | 含义            | 示例                         |
| -------------- | --------------- | ---------------------------- |
| `$eq`          | 等于            | `{age: {$eq: 25}}`           |
| `$ne`          | 不等于          | `{status: {$ne: "banned"}}`  |
| `$gt` / `$gte` | 大于 / 大于等于 | `{age: {$gte: 18}}`          |
| `$lt` / `$lte` | 小于 / 小于等于 | `{age: {$lt: 60}}`           |
| `$in` / `$nin` | 在/不在列表中   | `{city: {$in: ["BJ","SH"]}}` |
| `$and`         | 逻辑与          | `{$and: [{...}, {...}]}`     |
| `$or`          | 逻辑或          | `{$or: [{...}, {...}]}`      |
| `$not`         | 逻辑非          | `{age: {$not: {$gte: 18}}}`  |
| `$exists`      | 字段存在        | `{phone: {$exists: true}}`   |
| `$regex`       | 正则匹配        | `{name: {$regex: /^A/}}`     |
