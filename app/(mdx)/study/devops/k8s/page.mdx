## 第一阶段：概念与安装（入门）

### 1. 什么是 Kubernetes？

K8s 是**容器编排平台**，自动管理容器的部署、伸缩和运维。

```
物理/虚拟机集群
├── Master（控制平面）
│   ├── API Server   ← 集群统一入口
│   ├── Scheduler    ← 调度 Pod 到哪个 Node
│   ├── Controller   ← 维持期望状态
│   └── etcd         ← 集群数据存储
└── Worker Node × N
    ├── kubelet      ← 节点代理
    ├── kube-proxy   ← 网络规则
    └── Container Runtime（Docker/containerd）
```

## 第二阶段：kubectl 与基础操作（会用 K8s）

### 6. 运行第一个 Pod

```bash
# 运行 Nginx
kubectl run nginx --image=nginx:alpine

# 查看
kubectl get pods
kubectl get pods -o wide          # 显示 IP 和 Node
kubectl describe pod nginx        # 详细信息（事件/状态）
kubectl logs nginx                # 查看日志
kubectl logs -f nginx             # 实时日志

# 进入容器
kubectl exec -it nginx -- /bin/sh

# 端口转发（本地 → Pod）
kubectl port-forward pod/nginx 8080:80
# 浏览器: http://localhost:8080

# 删除
kubectl delete pod nginx
```

### 7. 核心资源速查

| 资源       | 缩写   | 作用                         |
| ---------- | ------ | ---------------------------- |
| Pod        | po     | 最小部署单元（1 到多个容器） |
| Deployment | deploy | 管理 Pod 副本 + 滚动更新     |
| Service    | svc    | 为 Pod 提供稳定 IP/DNS       |
| ConfigMap  | cm     | 非敏感配置                   |
| Secret     | —      | 敏感数据（密码/Token）       |
| Namespace  | ns     | 逻辑隔离                     |
| Ingress    | ing    | HTTP/HTTPS 路由              |

### 8. Deployment — 无状态应用的标准部署

```bash
# 创建 Deployment
kubectl create deployment my-app --image=nginx:alpine --replicas=3

# 查看
kubectl get deploy
kubectl get pods -l app=my-app    # 按标签过滤

# 更新镜像
kubectl set image deploy/my-app nginx=nginx:1.25

# 滚动更新状态
kubectl rollout status deploy/my-app

# 伸缩
kubectl scale deploy/my-app --replicas=5

# 回滚
kubectl rollout undo deploy/my-app

# 删除
kubectl delete deploy my-app
```

### 9. Service — 暴露应用

```bash
# 创建 Service（集群内访问）
kubectl expose deploy my-app --port=80 --target-port=80 --type=ClusterIP

# 创建 NodePort（外部可通过 NodeIP:端口 访问）
kubectl expose deploy my-app --port=80 --type=NodePort

# 查看
kubectl get svc
kubectl describe svc my-app
```

| Service 类型 | 访问方式           | 场景               |
| ------------ | ------------------ | ------------------ |
| ClusterIP    | 集群内部 IP        | 服务间通信（默认） |
| NodePort     | NodeIP:30000-32767 | 开发调试           |
| LoadBalancer | 云厂商 LB          | 生产外部访问       |

### 10. Namespace — 环境隔离

```bash
kubectl create ns dev
kubectl create ns staging
kubectl create ns prod

kubectl get pods -n dev
kubectl config set-context --current --namespace=dev  # 切换默认命名空间
```

> **小结**: 能用 kubectl 管理 Pod/Deployment/Service/Namespace，掌握 CRUD 操作。

## 第三阶段：YAML 声明式配置（核心技能）

### 11. 声明式 vs 命令式

```bash
# 命令式（一步步告诉 K8s 做什么）
kubectl run nginx --image=nginx
kubectl expose deploy nginx --port=80

# 声明式（描述期望状态，K8s 自动达到）— 推荐
kubectl apply -f deployment.yaml
```

### 12. Deployment YAML 模板

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend
  labels: { app: frontend }
spec:
  replicas: 3
  selector:
    matchLabels: { app: frontend }
  template:
    metadata:
      labels: { app: frontend }
    spec:
      containers:
        - name: nginx
          image: registry.example.com/frontend:1.0.0
          ports: [{ containerPort: 80 }]
          resources:
            requests: { cpu: 100m, memory: 128Mi }
            limits: { cpu: 500m, memory: 256Mi }
```

### 13. Service YAML

```yaml
apiVersion: v1
kind: Service
metadata:
  name: frontend-svc
spec:
  selector: { app: frontend }
  ports: [{ port: 80, targetPort: 80 }]
  type: ClusterIP
```

### 14. 生成 YAML 的技巧

```bash
# Dry-run 生成模板
kubectl create deploy my-app --image=nginx --dry-run=client -o yaml > deploy.yaml

# 导出已有资源
kubectl get deploy my-app -o yaml

# 应用/删除
kubectl apply -f deploy.yaml
kubectl delete -f deploy.yaml
kubectl apply -f ./k8s/  # 应用整个目录
```

> **小结**: 能用 YAML 定义 Deployment 和 Service，理解 `kubectl apply -f` 的工作方式。

## 第四阶段：Pod 深度理解

### 15. Pod 生命周期

```
Pending → Running → Succeeded/Failed
                ↳ CrashLoopBackOff（崩溃重启循环）
                ↳ ImagePullBackOff（拉镜像失败）
```

### 16. 多容器 Pod（Sidecar 模式）

```yaml
spec:
  containers:
    - name: app
      image: my-app:latest
    - name: log-shipper # Sidecar: 收集日志
      image: fluentd:latest
      volumeMounts:
        - name: logs
          mountPath: /var/log/app
  volumes:
    - name: logs
      emptyDir: {}
```

### 17. Init Container（初始化容器）

```yaml
spec:
  initContainers:
    - name: wait-for-db
      image: busybox
      command: ["sh", "-c", "until nc -z db 5432; do sleep 2; done"]
  containers:
    - name: app
      image: my-app
```

### 18. 健康检查 — 探针

```yaml
livenessProbe: # 存活探针：失败 → 重启容器
  httpGet:
    path: /health
    port: 80
  initialDelaySeconds: 15
  periodSeconds: 20

readinessProbe: # 就绪探针：失败 → 从 Service 摘除
  httpGet:
    path: /ready
    port: 80
  initialDelaySeconds: 5
  periodSeconds: 10
```

> **小结**: 理解 Pod 生命周期和 Sidecar/InitContainer/探针三种进阶模式。

### 20. Secret — 敏感数据

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: app-secret
type: Opaque
stringData: # 明文（自动 Base64 编码）
  DB_PASSWORD: "super-secret-123"
  API_KEY: "sk-xxx"
```

```bash
# 从文件创建
kubectl create secret generic app-secret --from-literal=DB_PASS=xxx --from-file=key.pem
```

### 21. Volume — 存储挂载

| 类型             | 生命周期 | 用途                    |
| ---------------- | -------- | ----------------------- |
| emptyDir         | Pod 内   | 临时文件/缓存           |
| hostPath         | 节点     | 日志/数据（不推荐生产） |
| PersistentVolume | 独立     | 数据库/持久化（推荐）   |
| configMap/secret | Pod 内   | 配置文件                |

```yaml
# PersistentVolume + PVC
apiVersion: v1
kind: PersistentVolumeClaim
metadata: { name: data-pvc }
spec:
  accessModes: ["ReadWriteOnce"]
  resources: { requests: { storage: 10Gi } }
```

> **小结**: ConfigMap 管配置、Secret 管密码、PVC 管存储。

## 第六阶段：Ingress — HTTP 路由

### 22. Ingress 配置

```bash
# 安装 Ingress Controller（以 Nginx 为例）
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/main/deploy/static/provider/cloud/deploy.yaml
```

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: web-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
    - host: www.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service: { name: frontend-svc, port: { number: 80 } }
          - path: /api
            pathType: Prefix
            backend:
              service: { name: api-svc, port: { number: 3000 } }
  tls:
    - hosts: [www.example.com]
      secretName: tls-secret
```

### 23. Ingress 路由规则

```
www.example.com/     → frontend-svc:80
www.example.com/api  → api-svc:3000
admin.example.com    → admin-svc:80
```

> **小结**: Ingress 是 K8s 的七层路由，支持域名/路径/TLS。

## 第七阶段：高级工作负载

### 24. StatefulSet — 有状态应用

适合数据库等需要**稳定网络标识 + 持久存储**的应用：

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata: { name: postgres }
spec:
  serviceName: postgres
  replicas: 1
  selector:
    matchLabels: { app: postgres }
  template:
    spec:
      containers:
        - name: postgres
          image: postgres:16
          volumeMounts:
            - name: data
              mountPath: /var/lib/postgresql/data
  volumeClaimTemplates:
    - metadata: { name: data }
      spec:
        accessModes: ["ReadWriteOnce"]
        resources: { requests: { storage: 20Gi } }
```

### 25. DaemonSet — 每节点一个 Pod

```yaml
# 日志收集 / 监控 Agent（每个 Node 都跑一个）
apiVersion: apps/v1
kind: DaemonSet
metadata: { name: fluentd }
spec:
  selector:
    matchLabels: { name: fluentd }
  template:
    spec:
      containers:
        - name: fluentd
          image: fluentd:latest
```

### 26. Job & CronJob — 任务

```yaml
# 一次性 Job
apiVersion: batch/v1
kind: Job
metadata: { name: migration }
spec:
  template:
    spec:
      containers:
        - name: migrate
          image: my-app:latest
          command: ["npm", "run", "migrate"]
      restartPolicy: Never

---
# 定时任务
apiVersion: batch/v1
kind: CronJob
metadata: { name: cleanup }
spec:
  schedule: "0 2 * * *" # 每天凌晨 2 点
  jobTemplate:
    spec:
      template:
        spec:
          containers:
            - name: cleanup
              image: busybox
              command: ["rm", "-rf", "/tmp/*"]
          restartPolicy: Never
```

> **小结**: StatefulSet 跑数据库、DaemonSet 跑日志/监控 Agent、Job/CronJob 跑任务。

## 第九阶段：网络策略与安全

### 29. RBAC — 权限控制

```yaml
# 创建 ServiceAccount
apiVersion: v1
kind: ServiceAccount
metadata: { name: deployer }

---
# Role: 定义权限
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: { namespace: dev }
rules:
  - apiGroups: [""]
    resources: ["pods", "services"]
    verbs: ["get", "list", "create", "delete"]

---
# RoleBinding: 绑定用户到角色
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: { namespace: dev }
subjects:
  - kind: ServiceAccount
    name: deployer
roleRef:
  kind: Role
  name: deploy-role
  apiGroup: rbac.authorization.k8s.io
```

### 30. NetworkPolicy — 网络隔离

```yaml
# 只允许 frontend → backend 的流量
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: backend-policy }
spec:
  podSelector: { matchLabels: { app: backend } }
  ingress:
    - from:
        - podSelector: { matchLabels: { app: frontend } }
      ports: [{ port: 3000 }]
```

## 第十一阶段：前端项目部署实战

### 34. 完整部署流程

```dockerfile
# Dockerfile（多阶段构建）
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine

```

```bash
# 1. 构建镜像
docker build -t registry.example.com/frontend:1.0.0 .

# 2. 推送镜像
docker push registry.example.com/frontend:1.0.0

# 3. 部署到 K8s
kubectl apply -f configmap.yaml
kubectl apply -f secret.yaml
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml
kubectl apply -f ingress.yaml

# 4. 验证
kubectl get pods -w
kubectl get svc
kubectl get ingress

# 5. 滚动更新
kubectl set image deploy/frontend nginx=registry.example.com/frontend:1.0.1
kubectl rollout status deploy/frontend
```

## 第十三阶段：Kustomize — 配置管理进阶

### 39. Kustomize 概念

Kustomize 是 K8s 内置的**配置定制工具**（`kubectl apply -k`），无需模板引擎即可管理多环境 YAML。

```
base/                        # 公共配置
├── kustomization.yaml
├── deployment.yaml
└── service.yaml

overlays/
├── dev/
│   ├── kustomization.yaml   # 覆盖: replicas=1, env=dev
│   └── configmap.yaml
└── prod/
    ├── kustomization.yaml   # 覆盖: replicas=3, env=prod
    └── configmap.yaml
```

```yaml
# overlays/prod/kustomization.yaml
resources: ["../../base"]
patches:
  - patch: |-
      - op: replace; path: /spec/replicas; value: 3
    target: { kind: Deployment, name: frontend }
configMapGenerator:
  - name: app-config
    literals: ["ENV=production"]
images:
  - name: frontend; newTag: 1.0.0
```

```bash
kubectl apply -k overlays/prod   # 一键部署生产环境
```

## 第十五阶段：故障排查深度

### 42. Pod 无法启动完整排查流程

```bash
# 1. 查看 Pod 状态
kubectl get pods -o wide

# 2. 查看 Events（最关键）
kubectl describe pod <pod> | grep -A 20 Events

# 3. 根据状态定位
# Pending → 资源不足/不能调度 → describe pod + describe node
# ImagePullBackOff → 镜像问题 → 检查镜像名/prefecth secret
# CrashLoopBackOff → 启动崩溃 → kubectl logs <pod>
# OOMKilled → 内存不足 → 增加 memory limit

# 4. 检查网络连通性
kubectl run debug --rm -it --image=busybox -- /bin/sh
# nslookup my-service
# wget -qO- http://my-service:80

# 5. 检查 DNS
kubectl run debug --rm -it --image=busybox -- nslookup kubernetes.default
```

### 43. Service 不通排查

```bash
# Service → Pod 链路检查
kubectl get svc my-service           # Service ClusterIP
kubectl get endpoints my-service     # 应该有 Pod IP 列表
# 如果 endpoints 为空 → selector 不匹配 → 检查标签

kubectl get pods -l app=my-app -o wide  # 查看 Pod 标签
kubectl exec <pod> -- env | grep APP    # 对比标签
```

## 第十六阶段：生产最佳实践

### 44. 安全清单

```yaml
# 1. 不以 root 运行
securityContext:
  runAsNonRoot: true
  runAsUser: 1001

# 2. 只读根文件系统
securityContext:
  readOnlyRootFilesystem: true

# 3. 资源限制（每个容器都必须有）
resources:
  requests: { cpu: 100m, memory: 128Mi }
  limits: { cpu: 500m, memory: 256Mi }

# 4. Pod 中断预算 (PDB)
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata: { name: frontend-pdb }
spec:
  minAvailable: 2
  selector: { matchLabels: { app: frontend } }
```

### 45. 生产部署 Checklist

```txt
✅ 每个容器设置 resources requests/limits
✅ 配置 liveness + readiness 探针
✅ 使用非 root 用户运行容器
✅ 敏感数据使用 Secret（不硬编码）
✅ Pod 设置 PodDisruptionBudget
✅ 使用 HPA 自动伸缩
✅ 开启滚动更新（不用 Recreate）
✅ 日志收集到中心化平台 (EFK/Loki)
✅ 监控指标导出 (Prometheus)
✅ 备份 etcd + PersistentVolume
```
