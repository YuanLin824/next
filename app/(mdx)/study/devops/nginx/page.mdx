# Nginx 学习指南

> 难度递进式 Nginx 学习文档，从安装到企业级反向代理和负载均衡。

---

## 第一阶段：安装与基础命令（入门）

### 1. Nginx 是什么？

Nginx 是**高性能 HTTP 和反向代理服务器**，也是 IMAP/POP3 邮件代理服务器。以事件驱动架构著称，单机可处理数万并发连接。

核心能力：静态资源服务 | 反向代理 | 负载均衡 | HTTPS/TLS | Gzip 压缩 | HTTP 缓存

### 2. Docker 安装

```bash
docker pull nginx:alpine
docker run -d --name nginx -p 8080:80 nginx:alpine
# 浏览器访问 http://localhost:8080 → 看到 Nginx 欢迎页
```

### 3. 常用命令

```bash
nginx -t                # 测试配置文件语法
nginx -s reload         # 重载配置（不中断服务）
nginx -s stop           # 快速停止
nginx -s quit           # 优雅停止（处理完当前请求）
nginx -s reopen         # 重新打开日志文件

# Docker 中
docker exec nginx nginx -t
docker exec nginx nginx -s reload
```

### 4. 配置文件结构

Nginx 默认配置路径 `/etc/nginx/nginx.conf`：

```nginx
# 全局块 — 影响所有连接的设置
user nginx;
worker_processes auto;          # 工作进程数(建议 CPU 核心数)
error_log /var/log/nginx/error.log warn;

# events 块 — 连接处理方式
events {
    worker_connections 1024;    # 每个工作进程最大连接数
}

# http 块 — HTTP 服务器全局配置
http {
    include /etc/nginx/mime.types;  # MIME 类型映射
    default_type application/octet-stream;

    # server 块 — 一个虚拟主机（站点）
    server {
        listen 80;                   # 监听端口
        server_name example.com;     # 域名

        location / {                 # 路径匹配
            root /usr/share/nginx/html;
            index index.html;
        }
    }
}
```

> **小结**: 理解 Nginx 的层级结构（全局→events→http→server→location），能启动和重载。

## 第二阶段：静态文件服务（Web 服务器）

### 5. 静态站点配置

```nginx
server {
    listen 80;
    server_name www.example.com;
    root /var/www/dist;
    index index.html;

    # SPA 路由：所有路径都返回 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源强缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

### 6. try_files 详解

```nginx
# 依次尝试: 文件 $uri → 目录 $uri/ → /index.html
try_files $uri $uri/ /index.html;

# 如果都没找到 → =404 返回 404
try_files $uri $uri/ =404;
```

### 7. root vs alias

```nginx
# root → 路径拼接到 root 后面
location /images/ { root /var/www; }    # /images/logo.png → /var/www/images/logo.png

# alias → 路径替换
location /static/ { alias /var/www/; }  # /static/logo.png → /var/www/logo.png
```

> **小结**: 能配置静态站点，理解 `try_files` 实现 SPA 路由，区分 `root` 和 `alias`。

## 第三阶段：反向代理（核心能力）

### 8. proxy_pass 反向代理

```nginx
# 基础反向代理
location /api/ {
    proxy_pass http://localhost:3000/;         # 末尾 / 会剥离 /api 前缀
    # proxy_pass http://localhost:3000;         # 无 / 保留 /api 前缀
}
```

### 9. 代理头透传

```nginx
location /api/ {
    proxy_pass http://backend:3000;

    proxy_set_header Host $host;                         # 原请求的域名
    proxy_set_header X-Real-IP $remote_addr;             # 客户端真实 IP
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; # 代理链 IP
    proxy_set_header X-Forwarded-Proto $scheme;          # 原始协议(HTTP/HTTPS)
}
```

### 10. 前后端同域名

```nginx
server {
    listen 80;
    server_name app.example.com;

    location / {
        root /var/www/dist;
        try_files $uri /index.html;
    }

    location /api/ {
        proxy_pass http://backend:3000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 11. WebSocket 代理

```nginx
location /ws {
    proxy_pass http://backend:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
}
```

### 12. 超时与缓冲

```nginx
location /api/ {
    proxy_pass http://backend:3000;

    # 超时控制
    proxy_connect_timeout 10s;      # 连接后端超时
    proxy_read_timeout 60s;         # 读取后端响应超时
    proxy_send_timeout 60s;         # 发送请求到后端超时

    # 缓冲控制
    proxy_buffering on;             # 响应缓冲（默认开启）
    proxy_buffer_size 4k;
    proxy_buffers 8 4k;
    proxy_busy_buffers_size 8k;
}
```

> **小结**: 掌握反向代理的核心配置：proxy_pass、代理头透传、前后端同域名、WebSocket。

## 第四阶段：负载均衡

### 13. upstream 负载均衡

```nginx
upstream backend {
    server 192.168.1.10:3000 weight=3 max_fails=3 fail_timeout=30s;
    server 192.168.1.11:3000 weight=1;
    server 192.168.1.12:3000 backup;

    keepalive 32;   # 与后端保持的空闲长连接数
}

server {
    location /api/ {
        proxy_pass http://backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
    }
}
```

### 14. 五种负载策略

| 策略         | 指令                             | 说明                       |
| ------------ | -------------------------------- | -------------------------- |
| 轮询（默认） | —                                | 依次分配                   |
| 权重         | `weight=N`                       | 按权重比例                 |
| 最少连接     | `least_conn`                     | 分配到连接最少             |
| IP 哈希      | `ip_hash`                        | 同 IP 固定同后端(会话保持) |
| 一致性哈希   | `hash $request_uri consistent`   | 按 URI 哈希                |
| 最短响应时间 | `least_time header` (Nginx Plus) | 响应最快优先               |

### 15. 后端健康检查

```nginx
upstream backend {
    server 192.168.1.10:3000 max_fails=3 fail_timeout=30s;  # 30s 内失败 3 次 → 摘除 30s
    server 192.168.1.11:3000 max_fails=2 fail_timeout=15s;
    server 192.168.1.12:3000 down;   # 永久下线
}
```

> **小结**: 能用 upstream 实现负载均衡，理解五种策略和健康检查。

## 第五阶段：HTTPS 与安全

### 16. SSL/TLS 配置

```nginx
server {
    listen 443 ssl http2;
    server_name www.example.com;

    ssl_certificate     /etc/nginx/ssl/example.com.pem;
    ssl_certificate_key /etc/nginx/ssl/example.com.key;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256;
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    # HSTS — 强制浏览器 HTTPS
    add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload";
}
```

### 17. HTTP → HTTPS 重定向

```nginx
server {
    listen 80;
    server_name www.example.com;
    return 301 https://$host$request_uri;
}
```

### 18. 安全头

```nginx
add_header X-Frame-Options "SAMEORIGIN" always;           # 防点击劫持
add_header X-Content-Type-Options "nosniff" always;       # 防 MIME 嗅探
add_header X-XSS-Protection "1; mode=block" always;       # XSS 过滤
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
server_tokens off;                                         # 隐藏版本号
```

### 19. 访问控制

```nginx
# IP 白名单
location /admin {
    allow 192.168.1.0/24;
    deny all;
}

# HTTP Basic Auth
location /private {
    auth_basic "Restricted Area";
    auth_basic_user_file /etc/nginx/.htpasswd;
}

# 限制请求方法
if ($request_method !~ ^(GET|POST|HEAD)$) {
    return 405;
}
```

> **小结**: 能配置 HTTPS、HTTP→HTTPS 重定向、安全头和访问控制。

## 第六阶段：Gzip、缓存与限流

### 20. Gzip 压缩

```nginx
gzip on;
gzip_vary on;
gzip_min_length 1024;
gzip_comp_level 6;                    # 1-9，6 是平衡点
gzip_types text/plain text/css application/json application/javascript text/xml image/svg+xml;
gzip_proxied any;                     # 反向代理的响应也压缩
```

### 21. 浏览器缓存控制

```nginx
# 静态资源强缓存
location ~* \.(js|css|png|jpg)$ { expires 1y; add_header Cache-Control "public, immutable"; }

# HTML 不缓存（确保获取最新版本）
location / { add_header Cache-Control "no-cache"; }
```

### 22. 代理缓存

```nginx
proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=api_cache:10m max_size=1g inactive=60m;

location /api/ {
    proxy_cache api_cache;
    proxy_cache_valid 200 1h;
    proxy_cache_valid 404 1m;
    proxy_cache_key "$scheme$request_method$host$request_uri";  # 缓存 Key
    proxy_cache_use_stale error timeout updating;               # 后端异常时返回过期缓存
    proxy_cache_bypass $http_cache_control;                     # 客户端可跳过缓存

    add_header X-Cache-Status $upstream_cache_status;
    proxy_pass http://backend;
}
```

### 23. 限流

```nginx
# 定义限流规则
limit_req_zone $binary_remote_addr zone=mylimit:10m rate=10r/s;   # 10 请求/秒
limit_conn_zone $binary_remote_addr zone=connlimit:10m;           # 并发控制

location /api/ {
    limit_req zone=mylimit burst=20 nodelay;   # 允许 20 个突发，立即处理
    limit_conn connlimit 10;                   # 单 IP 最多 10 并发
    limit_rate 500k;                           # 限速 500KB/s
    proxy_pass http://backend;
}
```

> **小结**: 掌握 Gzip 压缩、缓存策略（强缓存/代理缓存）、请求限流和并发限制。

## 第七阶段：location 匹配与 URL 重写

### 24. location 匹配优先级

```nginx
# 优先级（从高到低）：
# 1. = 精确匹配    location = /           { }
# 2. ^~ 前缀优先   location ^~ /images/   { }
# 3. ~ 正则匹配    location ~ \.(gif|jpg)$ { }
# 4. 普通前缀     location /api/          { }
# 5. / 通用匹配   location /              { }

location = / { return 200 "精确匹配 /"; }
location ^~ /static/ { }           # 前缀优先（不检查正则）
location ~ \.php$ { }              # 正则匹配（区分大小写）
location ~* \.(jpg|png)$ { }       # 正则匹配（不区分大小写）
location /api/ { }                 # 普通前缀
location / { }                     # 兜底匹配
```

### 25. rewrite 重写

```nginx
# 旧 URL 重定向到新 URL
rewrite ^/old-page$ /new-page permanent;   # 301 永久重定向
rewrite ^/old-path$ /new-path redirect;    # 302 临时重定向

# 内部重写（不改浏览器 URL）
rewrite ^/api/v1/(.*)$ /api/v2/$1 last;   # last: 重写后重新匹配 location

# 按条件重写
if ($host = "old.example.com") {
    rewrite ^(.*)$ https://new.example.com$1 permanent;
}
```

### 26. return 与 error_page

```nginx
# 直接返回
return 301 https://$host$request_uri;   # 301 重定向
return 204;                              # 空响应
return 200 "OK";                         # 返回文本

# 自定义错误页
error_page 404 /404.html;
error_page 500 502 503 504 /50x.html;

# 精确错误页位置
location = /50x.html { root /usr/share/nginx/html; }
```

> **小结**: 理解 location 五级匹配优先级，能用 rewrite 重定向和 return 返回。

## 第八阶段：变量与条件判断

### 27. 内置变量

| 变量                     | 含义                                      |
| ------------------------ | ----------------------------------------- |
| `$remote_addr`           | 客户端 IP                                 |
| `$host`                  | 请求 Host 头                              |
| `$request_uri`           | 完整请求 URI（含参数）                    |
| `$uri`                   | 当前 URI（不含参数，可能被 rewrite 改变） |
| `$scheme`                | http / https                              |
| `$request_method`        | GET / POST                                |
| `$http_<name>`           | 任意请求头（如 `$http_user_agent`）       |
| `$args`                  | 查询参数字符串                            |
| `$arg_<name>`            | 特定查询参数（如 `$arg_page` → ?page=1）  |
| `$upstream_cache_status` | HIT / MISS / EXPIRED                      |

### 28. if / set / map

```nginx
# if — 在 server/location 中使用（谨慎：有陷阱）
if ($http_user_agent ~* "bot") { return 403; }

# set — 给变量赋值
set $cache_key "$scheme://$host$request_uri";

# map — 在 http 块中定义映射
map $http_upgrade $connection_upgrade {
    default upgrade;
    ""      close;
}
# 使用: proxy_set_header Connection $connection_upgrade;
```

> **小结**: 掌握 Nginx 变量体系（内置/自定义/map），能写条件判断。

## 第十阶段：性能调优

### 31. Worker 与连接优化

```nginx
worker_processes auto;              # CPU 核心数
worker_rlimit_nofile 65535;         # 最大文件描述符
events {
    worker_connections 4096;        # 每 worker 最大连接数
    use epoll;                      # Linux 高性能事件模型
    multi_accept on;                # 一次接受多个连接
}
```

### 32. 网络与传输优化

```nginx
sendfile on;                        # 零拷贝传输文件
tcp_nopush on;                      # 累积数据包再发送（配合 sendfile）
tcp_nodelay on;                     # 禁止 Nagle 算法（对 keep-alive 优化）
keepalive_timeout 65;               # 客户端长连接超时
keepalive_requests 100;             # 单个长连接最大请求数
client_max_body_size 10m;           # 客户端请求体最大大小
client_body_buffer_size 128k;       # 请求体缓冲区
```

### 33. 可优化的配置

| 配置项               | 建议值    | 说明               |
| -------------------- | --------- | ------------------ |
| `worker_processes`   | `auto`    | CPU 核心数         |
| `worker_connections` | 2048-4096 | 每 worker 最大连接 |
| `gzip on`            | ✅        | 压缩传输           |
| `sendfile on`        | ✅        | 零拷贝             |
| `tcp_nopush on`      | ✅        | 批量发送           |
| `keepalive_timeout`  | 60-75s    | 减少 TCP 握手      |

### 38. 跨域完整方案

```nginx
location /api/ {
    # 生产环境用 map 动态设置白名单
    set $cors_origin "";
    if ($http_origin ~* "^https?://(www\.)?example\.com$") {
        set $cors_origin $http_origin;
    }

    add_header Access-Control-Allow-Origin $cors_origin;
    add_header Access-Control-Allow-Methods "GET, POST, PUT, DELETE, OPTIONS";
    add_header Access-Control-Allow-Headers "Content-Type, Authorization";
    add_header Access-Control-Allow-Credentials true;
    add_header Access-Control-Max-Age 86400;  # 预检缓存 24 小时

    if ($request_method = OPTIONS) { return 204; }
    proxy_pass http://backend;
}
```

## 第十三阶段：Upstream 高级特性

### 40. 后端长连接池

```nginx

location /api/ {
    proxy_pass http://backend;

}
```

```nginx
    server backend3:3000 backup;
}
```

## 第十六阶段：Nginx 架构原理

### 49. Master-Worker 架构

```
Master 进程 (root)
├── 读取配置、管理 Worker
├── Worker × N (www-data)
│   ├── 单线程、事件驱动
│   ├── 共享监听端口 (SO_REUSEPORT)
│   └── 独立处理连接（无锁）
└── Cache Manager / Loader
```

```
请求处理流程:
  客户端连接 → epoll_wait 监听事件 → accept 接受
    → HTTP 解析 → 查找 location → 静态文件/反向代理
      → 返回响应 → 日志记录
```

### 50. 为什么 Nginx 这么快？

| 原因                     | 说明                             |
| ------------------------ | -------------------------------- |
| 事件驱动（epoll/kqueue） | 非阻塞 I/O，单线程处理数万连接   |
| Master-Worker 多进程     | 充分利用多核 CPU                 |
| sendfile 零拷贝          | 文件直接内核态传输，不经过用户态 |
| 内存池                   | 减少 `malloc/free` 开销          |
| 模块化设计               | 核心轻量，按需加载模块           |

### 51. Nginx vs Apache 对比

| 维度       | Nginx                | Apache                        |
| ---------- | -------------------- | ----------------------------- |
| 架构       | 事件驱动、异步非阻塞 | 进程/线程池（prefork/worker） |
| 静态文件   | ⭐⭐⭐⭐⭐           | ⭐⭐⭐                        |
| 反向代理   | ⭐⭐⭐⭐⭐           | ⭐⭐⭐                        |
| 动态内容   | 需配合 FastCGI/后端  | ⭐⭐⭐⭐ (mod_php)            |
| 配置灵活度 | ⭐⭐⭐⭐             | ⭐⭐⭐⭐⭐ (.htaccess)        |
| 内存占用   | 低                   | 较高                          |
| 高并发     | ⭐⭐⭐⭐⭐           | ⭐⭐⭐                        |
| 生态       | 现代首选             | 传统项目                      |
