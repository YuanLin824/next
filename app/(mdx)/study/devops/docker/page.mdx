# Docker 学习指南

> 难度递进式 Docker 学习文档，从安装到多服务编排。

## 第一阶段：核心概念与安装（入门）

### 1. Docker 三大核心

| 概念                  | 说明                                    | 类比           |
| --------------------- | --------------------------------------- | -------------- |
| **Image（镜像）**     | 极度精简的 Linux 程序运行环境，分层只读 | 类/模板        |
| **Container（容器）** | Image 的运行实例，共享宿主机内核        | 对象/实例      |
| **Registry（仓库）**  | 存储和分发 Image 的地方                 | npm/Maven 仓库 |

```
Dockerfile → build → Image → run → Container
              push/pull ↕
            Registry (Docker Hub)
```

### 2. 安装 Docker

```bash
# Ubuntu
sudo apt update && sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# CentOS
sudo yum install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# macOS/Windows → 下载 Docker Desktop

# 验证
docker version && docker run hello-world
```

### 3. 第一个容器

```bash
docker pull nginx:alpine            # 拉取镜像
docker run -d -p 8080:80 nginx:alpine  # 运行容器（端口映射 8080→80）
# 浏览器访问 http://localhost:8080  → 见到 Nginx 欢迎页

docker ps                           # 查看运行中的容器
docker stop <container>             # 停止
docker rm <container>               # 删除
```

> **小结**：理解 Image/Container/Registry 三大概念，能运行第一个容器。

### 5. 镜像分层原理

```bash

# Dockerfile 每条指令(RUN/COPY/ADD)创建一个层
# 层可共享、可缓存 → 相同层只需下载/存储一次
# 优化: 合并 RUN、先 COPY package.json 再 COPY 源码（利用缓存）
```

## 第三阶段：容器操作（核心技能）

### 6. 容器生命周期

```bash
# 运行
docker run -d --name myapp -p 3000:3000 -e NODE_ENV=production -v /host/data:/app/data --restart unless-stopped myapp:latest

# 管理
docker ps -a                        # 所有容器
docker start/stop/restart <name>
docker rm <name>                    # 删除已停止
docker rm -f <name>                 # 强制删除（运行中也可）

# 交互
docker exec -it <name> bash         # 进入容器
docker logs -f --tail 100 <name>    # 实时日志
docker cp <name>:/path/file ./      # 复制文件
docker stats                        # 资源使用
docker inspect <name>               # 详细信息（IP/挂载/网络）
```

### 7. 常用 run 参数速查

| 参数                | 说明           | 示例                  |
| ------------------- | -------------- | --------------------- |
| `-d`                | 后台运行       |                       |
| `--name`            | 指定名称       | `--name myapp`        |
| `-p`                | 端口映射       | `-p 8080:80`          |
| `-e` / `--env-file` | 环境变量       | `-e NODE_ENV=prod`    |
| `-v` / `--mount`    | 挂载卷         | `-v /host:/container` |
| `--restart`         | 重启策略       | `unless-stopped`      |
| `-m` / `--cpus`     | 资源限制       | `-m 512m --cpus=1.5`  |
| `--rm`              | 退出后自动删除 |                       |
| `-it`               | 交互终端       |                       |
| `--network`         | 指定网络       | `--network mynet`     |

> **小结**：掌握 docker run 核心参数的组合使用。

## 第四阶段：数据卷与网络

### 8. Volume — 持久化数据

```bash
# 命名卷（推荐，由 Docker 管理）
docker volume create app-data
docker run -v app-data:/app/data myapp

# 绑定挂载（直接映射宿主机路径）
docker run -v /host/path:/container/path myapp
docker run --mount type=bind,source=/host/path,target=/container/path myapp

# 只读挂载
docker run -v /host/config:/app/config:ro myapp

# 管理
docker volume ls
docker volume rm app-data
docker volume prune
```

### 9. Network — 容器间通信

```bash
# 创建自定义网络（推荐）
docker network create mynet

# 同一网络中的容器可通过容器名互相访问
docker run --network mynet --name app1 myapp
docker run --network mynet --name app2 myapp
# app1 可直接 ping app2

# 网络类型
# bridge:  默认，NAT 桥接
# host:    与宿主机共享网络
# none:    无网络
```

```bash
docker network ls
docker network inspect mynet
docker network connect mynet <container>  # 动态加入网络
```

## 第五阶段：Dockerfile（镜像构建核心）

### 10. 核心指令

```dockerfile
FROM node:20-alpine                # 基础镜像（必需，第一行）
WORKDIR /app                       # 设置工作目录
COPY package*.json ./              # 复制文件（先复制依赖文件以利用缓存）
RUN npm ci                         # 执行命令（构建时）
COPY . .                           # 再复制源码
ENV NODE_ENV=production PORT=3000  # 环境变量
EXPOSE 3000                        # 声明端口
CMD ["node", "server.js"]          # 默认启动命令
```

| 指令          | 用途                      | 时机      |
| ------------- | ------------------------- | --------- |
| `FROM`        | 基础镜像                  | 构建      |
| `WORKDIR`     | 设置工作目录              | 构建+运行 |
| `COPY`        | 复制文件                  | 构建      |
| `ADD`         | 复制+解压                 | 构建      |
| `RUN`         | 执行命令                  | 构建      |
| `ENV`         | 环境变量                  | 构建+运行 |
| `ARG`         | 构建参数（`--build-arg`） | 构建      |
| `EXPOSE`      | 声明端口                  | 文档      |
| `CMD`         | 默认启动命令              | 运行      |
| `ENTRYPOINT`  | 入口点（不可覆盖）        | 运行      |
| `USER`        | 切换用户                  | 运行      |
| `HEALTHCHECK` | 健康检查                  | 运行      |

### 11. 多阶段构建（减小镜像体积）

```dockerfile
# 阶段1: 构建
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./ && RUN npm ci
COPY . . && RUN npm run build

# 阶段2: 生产运行（只复制构建产物）
FROM node:20-alpine AS runner
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
EXPOSE 3000
CMD ["node", "dist/server.js"]
```

### 12. 优化镜像大小

```dockerfile
# 1. 使用 Alpine 基础镜像
FROM node:20-alpine     # 比 node:20 小 ~10 倍

# 2. 合并 RUN 指令（减少层数）
RUN apt-get update && apt-get install -y pkg1 pkg2 && rm -rf /var/lib/apt/lists/*

# 3. .dockerignore 排除无关文件
# node_modules/  .git/  .env  dist/  *.log

# 4. 生产用 npm ci --omit=dev
```

### 13. 安全实践

```dockerfile
# 创建非 root 用户
RUN addgroup -g 1001 app && adduser -S -u 1001 -G app app
USER app

# 健康检查
HEALTHCHECK --interval=30s --timeout=3s --retries=3 CMD curl -f http://localhost:3000/health || exit 1
```

> **小结**：能写多阶段 Dockerfile，理解指令顺序对缓存的影响。

## 第六阶段：Docker-Compose（多服务编排）

### 14. docker-compose.yml 基础

```yaml
services:
  frontend:
    build: . # 从当前目录 Dockerfile 构建
    ports: ["80:80"]
    restart: unless-stopped

  backend:
    image: node:20-alpine
    working_dir: /app
    command: ["node", "server.js"]
    ports: ["3000:3000"]
    environment:
      - DB_HOST=db
      - DB_PORT=5432
    depends_on:
      - db

  db:
    image: postgres:16-alpine
    volumes:
      - pgdata:/var/lib/postgresql/data
    environment:
      POSTGRES_PASSWORD: secret123

volumes:
  pgdata:
```

### 15. Compose 常用命令

```bash
docker compose up -d                # 启动所有服务
docker compose up -d --build        # 重新构建并启动
docker compose down                 # 停止 + 删除容器/网络
docker compose down -v              # 同时删除数据卷
docker compose ps                   # 查看服务状态
docker compose logs -f frontend     # 查看日志
docker compose exec backend bash    # 进入容器
docker compose restart              # 重启
docker compose pull                 # 拉取最新镜像
```

### 16. depends_on vs healthcheck

```yaml
services:
  app:
    depends_on:
      db:
        condition: service_healthy  # 等 db 健康检查通过后再启动
  db:
    image: postgres:16-alpine
    healthcheck:
      test: ["CMD", "pg_isready", "-U", "postgres"]
      interval: 5s; timeout: 3s; retries: 5
```

### 21. Buildx 缓存优化

```dockerfile
# 利用 BuildKit 缓存挂载加速 npm install
RUN --mount=type=cache,target=/root/.npm \
    npm ci

# 利用缓存挂载加速 apt-get
RUN --mount=type=cache,target=/var/cache/apt \
    apt-get update && apt-get install -y curl
```

```bash
# 远程缓存（CI 中跨构建复用）
docker buildx build --cache-to=type=registry,ref=registry.example.com/cache:myapp \
  --cache-from=type=registry,ref=registry.example.com/cache:myapp \
  -t myapp:latest .
```

### 32. GitHub Actions + Docker

```yaml

name: Docker Build & Push
on:
  push:
    branches: [main]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/login-action@v3

        with:
          push: true
          tags: registry.example.com/app:${{ github.sha }}, registry.example.com/app:latest
          cache-from: type=gha; cache-to: type=gha,mode=max
```

### 重启策略

| `always`                   | 总是重启             |

## 第十三阶段：生产最佳实践

### 34. 优化镜像大小的 5 个技巧

```dockerfile
# 1. Alpine 基础镜像 — node:20-alpine (~50MB vs node:20 ~350MB)
FROM node:20-alpine

# 2. 多阶段构建 — 构建依赖不进入最终镜像
FROM node:20-alpine AS builder
RUN npm ci
FROM node:20-alpine
COPY --from=builder /app/dist ./dist

# 3. .dockerignore 排除无关文件
# node_modules/  .git/  tests/  *.md  .env

# 4. 清理包管理器缓存
RUN apk add --no-cache curl   # Alpine (--no-cache 不缓存安装包)

# 5. 合并 RUN — 减少层数
RUN apt-get update && apt-get install -y pkg1 pkg2 && rm -rf /var/lib/apt/lists/*
```

### 35. 生产环境 Checklist

```txt
✅ 使用固定版本标签(node:20.11.0-alpine 而非 node:latest)
✅ 以非 root 用户运行 (USER appuser)
✅ HEALTHCHECK 监控应用健康状态
✅ 日志输出到 stdout/stderr (不要写文件)
✅ 通过环境变量传配置 (ENV / -e)
✅ 使用 .dockerignore 减小构建上下文
✅ 限制资源使用 (-m 512m --cpus=1)
✅ 设置 restart: unless-stopped
✅ 敏感数据用 Docker Secrets 或外部注入
✅ 不要在镜像中硬编码密钥
```

## 第十五阶段：Docker Context — 远程管理

### 39. 远程 Docker 管理

```bash
# 列出所有 context
docker context ls

# 创建远程 context（通过 SSH）
docker context create remote-server --docker "host=ssh://user@192.168.1.100"

# 切换到远程
docker context use remote-server
docker ps                           # 查看远程服务器上的容器

# 切换回本地
docker context use default
```
