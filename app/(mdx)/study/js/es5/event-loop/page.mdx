# 事件循环 (Event Loop)

---

## 为什么需要事件循环

JavaScript 是**单线程**语言，同一时间只能执行一个任务。如果所有任务都是同步的，一个耗时操作就会阻塞整个页面。

事件循环机制让 JS 能用**异步非阻塞**的方式处理任务：

```
同步代码直接执行 → 异步任务注册回调 → 等时机成熟，回调进入任务队列 → 事件循环调度执行
```

---

## 宏任务与微任务

### 宏任务 (Macro Task)

触发新一轮事件循环的"入口"任务，每轮循环只执行**一个**宏任务。

| 来源                | 说明                           |
| ------------------- | ------------------------------ |
| `script` (整体代码) | 入口脚本本身就是一个宏任务     |
| `setTimeout`        | 定时器回调                     |
| `setInterval`       | 定时器回调                     |
| `setImmediate`      | Node.js 特有                   |
| `I/O`               | Node.js 中的 I/O 回调          |
| `UI rendering`      | 浏览器渲染（在宏任务之间执行） |
| `postMessage`       | 跨文档通信                     |
| `MessageChannel`    | 消息通道                       |

### 微任务 (Micro Task)

在当前宏任务执行完后、下一个宏任务之前**清空所有微任务**。

| 来源                                         | 说明                       |
| -------------------------------------------- | -------------------------- |
| `Promise.then()` / `.catch()` / `.finally()` | Promise 回调               |
| `async/await` (`await` 之后的部分)           | 本质是 `Promise.then()`    |
| `MutationObserver`                           | DOM 变化监听               |
| `queueMicrotask()`                           | 显式添加微任务             |
| `process.nextTick()`                         | Node.js 特有（优先级最高） |

## 浏览器事件循环流程

```
┌─────────────────────────────────────────┐
│  执行一个宏任务                         │
│  (从宏任务队列取出第一个)               │
├─────────────────────────────────────────┤
│  执行过程中产生微任务 → 放入微任务队列  │
│  宏任务执行完毕                         │
├─────────────────────────────────────────┤
│  清空微任务队列                         │
│  (包括微任务中产生的新微任务，全部吃完) │
├─────────────────────────────────────────┤
│  需要渲染时 → 执行 UI render            │
├─────────────────────────────────────────┤
│  取下一个宏任务，开始下一轮循环         │
└─────────────────────────────────────────┘
```

**核心规则：**

1. 先执行一个宏任务
2. 执行**所有**微任务（包括执行过程中新产生的微任务）
3. 需要渲染时 → UI 渲染
4. 下一轮事件循环，执行下一个宏任务

```js
console.log("1") // 同步，直接执行

setTimeout(() => {
  console.log("2") // 宏任务
}, 0)

Promise.resolve().then(() => {
  console.log("3") // 微任务
})

console.log("4")

// 输出: 1 4 3 2
```

### 微任务嵌套

微任务执行过程中产生的新微任务，会在本轮循环中**一并清空**，不会等到下一轮。

```js
Promise.resolve()
  .then(() => {
    console.log("1")
    Promise.resolve()
      .then(() => {
        console.log("2")
      })
      .then(() => {
        console.log("3")
      })
  })
  .then(() => {
    console.log("4")
  })

// 输出: 1 2 4 3
// 注意 .then 的注册顺序
```

## Node.js 事件循环

Node.js 的事件循环基于 `libuv` 库，比浏览器更复杂，分为 6 个阶段：

```
   ┌───────────────────────────┐
┌─>│           timers          │  setTimeout / setInterval 回调
│  ├───────────────────────────┤
│  │     pending callbacks     │  延迟到下一轮的 I/O 回调
│  ├───────────────────────────┤
│  │       idle, prepare       │  内部使用
│  ├───────────────────────────┤
│  │          poll             │  获取新 I/O 事件、执行 I/O 回调
│  ├───────────────────────────┤
│  │          check            │  setImmediate 回调
│  ├───────────────────────────┤
│  │      close callbacks      │  关闭回调 (socket.on('close'))
└──┴───────────────────────────┘
         ┌───────────────┐
         │ nextTick 队列 │  process.nextTick — 比微任务优先级更高
         │  微任务队列   │  Promise.then
         └───────────────┘
```

**Node.js 执行顺序**：

1. 执行同步代码
2. 清空 `process.nextTick` 队列
3. 清空微任务队列（`Promise.then`）
4. 进入事件循环的 6 个阶段

### process.nextTick vs Promise.then

```js
// nextTick 优先级高于 Promise
Promise.resolve().then(() => console.log("Promise"))
process.nextTick(() => console.log("nextTick"))
// 输出: nextTick → Promise
```

### setImmediate vs setTimeout(fn, 0)

```js
// 在主模块中，执行顺序不确定（受进程性能影响）
setTimeout(() => console.log("timeout"), 0)
setImmediate(() => console.log("immediate"))

// 在 I/O 回调中，setImmediate 一定先执行
fs.readFile("./file", () => {
  setTimeout(() => console.log("timeout"), 0)
  setImmediate(() => console.log("immediate"))
  // 输出: immediate → timeout
})
```

## async/await 在事件循环中的行为

`await` 之后的代码相当于被包装进 `Promise.then()`，作为**微任务**执行。

```js
console.log("script start")

async function async1() {
  console.log("async1 start") // 同步
  await async2()
  console.log("async1 end") // await 之后 → 微任务
}

async function async2() {
  console.log("async2")
}

setTimeout(() => console.log("setTimeout"), 0) // 宏任务

async1()

new Promise((resolve) => {
  console.log("promise1") // 同步（executor 立即执行）
  resolve()
})
  .then(() => console.log("promise2")) // 微任务
  .then(() => console.log("promise3")) // 微任务

console.log("script end") // 同步

// 输出: script start → async1 start → async2 → promise1 → script end
//       → async1 end → promise2 → promise3 → setTimeout
```

### await 拆解

```js
// 以下两段代码等价
async function foo() {
  console.log(2)
  await 1
  console.log(3)
}

// 等价于
function foo() {
  return Promise.resolve(1).then(() => {
    console.log(3)
  })
}
// 注意: console.log(2) 是同步的，只有 await 后面的才是微任务
```

## requestAnimationFrame & requestIdleCallback

这两个 API 的位置：

```
宏任务结束 → 微任务清空 → requestAnimationFrame → 重绘(render) → requestIdleCallback
```

| API                     | 时机             | 频率                  | 用途                       |
| ----------------------- | ---------------- | --------------------- | -------------------------- |
| `requestAnimationFrame` | 渲染前           | ~60fps（16.7ms 一次） | 动画、DOM 批量更新         |
| `requestIdleCallback`   | 渲染后的空闲时间 | 不固定                | 低优先级任务（分析上报等） |

```js
requestAnimationFrame(() => {
  console.log("在渲染之前执行")
})

requestIdleCallback(
  (deadline) => {
    console.log(deadline.timeRemaining(), "ms 剩余")
  },
  { timeout: 2000 }
)
```

## 经典面试题

### 题目 1

```js
setTimeout(() => console.log(1), 0)

new Promise((resolve) => {
  console.log(2)
  resolve()
})
  .then(() => console.log(3))
  .then(() => console.log(4))

console.log(5)

// 输出: 2 5 3 4 1
```

### 题目 2

```js
async function async1() {
  console.log("a")
  await async2()
  console.log("b")
}

async function async2() {
  console.log("c")
}

console.log("d")

setTimeout(() => console.log("e"), 0)

async1()

new Promise((resolve) => {
  console.log("f")
  resolve()
}).then(() => console.log("g"))

console.log("h")

// 输出: d a c f h b g e
```

### 题目 3 — 微任务中产生新微任务

```js
Promise.resolve()
  .then(() => {
    console.log(1)
    Promise.resolve().then(() => console.log(2))
  })
  .then(() => {
    console.log(4) // 注意：这个 .then 在上面的链上，而非内层链
  })

Promise.resolve().then(() => console.log(3))

// 输出: 1 2 3 4
// 解释:
// 微任务队列初始: [then1, then3]
// 执行 then1 → 输出 1, 内层 .then 注册(微任务), then1 返回 resolved, 注册 4
// 执行 then2(内层) → 输出 2
// 执行 then3 → 输出 3
// 执行 then4 → 输出 4
```

### 题目 4 — Node.js 版

```js
setTimeout(() => console.log(1), 0)
setImmediate(() => console.log(2))
process.nextTick(() => console.log(3))
Promise.resolve().then(() => console.log(4))

console.log(5)

// 输出: 5 3 4 1 2 或 5 3 4 2 1
// nextTick 最先，然后是微任务 4
// setTimeout(0) 和 setImmediate 在主模块中顺序不定
```

## 汇总速查表

### 执行优先级（从高到低）

| 优先级 | 内容                                                             | 环境    |
| ------ | ---------------------------------------------------------------- | ------- |
| 1      | 同步代码                                                         | 通用    |
| 2      | `process.nextTick()`                                             | Node.js |
| 3      | 微任务（`Promise.then` / `MutationObserver` / `queueMicrotask`） | 通用    |
| 4      | 宏任务（`setTimeout` / `setInterval` / `setImmediate` / `I/O`）  | 通用    |
| 5      | `requestAnimationFrame`                                          | 浏览器  |
| 6      | UI 渲染                                                          | 浏览器  |
| 7      | `requestIdleCallback`                                            | 浏览器  |

### 浏览器 vs Node.js

| 维度       | 浏览器                                                              | Node.js                              |
| ---------- | ------------------------------------------------------------------- | ------------------------------------ |
| 宏任务来源 | `setTimeout` / `setInterval` / `script` / UI Render / `postMessage` | 6 个阶段（timers / poll / check 等） |
| 微任务来源 | `Promise.then` / `MutationObserver`                                 | `Promise.then` / `process.nextTick`  |
| nextTick   | 不存在                                                              | 有，优先级高于 `Promise.then`        |
| 渲染       | 宏任务之间可插渲染                                                  | 无渲染                               |
| 事件循环库 | 浏览器内核                                                          | `libuv`                              |

### 任务分类

| 类型       | 执行时机         | 每轮执行量 | 举例                                                 |
| ---------- | ---------------- | ---------- | ---------------------------------------------------- |
| **同步**   | 立即             | —          | 普通代码、`Promise` 构造函数内                       |
| **微任务** | 当前宏任务结束后 | 清空全部   | `Promise.then`、`MutationObserver`、`queueMicrotask` |
| **宏任务** | 新的一轮事件循环 | 取一个     | `setTimeout`、`setInterval`、`setImmediate`          |
