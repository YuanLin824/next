## 一、基础概念（难度：★☆☆）

### Q1: CSS 有哪几种引入方式？`link` 和 `@import` 的区别？

| 方式         | 示例                                   | 特点                                    |
| ------------ | -------------------------------------- | --------------------------------------- |
| 行内样式     | `<div style="color:red">`              | 优先级最高（除 `!important`），无复用性 |
| 内联样式     | `<style>div{}</style>`                 | 页面级样式                              |
| **外部链接** | `<link rel="stylesheet" href="a.css">` | 推荐，可缓存、可并行下载                |
| 导入         | `@import url("a.css")` 写在 CSS 中     | 不推荐，串行阻塞加载                    |

```html
<link rel="stylesheet" href="style.css" />
```

**link 与 @import 的核心区别**：

| 对比项     | `link`                                       | `@import`                                       |
| ---------- | -------------------------------------------- | ----------------------------------------------- |
| 加载时机   | HTML 解析时**并行下载**                      | CSS 解析时**串行加载**，等宿主 CSS 加载完才下载 |
| 渲染阻塞   | 可以 `async`/`defer` 控制，可配合 preload    | 会阻塞渲染                                      |
| DOM 操作   | JS 可动态创建 link 节点                      | 无法动态插入                                    |
| 浏览器支持 | 所有浏览器                                   | IE5+（但低版本 bug 多）                         |
| 性能       | **快**（并行）                               | **慢**（串行）                                  |
| 权重       | 均同属于「样式来源」，不因引入方式不同而不同 | 同上                                            |

### Q2: 盒模型是什么？`box-sizing` 的作用？

**标准盒模型（W3C）与怪异盒模型（IE）**：

```
标准盒模型 (content-box): │ 怪异盒模型 (border-box)：
┌─────────────────────┐   │ ┌─────────────────────┐
│       margin        │   │ │        margin       │
│  ┌───────────────┐  │   │ │  ┌───────────────┐  │
│  │    border     │  │   │ │  │    border     │  │
│  │ ┌───────────┐ │  │   │ │  │ ┌───────────┐ │  │
│  │ │  padding  │ │  │   │ │  │ │  padding  │ │  │
│  │ │ ┌───────┐ │ │  │   │ │  │ │ ┌───────┐ │ │  │
│  │ │ │content│ │ │  │   │ │  │ │ │content│ │ │  │
│  │ │ │ w=100 │ │ │  │   │ │  │ │ │ w=100 │ │ │  │
│  └─┴─┴───────┴─┴─┘  │   │ │  └─┴─┴───────┴─┴─┘  │
└─────────────────────┘   │ └─────────────────────┘
width = 100px             │ width = 100px
总宽 = 100 + 2b + 2p + 2m │ 总宽 = 100 + 2m（border/padding 在内）
```

```css
/* content-box：width 只含内容区（默认）
 * border-box：width 含 border + padding + content（推荐全局使用）*/
* {
  box-sizing: border-box;
}
```

| 对比项     | `content-box`（默认） | `border-box`                 |
| ---------- | --------------------- | ---------------------------- |
| width 包含 | 仅 content            | content + padding + border   |
| 直觉       | 需要心算实际宽度      | 写多少就是多少（推荐）       |
| 使用场景   | 老项目 / 特定需求     | 现代项目（reset 里全局设置） |

### Q3: 选择器优先级（Specificity）如何计算？

**优先级计算规则**：将选择器分解为 `(a, b, c, d)` 四元组：

```
a: 行内样式
b: id 选择器数量
c: 类 / 属性 / 伪类数量  (.class  [attr]  :hover)
d: 元素 / 伪元素数量     (div     ::before)

比较顺序：a > b > c > d，从左到右逐位比较
```

```css
/* 示例 */
#nav .item:hover        → (0, 1, 2, 0)
li.item.active          → (0, 0, 2, 1)
ul > li::before         → (0, 0, 0, 3)
div[data-x]             → (0, 0, 1, 1)

/* 覆盖顺序总结：!important > 行内 > id > 类/属性/伪类 > 元素/伪元素 > 通配符 */
```

**容易踩的坑**：

```css
/* 1. :not() 伪类本身不参与优先级计算，但内部的选择器参与 */
div:not(.foo)   → (0, 0, 1, 1)   /* .foo 参与计算 */
div:not(#bar)   → (0, 1, 0, 1)   /* #bar 参与计算 */

/* 2. 相同优先级时，后写的生效（靠后覆盖） */
/* 3. !important 打破层叠，但同属性的 !important 仍按优先级比较 */
/* 4. 通配符 * 优先级为 (0,0,0,0)，低于任何元素选择器 */
```

### Q4: 哪些 CSS 属性会继承？哪些不会？

| 会继承的属性（主要影响文本）     | 不会继承的属性（布局/盒模型）    |
| -------------------------------- | -------------------------------- |
| `color`、`font-*`、`line-height` | `width/height`、`margin/padding` |
| `text-align`、`text-indent`      | `border`、`background`           |
| `visibility`（特殊：可继承）     | `display`、`position`            |
| `cursor`、`letter-spacing`       | `box-sizing`、`overflow`         |
| `word-spacing`、`white-space`    | `z-index`、`float`、`clear`      |
| `list-style`                     | `flex/grid` 相关、`transform`    |

```css
/* 强制继承 / 取消继承 */
.foo {
  width: initial; /* 恢复默认值 */
  color: inherit; /* 强制继承父级 */
}

/* 全局继承技巧：通配符继承字体 */
* {
  box-sizing: border-box;
  font: inherit; /* 让所有元素继承字体，防止表单元素默认字体不同 */
}
```

### Q5: 块级、行内、行内块元素有什么区别？

| 特性           | `block`（块级）  | `inline`（行内）      | `inline-block`（行内块） |
| -------------- | ---------------- | --------------------- | ------------------------ |
| 独占一行       | ✅               | ❌（同行排列）        | ❌（同行排列）           |
| width/height   | ✅ 生效          | ❌ 无效（由内容决定） | ✅ 生效                  |
| margin/padding | 四方向都生效     | 水平生效，垂直不推挤  | 四方向都生效             |
| 常见元素       | `div p h1 ul li` | `span a i b em`       | `img input button`       |
| 默认宽度       | 撑满父容器       | 内容宽度              | 内容宽度                 |

```css
/* 相互转换 */
.foo {
  display: block; /* 块 */
  display: inline; /* 行内 */
  display: inline-block; /* 行内块 */
}
```

### Q6: 什么是文档流（normal flow）？脱离文档流的方式有哪些？

```
文档流：元素按从左到右、从上到下的顺序排列，块级竖排、行内横排。

脱离文档流（不再占据原位置，后面元素会上移补位）：
1. position: absolute / fixed —— 相对定位容器/视口定位
2. float —— 左/右浮动，但文字会环绕（半脱离）
3. display: none —— 完全移除

不脱离文档流但改变定位：
- position: relative —— 占据原位置，视觉偏移
- transform —— 视觉偏移，不改变布局位置
```

```css
/* float 的半脱离：脱离普通流，但文字环绕 */
img {
  float: left;
}
/* 文字会环绕图片，而不是图片下面的元素补上来 */
```

## 二、布局（难度：★☆☆ → ★★☆）

### Q7: `position` 的 5 个值分别怎么定位？

| 值         | 定位基准                                                | 是否脱离文档流 | 是否影响兄弟布局 |
| ---------- | ------------------------------------------------------- | -------------- | ---------------- |
| `static`   | 默认，正常文档流                                        | ❌             | ❌               |
| `relative` | 自己原来的位置                                          | ❌（保留位置） | ❌               |
| `absolute` | **最近的非 static 定位祖先**（没有则相对 viewport）     | ✅             | ✅               |
| `fixed`    | **视口（viewport）**（有 transform 祖先时改相对该祖先） | ✅             | ✅               |
| `sticky`   | 最近滚动容器，相对流内位置 + 视口阈值双重定位           | 流动定位       | 特殊             |

```css
/* sticky 实现吸顶（无需 JS） */
.header {
  position: sticky;
  top: 0; /* 滚到顶部时吸住 */
  z-index: 10;
}
```

**易错点**：

```css
/* 1. fixed 的包含块陷阱：祖先有 transform/filter/perspective 时，fixed 相对该祖先定位 */
.parent {
  transform: translateZ(0); /* 创建包含块，子元素 fixed 失效变 absolute */
}

/* 2. absolute 定位必须给父级加 relative（否则相对 body 定位，布局会乱） */
.parent {
  position: relative;
}
.child {
  position: absolute;
  right: 0;
}
```

### Q8: 水平垂直居中有哪些方案？（高频手写）

```html
<div class="parent">
  <div class="child">内容</div>
</div>
```

```css
/* 方案 1：flex（最推荐） */
.parent {
  display: flex;
  justify-content: center; /* 水平 */
  align-items: center; /* 垂直 */
}

/* 方案 2：grid */
.parent {
  display: grid;
  place-items: center;
}

/* 方案 3：absolute + transform（父级需 relative） */
.parent {
  position: relative;
}
.child {
  position: absolute;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);
}

/* 方案 4：absolute + 四边 0 + margin auto（需定宽高） */
.child {
  position: absolute;
  top: 0;
  right: 0;
  bottom: 0;
  left: 0;
  margin: auto;
  width: 100px;
  height: 100px;
}

/* 方案 5：text-align + line-height（单行文本垂直居中） */
.parent {
  line-height: 200px; /* 等于容器高度 */
  text-align: center;
}
```

### Q9: 实现三栏布局（圣杯 / 双飞翼 / flex / grid）

**两翼固定宽度、中间自适应**：

```css
/* 方案 1：flex（最简单） */
.container {
  display: flex;
}
.left {
  width: 200px;
}
.right {
  width: 200px;
}
.center {
  flex: 1; /* 自适应 */
}

/* 方案 2：grid */
.container {
  display: grid;
  grid-template-columns: 200px 1fr 200px;
}

/* 方案 3：float（圣杯布局核心思想） */
.left {
  float: left;
  width: 200px;
}
.right {
  float: right;
  width: 200px;
}
.center {
  margin: 0 200px; /* 中间留出两侧空间 */
}

/* 方案 4：absolute */
.left {
  position: absolute;
  left: 0;
  width: 200px;
}
.right {
  position: absolute;
  right: 0;
  width: 200px;
}
.center {
  margin: 0 200px;
}
```

**圣杯 vs 双飞翼的区别**：

| 方案   | 核心实现                        | 缺点                         |
| ------ | ------------------------------- | ---------------------------- |
| 圣杯   | `padding` 撑开 + 负 margin 归位 | 结构复杂，宽度小于左栏会错乱 |
| 双飞翼 | 中间再加一层 div，`margin` 让位 | 多一层 DOM                   |
| flex   | `flex: 1`                       | 兼容性现代浏览器             |
| grid   | `grid-template-columns`         | 同上                         |

### Q10: Flexbox 布局核心面试点

**主轴与交叉轴**：

```
默认（flex-direction: row）：
主轴（main axis）→ 水平向右
交叉轴（cross axis）↓ 垂直向下

flex-direction: column 时互换
```

**flex 属性的完整解析**（高频必问）：

```css
/* flex: 1 是简写，等于 */
flex-grow: 1; /* 剩余空间分配比例 */
flex-shrink: 1; /* 空间不足时缩小比例 */
flex-basis: 0%; /* 主轴方向的初始尺寸 */

/* 常见用法 */
flex: 1; /* 等分剩余空间（经典自适应） */
flex: 0 0 100px; /* 固定 100px，不伸缩 */
flex: auto; /* flex: 1 1 auto，按内容尺寸分配 */
```

**核心对齐属性**：

```css
/* 主轴对齐：水平方向（row 时） */
justify-content: flex-start | flex-end | center | space-between | space-around | space-evenly;

/* 交叉轴对齐：垂直方向（row 时） */
align-items: stretch（默认拉伸） | flex-start | center | baseline;

/* 交叉轴整体对齐（多行时）： */
align-content: flex-start | center | space-between; /* 需要 flex-wrap: wrap */

/* 单个项目覆盖 */
align-self: center;

/* 换行 */
flex-wrap: wrap;
```

**易错点**：

```css
/* 1. align-items 是单行内对齐，align-content 是多行整体对齐 */
/* 2. 子元素 margin: auto 可以吃掉剩余空间实现居中/靠右 */
.child {
  margin: auto; /* flex 容器中 === 居中 */
}
/* 3. min-width 陷阱：flex 子项内容过长默认不收缩到小于内容宽度 */
.child {
  min-width: 0; /* 允许收缩 */
}
```

### Q11: Grid 布局核心面试点

```css
.container {
  display: grid;

  /* 列/行轨道 */
  grid-template-columns: 200px 1fr 2fr; /* 固定 + 比例 */
  grid-template-columns: repeat(3, 1fr); /* 重复 */
  grid-template-columns: repeat(auto-fill, minmax(120px, 1fr)); /* 自动填充 */

  /* 区域命名 */
  grid-template-areas:
    "header header header"
    "sidebar main main"
    "footer footer footer";

  /* 间距 */
  gap: 16px; /* 替代旧版 grid-gap */
}

.item {
  grid-area: main; /* 放进 named area */
}

/* 跨行跨列 */
.item {
  grid-row: 1 / 3;
  grid-column: 1 / 3; /* 占 1-2 列 */
}
```

**Grid 与 Flex 的选择**：

| 维度     | Flexbox                    | Grid                         |
| -------- | -------------------------- | ---------------------------- |
| 布局方向 | **一维**（单轴，主+交叉）  | **二维**（行列同时控制）     |
| 适合场景 | 组件内部、导航栏、列表排列 | 页面骨架、卡片墙、整页布局   |
| 对齐     | 单行内对齐                 | 区域整体对齐                 |
| 经典     | 侧边栏+内容、按钮组        | 12 栏系统、Dashboard、九宫格 |

```css
/* 等宽卡片墙（Grid 经典） */
.grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));
  gap: 16px;
}
```

### Q12: 如何实现响应式布局？rem / em / vw / vh 有什么区别？

| 单位        | 基准                             | 特点                           |
| ----------- | -------------------------------- | ------------------------------ |
| `px`        | 固定像素                         | 不随屏幕变化                   |
| `em`        | **父元素**字体大小（嵌套会累积） | 复合嵌套时难控制               |
| `rem`       | **根元素 html**字体大小          | 全局统一，媒体查询改 html 即可 |
| `vw`        | 视口宽度 1%                      | 直接随屏幕，`100vw` = 视口宽   |
| `vh`        | 视口高度 1%                      | `100vh` = 视口高               |
| `vmin/vmax` | 视口短边/长边的 1%               | 屏幕旋转时保持比例             |

**rem 适配方案**（动态根字号）：

```js
// 方案 1：JS 动态设置根字号（设计稿 375 宽）
function setRem() {
  const width = document.documentElement.clientWidth
  document.documentElement.style.fontSize = width / 10 + "px"
}
window.addEventListener("resize", setRem)
setRem()
// 之后 1rem = 37.5px，设计稿 75px 就写 2rem
```

```css
/* 方案 2：纯 CSS 媒体查询断点 */
html {
  font-size: 16px;
}
@media (min-width: 768px) {
  html {
    font-size: 18px;
  }
}
@media (min-width: 1024px) {
  html {
    font-size: 20px;
  }
}
```

```css
/* 方案 3：vw 直接适配（纯 CSS，无 JS） */
html {
  font-size: 10vw; /* 375 宽时 = 37.5px */
}
```

**媒体查询常用断点**：

```css
@media (max-width: 480px) {
} /* 手机 */
@media (min-width: 768px) {
} /* 平板 */
@media (min-width: 992px) {
} /* 桌面 */
@media (min-width: 1200px) {
} /* 大屏 */
```

### Q13: 移动端 1px 问题怎么解决？

**问题**：CSS 1px 在 Retina 屏（dpr=2/3）上会渲染成 2-3 物理像素，看起来比设计稿粗。

```css
/* 方案 1：transform: scale（最常用） */
.border-1px {
  position: relative;
}
.border-1px::after {
  position: absolute;
  bottom: 0;
  left: 0;
  transform: scaleY(0.5); /* dpr=2 时缩小一半 */
  transform-origin: 0 0;
  background: #ddd;
  width: 100%;
  height: 1px;
  content: "";
}
```

```js
// 方案 2：根据 dpr 动态设置视口（配合 px→rem 缩放）
const dpr = window.devicePixelRatio
const scale = 1 / dpr
document.write(`
  <meta name="viewport" content="width=device-width, initial-scale=${scale}, user-scalable=no">
`)
```

```css
/* 方案 3：border-image 或 box-shadow */
.border {
  box-shadow: 0 0 0 0.5px #ddd; /* 某些浏览器支持 0.5px */
  border: 1px solid #ddd;
}
```

## 三、样式细节（难度：★★☆）

### Q15: 什么是 BFC？如何触发？解决了什么问题？

**BFC（Block Formatting Context，块级格式化上下文）**：独立的渲染区域，内部元素的布局不会影响外部。

```
BFC 规则：
1. 内部元素垂直方向排列，margin 不合并（隔离）
2. BFC 区域不会与 float 元素重叠
3. 计算高度时包含浮动子元素
4. 每个 BFC 之间互不影响
```

**触发条件**：

```css
/* 常用触发方式 */
.element {
  display: flex / grid; /* ② 现代布局 */
  display: inline-block; /* ③ */
  position: absolute / fixed; /* ④ */
  float: left / right; /* ⑤ */
  overflow: hidden; /* ① overflow 非 visible（最常用） */
}
/* 不触发：overflow: visible、position: static、display: block */
```

**解决的经典问题**：

```css
/* 问题 1：浮动子元素导致父元素高度塌陷 */
.parent {
  overflow: hidden; /* 触发 BFC，父元素计算高度包含浮动子元素 */
}
.child {
  float: left;
}

/* 问题 2：两列布局浮动重叠 */
.left {
  float: left;
  width: 200px;
}
.right {
  overflow: hidden; /* BFC 不与 float 重叠 → 右侧自适应 */
}

/* 问题 3：margin 合并 */
/* 两个兄弟块级元素垂直 margin 取较大值（合并） */
/* 解决：给其中一个包裹触发 BFC 的容器，或改用 flex/grid */
```

### Q24: `transition` 和 `animation` 的区别？

| 对比项 | transition（过渡）               | animation（动画）              |
| ------ | -------------------------------- | ------------------------------ |
| 触发   | **需要状态改变**（hover/类切换） | **自动播放**，无需外部触发     |
| 帧控制 | 只有开始和结束（自动插值）       | **关键帧** `@keyframes` 多阶段 |
| 循环   | ❌ 不能循环                      | ✅ `iteration-count` 循环      |
| 反向   | 移除状态自动恢复                 | ✅ `animation-direction`       |
| 暂停   | ❌                               | ✅ `animation-play-state`      |

```css
/* transition */
.box {
  transition: width 0.3s ease 0.1s; /* 属性 时长 缓动 延迟 */
  width: 100px;
}
.box:hover {
  width: 200px;
}

/* animation */
@keyframes slide-in {
  from {
    transform: translateX(-100%);
  }
  to {
    transform: translateX(0);
  }
}
.box {
  animation: slide-in 1s ease-in-out infinite alternate;
  /*         名称    时长  缓动    循环   往返    */
}
```

**transition 易错点**：

```css
/* 1. 必须声明初始值才能过渡 */
.box {
  opacity: 1; /* 没有显式声明初始 opacity，hover 过渡不生效 */
}
/* 2. 默认只过渡已知属性，display 无法过渡（用 visibility/opacity 组合） */
/* 3. 多个属性逗号分隔 */

  opacity 0.3s,
  transform 0.3s;
/* 4. 简写顺序：property duration easing delay，delay 必须第二个时间值 */
```

### Q26: 为什么说 `transform` 和 `opacity` 动画性能好？

```
浏览器的渲染流水线：
JS → 样式计算 → 布局(layout) → 绘制(paint) → 合成(composite)

transform/opacity 只影响「合成」阶段
→ 跳过 layout 和 paint，由 GPU 合成器直接处理（走合成层）
→ 不触发重排重绘，可达到 60fps

而 width/height/left/top/margin 动画：
→ 每帧触发 layout + paint，主线程被占用，容易掉帧
```

```css
/* 正确做法：用 transform 替代 left/top */
.bad {
  left: 100px;
  transition: left 0.3s; /* ❌ 触发重排 */
}
.good {
  transform: translateX(100px);
  transition: transform 0.3s; /* ✅ 合成层动画 */
}

/* will-change 提前告知浏览器创建合成层 */
.smooth {
  will-change: transform; /* 仅对确实要动的元素使用，勿滥用 */
}
```

## 六、渲染原理与性能（难度：★★★）

### Q33: 浏览器是如何渲染页面的（关键渲染路径）？

```
① HTML 解析 → DOM 树
② CSS 解析 → CSSOM 树
③ DOM + CSSOM → Render Tree（渲染树）
④ Layout（布局）：计算每个节点的几何位置
⑤ Paint（绘制）：绘制像素
⑥ Composite（合成）：GPU 合成图层

注意：JS 位于 link/css 之后会阻塞渲染；CSS 阻塞渲染但 JS 可提前
```

```
具体流程：
HTML ──▶ DOM
                └──▶ Render Tree ──▶ Layout ──▶ Paint ──▶ Composite
CSS  ──▶ CSSOM
```

**优化关键渲染路径**：

```html
<!-- 1. 关键 CSS 内联（首屏无额外请求） -->
<style>
  .hero { ... }
</style>
<!-- 2. 非关键 CSS 异步加载（defer 思路） -->
<!-- 3. 避免 @import（串行阻塞） -->
<!-- 4. 减少 CSS 选择器复杂度（影响样式计算耗时） -->
```

### Q34: 重排（reflow）和重绘（repaint）的区别？如何避免？

| 对比项 | 重排（Reflow/Layout）             | 重绘（Repaint）      |
| ------ | --------------------------------- | -------------------- |
| 内容   | 重新计算**几何信息**（位置/尺寸） | 重新**绘制像素**     |
| 代价   | **大**（重排必然引起重绘）        | 相对小（如颜色变化） |
| 触发   | 增删元素、改宽高/字体/窗口 resize | 改颜色、背景、可见性 |

**触发重排的操作**（记住清单）：

```js
// 1. 增删改 DOM 节点
// 2. 修改几何属性：width/height/margin/padding/font-size
// 3. 修改 position
// 4. 获取强制同步布局的属性（读这些会强制重排！）
offsetWidth / offsetHeight / offsetTop / offsetLeft
clientWidth / clientHeight
getBoundingClientRect()
getComputedStyle()
scrollTop / scrollWidth
```

```js
// 避免强制同步布局（读写分离）
// ❌ 循环里读-写交替，每次都强制重排
for (let i = 0; i < list.length; i++) {
  const w = el.offsetWidth // 读 → 强制布局
  el.style.width = w + 10 + "px" // 写 → 重排
}
// ✅ 先统一读，再统一写（或使用 RAF 批量写）
const widths = list.map((el) => el.offsetWidth)
list.forEach((el, i) => {
  el.style.width = widths[i] + 10 + "px"
})

// 批量修改 DOM：DocumentFragment / display:none 后改
```

**避免重排的常用手段**：

```css
/* 1. 动画用 transform/opacity（合成层动画） */
/* 2. 固定动画元素尺寸、position: fixed 脱离文档流 */
/* 3. contain 属性：告知浏览器该元素独立 */
.panel {
  contain: layout paint; /* 内部变化不影响外部 */
}
/* 4. 用 class 切换替代逐属性修改 */
```

### Q35: 如何提升 CSS 选择器性能？

```
选择器匹配是从右往左（从元素向上找祖先），
所以「最右侧的选择器」越具体越好。

性能建议（经验排序）：
1. 避免通配符 *（最右侧尤其不能）
2. 避免后代选择器嵌套过深（#nav .menu .item a）
3. 避免使用标签选择器做右侧（div）
4. 类选择器是最佳平衡（唯一性 + 匹配快）
5. 避免不必要的 !important
6. 层级控制在 3 层以内
```

```css
/* 差 */

  color: red;
}
/* 好 */
.nav-link {
  color: red;
}

/* 但注意：现代浏览器选择器匹配已很快，过度优化无必要，
 * 更重要的是减少选择器数量与嵌套层数（影响样式计算） */
```

```
content-visibility: auto
├── 屏幕内：正常渲染
└── 屏幕外：跳过 layout/paint（渲染速度提升数倍）
    → 配合 contain-intrinsic-size 占位避免布局跳动
```

### Q37: 什么是层叠上下文？z-index 为什么会失效？

**创建层叠上下文的常见属性**：

```css
/* 1. 根元素 html */
/* 2. position + z-index（非 auto） */
position: relative;
z-index: 1;
/* 3. 不透明度的元素：opacity < 1 */
opacity: 0.5;
/* 4. transform / filter / perspective */
transform: translateZ(0);
/* 5. will-change 指定以上属性 */
/* 6. flex/grid 子项 + z-index */
/* 7. mix-blend-mode / isolation: isolate */
```

**z-index 失效的场景**：

```css
/* 失效原因 1：父级没有创建层叠上下文（z-index 需配合 position） */
.box {
  position: static;
  z-index: 999;
} /* ❌ 无效 */

/* 失效原因 2：父级层叠上下文把子级"关起来"了 */
.parent {
  position: relative;
  z-index: 1; /* 父级自成一个层叠上下文 */
}
.child {
  z-index: 999; /* 只在父级上下文内有效，永远打不过外层更高层的元素 */
}

/* 失效原因 3：同级比较，先看父级 */
/* 结论：z-index 只在同一个层叠上下文内比较 */
```

### Q38: 包含块（Containing Block）是什么？`absolute` 和 `fixed` 的包含块差异？

```
包含块 = 决定元素百分比尺寸/定位参照的"参照框"

- static/relative 元素：包含块 = 最近的块级祖先的内容盒（content box）
- absolute 元素：包含块 = 最近的非 static 定位祖先的「内边距盒（padding box）」
  └ 没有定位祖先时 = 初始包含块（视口大小）
- fixed 元素：包含块 = 视口（除非祖先有 transform/perspective/filter 等）
```

```css
.parent {
  position: relative;
  padding: 20px;
}
.child {
  position: absolute;
  left: 0; /* 相对 parent 的 padding 边缘（不是 content 边缘） */
  width: 50%; /* 相对 parent 的 content 宽度？不：padding box 宽度 */
}
```

**transform 陷阱（fixed 变 absolute）**：

```css
.ancestor {
  transform: translateZ(0); /* 这行会让子元素的 fixed 失效！ */
}
.child {
  position: fixed; /* 不再相对视口，而是相对 .ancestor */
}
```

### Q39: IFC / GFC / FFC 是什么？

```
格式化上下文（Formatting Context）：
├── BFC（Block FC）      —— 块级元素的布局规则（Q15 已述）
├── IFC（Inline FC）     —— 行内元素的布局规则
│    ├── 行内元素水平排列，超出换行
│    ├── 行高（line box）由内容最高元素决定
│    ├── vertical-align 控制行内元素垂直对齐
│    └── 幽灵空白：行内元素/图片下方有缝隙（vertical-align: middle 解决）
├── FFC（Flex FC）       —— display: flex 创建
└── GFC（Grid FC）       —— display: grid 创建
```

```css
/* 图片底部 3px 空隙（IFC 幽灵空白）的解决 */
img {
  display: block; /* 方案 1：变块级 */
  vertical-align: middle; /* 方案 2：对齐方式 */
  /* 或父容器 font-size: 0; */
}
```

### Q48: `margin` 合并（塌陷）的场景和解决？

### Q49: `line-height` 的取值方式有何区别？

```css
/* 数值：相对自身 font-size（推荐，可继承） */
line-height: 1.5; /* = 1.5 × font-size */

/* 长度：固定值 */
line-height: 24px;

/* 百分比：相对当前 font-size，但继承的是计算后的值 */
line-height: 150%; /* 继承时按父级计算结果传递 */

/* 关键区别：数值随元素自己的 font-size 变化，百分比继承死值 */
.parent {
  font-size: 20px;
  line-height: 150%;
} /* 计算得 30px */
.child {
  font-size: 10px;
} /* 子继承 30px 而非 150%！ */
/* 用数值 1.5 则子级自动 = 15px ✓ */
```

### Q50: `width: 100%` 与 `width: auto` 的区别？

| 对比项               | `width: auto`（默认）           | `width: 100%`                            |
| -------------------- | ------------------------------- | ---------------------------------------- |
| 基准                 | 自动填满父容器 **content** 宽度 | 父容器 **content** 宽度的 100%           |
| 有 padding/border 时 | 自动收缩让出空间（总宽 = 父宽） | **溢出**！总宽 = 父宽 + padding + border |
| 推荐                 | ✅ 尽量用 auto                  | ❌ 需要手动 box-sizing 配合              |

```css
.box {
  padding: 16px;
  width: 100%; /* 再加 padding 就横向溢出 */
}
/* 正确写法：width: auto 或 width: 100% + box-sizing: border-box */
```

### Q51: `display: none` 和 `visibility: hidden` 的补充考点？

```css
/* display: none 的元素 —— 不生成盒，不占位 */
/* visibility: hidden 的元素 —— 占位但不可见 */
/* 注意：visibility 可继承！父 hidden 子 visible 可以恢复 */
.parent {
  visibility: hidden;
}
.child {
  visibility: visible; /* ✅ 子元素可以重新显示！display:none 做不到 */
}
```

### Q52: `z-index: auto` 和 `z-index: 0` 的区别？

```css
/* 关键区别：z-index: 0 会创建层叠上下文，auto 不会 */
.box {
  position: relative;
  z-index: 0; /* 创建层叠上下文：内部元素 z-index 被限制在 0 层级 */
}
.box {
  position: relative;
  z-index: auto; /* 不创建：内部元素可正常参与外层比较 */
}
```
