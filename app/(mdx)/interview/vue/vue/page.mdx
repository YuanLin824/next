## 一、响应式系统

### Q1: Vue 2 和 Vue 3 的响应式原理有什么区别？

**Vue 2 — `Object.defineProperty`**：

```js
// Vue 2 原理简化
function observe(obj) {
  if (typeof obj !== "object" || obj === null) return
  for (let key of Object.keys(obj)) {
    let val = obj[key]
    observe(val) // 递归劫持
    Object.defineProperty(obj, key, {
      get() {
        console.log(`读取 ${key}`)
        return val
      },
      set(newVal) {
        console.log(`设置 ${key} = ${newVal}`)
        if (newVal !== val) {
          val = newVal
          observe(newVal) // 新值是对象也需要劫持
          // 通知更新...
        }
      },
    })
  }
}
```

**Vue 3 — `Proxy`**：

```js
function reactive(obj) {
  return new Proxy(obj, {
    get(target, key, receiver) {
      if (typeof target[key] === "object" && target[key] !== null) {
        return reactive(target[key]) // 懒代理（用到时才递归）
      }
      return Reflect.get(target, key, receiver)
    },
    set(target, key, value, receiver) {
      const result = Reflect.set(target, key, value, receiver)
      console.log(`设置 ${String(key)} = ${value}`)
      return result
    },
    deleteProperty(target, key) {
      console.log(`删除 ${String(key)}`)
      return Reflect.deleteProperty(target, key)
    },
  })
}
```

| 维度          | Vue 2                                            | Vue 3                            |
| ------------- | ------------------------------------------------ | -------------------------------- |
| 实现方式      | `Object.defineProperty`                          | `Proxy`                          |
| 数组监听      | ❌ 不能监听索引赋值/`length`（7 个变异方法重写） | ✅ 天然支持                      |
| 新增/删除属性 | ❌ `Vue.set` / `Vue.delete`                      | ✅ 直接 `obj.newProp = val`      |
| 性能          | 初始化递归所有属性（深层对象慢）                 | **懒代理** — 用到才代理          |
| 兼容性        | IE9+                                             | 不支持 IE（Proxy 不可 polyfill） |

### Q2: Vue 3 的 ref 和 reactive 有什么区别？

```ts
import { ref, reactive, isRef, toRef, toRefs } from "vue"

// ref — 包装原始值为响应式对象 ❯ .value 读写
const count = ref(0) // ref(0) → { value: 0 }
count.value++ // 触发更新
console.log(isRef(count)) // true

// reactive — 包装对象为响应式代理（深层）
const state = reactive({ name: "Alice", age: 18 })
state.name = "Bob" // 直接读写（不需要 .value）

// ref 也可以包对象 — 内部调用 reactive
const user = ref({ name: "Alice" }) // ref → reactive({ name: "Alice" })

// toRef / toRefs — 解构 reactive 保持响应式
const { name, age } = toRefs(state) // name → Ref<string>
// ❌ const { name } = state         // 解构后丢失响应式

// 模板中 ref 自动解包
// <div>{{ count }}</div> — 不需要 count.value
```

| 维度           | `ref`                      | `reactive`            |
| -------------- | -------------------------- | --------------------- |
| 参数类型       | 任意值（原始/对象）        | 仅对象/数组           |
| 访问方式       | `.value`（模板中自动解包） | 直接访问              |
| 解构保持响应式 | 需 `toRefs`                | 需 `toRefs`           |
| 替换整体       | ✅ `ref.value = newObj`    | ❌ 重新赋值丢失响应式 |
| 类型推导（TS） | 较好                       | 一般                  |
| **推荐场景**   | **首选**（Vue 官方推荐）   | 表单对象/数据聚合     |

### Q3: 说一说 Vue 的依赖收集（Dep / Effect）机制？

```
组件渲染时:
  读取响应式数据 → get 拦截 → track（收集当前 effect）
数据变化时:
  修改响应式数据 → set 拦截 → trigger（通知收集的 effects 重新执行）
```

```js
// Vue 3 简化实现
let activeEffect = null
const targetMap = new WeakMap()

function track(target, key) {
  if (!activeEffect) return
  let depsMap = targetMap.get(target)
  if (!depsMap) targetMap.set(target, (depsMap = new Map()))
  let deps = depsMap.get(key)
  if (!deps) depsMap.set(key, (deps = new Set()))
  deps.add(activeEffect) // 收集依赖
}

function trigger(target, key) {
  const depsMap = targetMap.get(target)
  if (!depsMap) return
  const deps = depsMap.get(key)
  deps?.forEach((effect) => effect()) // 通知更新
}
```

### Q4: computed 和 watch 有什么区别？怎么选？

| 维度   | `computed`                   | `watch`                         |
| ------ | ---------------------------- | ------------------------------- |
| 缓存   | ✅ 依赖不变不重新计算        | ❌ 每次触发都执行               |
| 返回值 | 返回一个 ref                 | 无返回值（执行副作用）          |
| 异步   | ❌ 不支持                    | ✅ `async` 回调                 |
| 场景   | 派生数据（过滤/格式化/求和） | 数据变化后的副作用（请求/存储） |

```ts
// computed — 有缓存，派生数据
const fullName = computed(() => `${firstName.value} ${lastName.value}`)

// computed 可写
const fullName = computed({
  get: () => `${firstName.value} ${lastName.value}`,
  set: (val) => {
    ;[firstName.value, lastName.value] = val.split(" ")
  },
})

// watch — 无返回值，副作用
watch(searchQuery, async (newVal) => {
  results.value = await fetch(`/api/search?q=${newVal}`)
})

// watchEffect — 自动追踪依赖
watchEffect(() => {
  console.log(`count 现在是 ${count.value}`)
})
```

### Q5: watchEffect 和 watch 有什么区别？

```ts
// watch — 手动指定监听源
watch(count, (newVal, oldVal) => console.log(newVal, oldVal))
watch([count, name], ([newC, newN]) => {}) // 多个源

// watchEffect — 自动追踪回调中的响应式依赖
watchEffect(() => {
  // 自动追踪 count.value 和 name.value
  document.title = `${name.value}: ${count.value}`
})

// 区别
watch(count, (newVal, oldVal) => {
  // ✅ 可访问 oldValue
  // ✅ 懒执行（默认不立即执行，需 { immediate: true }）
})
watchEffect(() => {
  // ❌ 无法获取 oldValue
  // ✅ 立即执行（适合初始化副作用）
})
```

## 二、组合式 API

### Q6: Vue 3 Composition API 解决了什么问题？

```ts
// ❌ Options API 的问题：同一功能分散在不同选项中
export default {
  data() {
    return { searchQuery: "", results: [] }
  },
  watch: {
    searchQuery: {
      handler(q) {
        this.search(q)
      },
    },
  },
  methods: {
    async search(q) {
      this.results = await fetch(q)
    },
  },
  mounted() {
    /* 初始化 */
  },
}

// ✅ Composition API：同一功能的代码聚在一起
function useSearch() {
  const query = ref("")
  const results = ref([])
  watch(query, async (q) => {
    results.value = await fetch(q)
  })
  onMounted(() => {
    /* 初始化 */
  })
  return { query, results }
}
```

## 三、组件通信

### Q9: Vue 的组件通信方式有哪些？

| 方式                    | Vue 2    | Vue 3          | 方向            |
| ----------------------- | -------- | -------------- | --------------- |
| Props / emit            | ✅       | ✅             | 父 ↔ 子         |
| `v-model`               | ✅ (1个) | ✅ (多个)      | 父 ↔ 子         |
| `$refs` / `ref`         | ✅       | ✅             | 父 → 子         |
| `$parent` / `$children` | ✅       | ❌ 废弃        | 父 ↔ 子         |
| Provide / Inject        | ✅       | ✅             | 祖先 → 后代     |
| EventBus (`$on/$emit`)  | ✅       | ❌ 移除        | 任意            |
| Vuex / Pinia            | ✅       | ✅             | 全局            |
| `$attrs` / `$listeners` | ✅       | ✅ (Vue3 合并) | 父 → 子（透传） |

```vue
<!-- 1. Props + Emit -->
<!-- 子: -->
<script setup>
const props = defineProps({ msg: String })
const emit = defineEmits(["update"])
emit("update", "新值")
</script>

<!-- 2. v-model (Vue 3 支持多个) -->
<Child v-model:title="title" v-model:content="content" />
<!-- 子组件: defineProps({ title, content }) + defineEmits(['update:title', 'update:content']) -->

<!-- 3. 模板 ref → 访问子组件实例 -->
<Child ref="childRef" />
<script setup>
const childRef = ref(null)
</script>

<!-- 4. Provide / Inject -->
<!-- 祖先: -->
<script setup>
provide("key", value)
</script>
<!-- 后代: -->
<script setup>
const value = inject("key")
</script>

<!-- 5. $attrs 透传 — 未声明为 props 的属性自动传递到根元素 -->
<Child class="extra" @click="handleClick" />
```

### Q10: v-if 和 v-show 有什么区别？v-for 的 key 为什么重要？

| 区别          | `v-if`            | `v-show`                 |
| ------------- | ----------------- | ------------------------ |
| DOM 销毁/创建 | ✅ 真正的条件渲染 | ❌ 仅 CSS `display` 切换 |
| 初始渲染开销  | 小（不渲染）      | 大（始终渲染）           |
| 切换开销      | 大（重建/销毁）   | 小（CSS 切换）           |
| 适用          | 条件很少改变      | 频繁切换                 |

```vue
<!-- key 的作用：diff 算法中高效复用/重新排序 DOM -->
<li v-for="item in list" :key="item.id">{{ item.name }}</li>
<!-- ❌ 不要用 index 作为 key（列表顺序变化时 diff 失效） -->
```

### Q11: v-if 和 v-for 为什么不能同时使用？

Vue 2 中 `v-for` 优先级高于 `v-if`，导致每次渲染都先遍历再判断（性能浪费）。

```vue
<!-- ❌ Vue 2/3 都不推荐 -->
<li v-for="item in list" v-if="item.active" :key="item.id">

<!-- ✅ 用 computed 先过滤 -->
<li v-for="item in activeList" :key="item.id">
```

> Vue 3 中 `v-if` 优先级高于 `v-for`，但**仍然不推荐同用**。

## 四、核心机制

### Q12: Vue 的虚拟 DOM 和 diff 算法？

```
模板 template → 编译 → 渲染函数 → VNode 树
  ↓ 数据变化
新 VNode 树 → diff 对比旧 VNode → patch 更新真实 DOM
```

**Diff 算法优化（Vue 3 新增）：**

```txt
1. 静态标记 (PatchFlags): 编译时标记动态部分 — 只比较带标记的节点
2. 静态提升 (HoistStatic): 静态节点复用不重复创建
3. 事件缓存 (CacheHandlers): 内联函数缓存，避免子组件无意义更新
4. Block Tree: 动态节点链表，跳过静态子树
```


## 八、高频手写与原理

### Q20: 手写 Vue 2 响应式（简化版）

```js
class Dep {
  constructor() {
    this.subs = []
  }
  depend() {
    if (Dep.target) this.subs.push(Dep.target)
  }
  notify() {
    this.subs.forEach((w) => w.update())
  }
}

class Watcher {
  constructor(vm, key, cb) {
    this.vm = vm
    this.key = key
    this.cb = cb
    Dep.target = this
    this.oldValue = vm[key] // 触发 get → 依赖收集
    Dep.target = null
  }
  update() {
    const newVal = this.vm[this.key]
    if (newVal !== this.oldValue) {
      this.cb(newVal, this.oldValue)
      this.oldValue = newVal
    }
  }
}

function defineReactive(obj, key, val) {
  const dep = new Dep()
  Object.defineProperty(obj, key, {
    get() {
      dep.depend()
      return val
    },
    set(newVal) {
      if (newVal !== val) {
        val = newVal
        dep.notify()
      }
    },
  })
}
```

### Q21: 手写 Vue 3 reactive

```js
const targetMap = new WeakMap()
let activeEffect = null

function reactive(obj) {
  return new Proxy(obj, {
    get(target, key, receiver) {
      track(target, key)
      const result = Reflect.get(target, key, receiver)
      return typeof result === "object" && result !== null ? reactive(result) : result
    },
    set(target, key, value, receiver) {
      const oldVal = target[key]
      const result = Reflect.set(target, key, value, receiver)
      if (oldVal !== value) trigger(target, key)
      return result
    },
  })
}

function track(target, key) {
  if (!activeEffect) return
  let depsMap = targetMap.get(target) || targetMap.set(target, new Map()).get(target)
  let deps = depsMap.get(key) || depsMap.set(key, new Set()).get(key)
  deps.add(activeEffect)
}

function trigger(target, key) {
  targetMap
    .get(target)
    ?.get(key)
    ?.forEach((e) => e())
}

function effect(fn) {
  activeEffect = fn
  fn()
  activeEffect = null
}
```

### Q22: 手写 Vue 3 ref

```js
function ref(value) {
  return new RefImpl(value)
}

class RefImpl {
  constructor(value) {
    this._value = toReactive(value)
    this._rawValue = value
    this.dep = new Set()
  }
  get value() {
    trackRef(this)
    return this._value
  }
  set value(newVal) {
    if (newVal !== this._rawValue) {
      this._rawValue = newVal
      this._value = toReactive(newVal)
      triggerRef(this)
    }
  }
}

function toReactive(value) {
  return typeof value === "object" && value !== null ? reactive(value) : value
}
```

### Q23: Vue 中如何做权限控制？

### Q30: 如何在组合式函数 (Composable) 中用好 TypeScript？

```ts
// 泛型 Composable
export function useList<T>(fetchFn: () => Promise<T[]>) {
  const list = ref<T[]>([])
  const loading = ref(false)
  const error = ref<string | null>(null)

  async function refresh() {
    loading.value = true
    error.value = null
    try {
      list.value = await fetchFn()
    } catch (e) {
      error.value = (e as Error).message
    } finally {
      loading.value = false
    }
  }

  return { list, loading, error, refresh }
}

// 使用 — 类型自动推导
const { list, loading } = useList(() => fetch("/api/users").then((r) => r.json()))
// list → Ref<User[]>
```

## 十二、服务端渲染 (SSR)

### Q31: Vue SSR 的工作原理？Nuxt.js 能解决什么问题？

```
客户端渲染 (CSR)：        服务端返回空 HTML → 下载 JS → 执行 JS → 渲染
服务端渲染 (SSR)：         服务端执行 Vue → 返回完整 HTML → 下载 JS → hydration（激活）
```

Nuxt.js (Vue SSR 框架) 解决的问题：

| 问题     | Nuxt 方案                   |
| -------- | --------------------------- |
| SEO 差   | 服务端渲染完整 HTML         |
| 首屏慢   | 服务端预渲染                |
| 路由配置 | 文件系统路由                |
| 数据获取 | `useFetch` / `useAsyncData` |
| 代码分割 | 自动按路由拆分              |

```ts
// Nuxt 3 — 服务端数据获取
const { data, pending } = await useFetch("/api/posts")
// 服务端请求，返回 HTML 中包含数据，客户端 hydration
```

### Q32: Vue SSR 的 hydration 过程是怎样的？

```
1. 服务端：渲染 Vue 组件 → 生成 HTML 字符串 + 序列化状态 → 返回客户端
2. 客户端：加载 HTML → Vue 创建与 SSR 相同结构的虚拟 DOM
3. hydration：对比服务端 DOM 和客户端虚拟 DOM → 复用已有 DOM 节点
4. 激活：绑定事件监听、状态 → 转为完全交互式的 SPA
```

> 注意：SSR + hydration 时，客户端和服务端状态必须一致，否则 hydration 会失败。

### Q36: MVVM 是什么？Vue 是如何体现的？

- **Model**：数据层（data/reactive/ref）
- **View**：视图层（template）
- **ViewModel**：视图模型层（Vue 实例/组件）

Vue 通过**响应式系统**和**模板编译**实现双向绑定：Model 变化自动更新 View，View 交互自动修改 Model。

### Q37: Vue 组件的 data 为什么必须是函数？

```js
// 对象形式 → 组件复用时共享同一个引用
data: { count: 0 }           // ❌ 多个组件实例操作同一个 count

// 函数形式 → 每次调用返回新对象
data() { return { count: 0 } } // ✅ 每个组件实例独立
```
