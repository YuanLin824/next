# Next.js 面试题

---

## 一、基础概念

### Q1: 什么是 Next.js？它解决了 React 的哪些问题？

Next.js 是 React 的**全栈框架**，在 React 之上提供：

| React 的问题                | Next.js 的方案                         |
| --------------------------- | -------------------------------------- |
| 纯客户端渲染，SEO 差        | **SSR / SSG / ISR** — 服务端渲染       |
| 首屏白屏时间长              | 服务端预渲染 HTML                      |
| 路由需手动引入 react-router | **文件系统路由**（File-based Routing） |
| 数据获取需手动管理          | `fetch` + 自动请求去重 + 缓存          |
| 图片/字体等资源优化缺失     | `<Image>` / `<Link>` 等内置优化组件    |
| 没有统一的构建配置          | 自带 Webpack/Turbopack 构建            |

### Q2: Next.js 的渲染方式有哪些？各自什么区别？

| 渲染方式                  | 数据获取时机                    | 适用场景             |
| ------------------------- | ------------------------------- | -------------------- |
| **CSR** (Client-Side)     | 浏览器请求时（useEffect/fetch） | 仪表盘、需登录的页面 |
| **SSR** (Server-Side)     | 每次请求时服务端渲染            | 实时数据、个性化内容 |
| **SSG** (Static Site Gen) | 构建时生成静态 HTML             | 博客、文档、营销页   |
| **ISR** (Incremental)     | 构建时 + 定时后台更新           | 内容更新不频繁的页面 |

### Q3: App Router 和 Pages Router 有什么区别？

| 维度     | Pages Router                            | App Router                                  |
| -------- | --------------------------------------- | ------------------------------------------- |
| 引入版本 | Next.js 1.0                             | **Next.js 13+**（推荐）                     |
| 路由文件 | `pages/about.tsx`                       | `app/about/page.tsx`                        |
| 布局     | `_app.tsx` + `_document.tsx`            | **嵌套 Layout** (`layout.tsx`)              |
| 数据获取 | `getServerSideProps` / `getStaticProps` | **`async` 组件直接 fetch**                  |
| 组件类型 | 客户端和服务端组件混合                  | **默认服务端组件**，`use client` 标记客户端 |
| 流式渲染 | ❌                                      | ✅ `loading.tsx` + Suspense                 |
| 并行路由 | ❌                                      | ✅ `@folder` 插槽                           |
| 拦截路由 | ❌                                      | ✅ `(.)path` / `(..)path`                   |

## 二、路由

### Q4: App Router 的文件约定有哪些？

```
app/
├── layout.tsx          # 布局（包裹子页面，不会重置状态）
├── page.tsx            # 页面
├── loading.tsx         # 加载中 UI（Suspense fallback）
├── error.tsx           # 错误边界（Error Boundary）
├── global-error.tsx    # 根布局错误边界
├── not-found.tsx       # 404 页面
├── template.tsx        # 模板（每次导航重新渲染，不保持状态）
├── default.tsx         # 并行路由的默认回退
├── route.ts            # API 路由（GET/POST 等）
├── middleware.ts        # 全局中间件
└── opengraph-image.tsx # OG 图片生成
```

### Q5: layout.tsx 和 template.tsx 有什么区别？

| 维度               | `layout.tsx`        | `template.tsx`               |
| ------------------ | ------------------- | ---------------------------- |
| 导航时重新挂载     | ❌ 保持状态         | ✅ 每次重新挂载              |
| useEffect 重新执行 | ❌                  | ✅                           |
| 动画               | 不容易              | 适合（每次进入都有入场动画） |
| 适用场景           | 持久化导航栏/侧边栏 | 页面埋点、入场动画、表单重置 |

```tsx
// layout — 状态保持
export default function DashboardLayout({ children }) {
  const [count, setCount] = useState(0) // 导航时不会重置
  return <div>{children}</div>
}

// template — 每次重置
export default function DashboardTemplate({ children }) {
  const [count, setCount] = useState(0) // 每次导航都重置为 0
  return <div>{children}</div>
}
```

### Q6: Next.js 如何实现动态路由和路由分组？

### Q7: middleware.ts 能做什么？不能做什么？

```ts
// middleware.ts — 在请求到达页面前执行
import { NextResponse } from "next/server"
import type { NextRequest } from "next/server"

export function middleware(request: NextRequest) {
  const token = request.cookies.get("token")
  const { pathname } = request.nextUrl

  // ✅ 能做的：路由重定向、Header 操作、A/B 测试、Geo 定位、Bot 检测
  if (pathname.startsWith("/dashboard") && !token) {
    return NextResponse.redirect(new URL("/login", request.url))
  }

  // ❌ 不能做的：数据库操作、文件读写 — 运行在 Edge Runtime，只有有限的 API
  return NextResponse.next()
}

export const config = {
  matcher: ["/dashboard/:path*", "/api/:path*"], // 限定匹配范围
}
```

## 三、数据获取

### Q8: 服务端组件如何获取数据？

App Router 中服务端组件直接 `async`，无需 `getServerSideProps`：

```tsx
// 服务端组件 — 直接在组件内 await
export default async function BlogPage() {
  let posts = await fetch("https://api.example.com/posts") // 自动请求去重

  // 或者直接操作数据库（无需 API 中间层）
  // let posts = await db.post.findMany()

  return (
    <ul>
      {posts.map((p) => (
        <li key={p.id}>{p.title}</li>
      ))}
    </ul>
  )
}
```

### Q9: fetch 的缓存策略（Next.js 15+）？

```tsx
// 1. no-store — SSR 模式，每次请求都重新获取（默认，Next.js 15+）
fetch(url) // 等同于 { cache: "no-store" }

// 2. force-cache — SSG 模式，缓存直到手动失效
fetch(url, { cache: "force-cache" })

// 3. revalidate — ISR 模式，定时后台更新
fetch(url, { next: { revalidate: 60 } }) // 60 秒后重新验证

// 4. 按标签手动失效（On-Demand Revalidation）
// API Route 中调用:
import { revalidateTag, revalidatePath } from "next/cache"

revalidateTag("posts") // 失效所有标记为 'posts' 的 fetch
fetch(url, { next: { tags: ["posts"] } })

revalidatePath("/blog") // 失效指定路径的缓存

// 5. unstable_cache — 缓存任意异步函数（不仅是 fetch）
import { unstable_cache } from "next/cache"
let getPosts = unstable_cache(async () => db.post.findMany(), ["posts"], {
  revalidate: 3600,
  tags: ["posts"],
})
```

### Q10: 客户端组件如何获取数据？

| 方式                        | 适用场景                       |
| --------------------------- | ------------------------------ |
| `useEffect` + `fetch`       | 传统客户端请求                 |
| **Server Actions**          | 表单提交、数据变更             |
| 服务端组件传 props 到客户端 | 初始数据展示                   |
| SWR / TanStack Query        | 自动缓存、revalidate、乐观更新 |

```tsx
// ✅ 推荐：服务端获取，客户端接收
// app/page.tsx
export default async function Page() {
  const initialData = await getData()
  return <ClientComponent initialData={initialData} />
}
```

## 四、Server Actions

### Q11: 什么是 Server Actions？如何使用？

Server Actions 是**在服务端执行的异步函数**，可从客户端直接调用，无需手动创建 API 路由。

```tsx
// actions/user.ts
"use server"

export async function createUser(formData: FormData) {
  const name = formData.get("name") as string
  const email = formData.get("email") as string

  // 校验
  if (!name || name.length < 2) {
    return { error: "名称至少 2 个字符" }
  }

  // 鉴权
  const session = await getSession()
  if (!session) throw new Error("未登录")

  // 写入数据库
  await db.user.create({ data: { name, email } })

  // 清除缓存
  revalidatePath("/users")

  // 重定向
  redirect("/users")
}

// ===== 客户端使用 =====
;("use client")
import { createUser } from "@/actions/user"

export default function CreateUserForm() {
  const [state, formAction] = useActionState(createUser, { error: null })

  return (
    <form action={formAction}>
      <input name="name" />
      <input name="email" />
      <button type="submit">创建</button>
      {state?.error && <p className="text-red-500">{state.error}</p>}
    </form>
  )
}

// ===== 非表单调用 =====
import { startTransition } from "react"
startTransition(() => {
  createUser(formData)
})
```

### Q12: Server Actions 和 API Routes 如何选择？

| 维度     | Server Actions                     | API Routes                    |
| -------- | ---------------------------------- | ----------------------------- |
| 适用     | 表单、数据变更 (Mutation)          | 外部 API、Webhook、跨应用调用 |
| 复杂度   | 低（直接在组件中调用）             | 中（需手动创建 route.ts）     |
| 类型安全 | ✅ 天然类型安全                    | 需手动定义类型                |
| 缓存控制 | `revalidatePath` / `revalidateTag` | 手动控制                      |
| 适用项目 | 全栈 Next.js 应用                  | 对外 API、微服务              |

## 五、渲染与性能

### Q13: 什么是 Streaming SSR？如何实现？

Streaming 允许服务端将 HTML **分块发送**给浏览器，先展示不需数据的内容，等数据就绪后再流式发送剩余部分。

```tsx
// app/dashboard/page.tsx
import { Suspense } from "react"

export default function Dashboard() {
  return (
    <div>
      <h1>Dashboard</h1>

      {/* 这部分立即渲染，不阻塞 */}
      <Suspense fallback={<StatsSkeleton />}>
        <Stats /> {/* 内部 await fetch — 数据就绪后流式发送 */}
      </Suspense>

      <Suspense fallback={<ChartSkeleton />}>
        <Chart /> {/* 独立流式传输，互不阻塞 */}
      </Suspense>
    </div>
  )
}

// loading.tsx 是顶层 Suspense fallback
export default function Loading() {
  return <Skeleton />
}
```

### Q14: 如何优化图片和字体加载？

```tsx
// ===== 图片优化 =====
import Image from "next/image"

// next/image 自动: WebP/AVIF 转换、懒加载、占位模糊、宽高防 CLS
;<Image
  src="/hero.jpg"
  alt="Hero"
  width={1200}
  height={600}
  priority // 首屏图优先级
  placeholder="blur"

  remotePatterns: [{ protocol: "https", hostname: "cdn.example.com" }]

// ===== 字体优化 =====

// 本地字体 — 构建时内联，零网络请求
const myFont = localFont({ src: "./fonts/MyFont.woff2", variable: "--font-my" })

// Google 字体 — 构建时下载并自托管
import { Inter } from "next/font/google"

export default function Layout({ children }) {
  return <html className={`${inter.variable} ${myFont.variable}`}>{children}</html>
}
```

## 六、数据变更与缓存

### Q16: 如何实现 Optimistic UI（乐观更新）？

```tsx
;("use client")
import { useOptimistic } from "react"

export function TodoList({ todos }: { todos: Todo[] }) {
  const [optimisticTodos, addOptimistic] = useOptimistic(todos, (state, newTodo: Todo) => [
    newTodo,
    ...state,
  ])

  async function handleAdd(formData: FormData) {
    const title = formData.get("title") as string
    // 先乐观更新 UI
    addOptimistic({ id: Date.now(), title, completed: false })
    // 再实际请求
    await addTodo(formData)
  }

  return (
    <>
      <form action={handleAdd}>...</form>
      <ul>
        {optimisticTodos.map((todo) => (
          <li key={todo.id}>{todo.title}</li>
        ))}
      </ul>
    </>
  )
}
```

### Q17: 如何实现多级缓存（Request Memoization → Data Cache → Full Route Cache）？

```
                    fetch 请求
                        │
                        ▼
          Request Memoization (同次渲染去重 — 自动)
                        │
                        ▼
          Data Cache (跨请求缓存 — cache/revalidate 控制)
                        │
                        ▼
          Full Route Cache (整页 HTML — ISR/SSG)
                        │
                        ▼
          客户端 Router Cache (浏览器内存 — 30s 内有效)
```

```tsx
// Request Memoization: 同一页面请求多次只发一次网络请求（自动去重）
let user = await fetch("/api/user") // 网络请求
let sameUser = await fetch("/api/user") // 不请求，直接用缓存结果

// Data Cache + revalidate
let posts = await fetch("/api/posts", { next: { revalidate: 60 } })

// 不使用 fetch 的数据缓存
let data = await unstable_cache(() => db.query("..."), ["key"], { revalidate: 3600 })()

// Router Cache — 客户端缓存页面，30s 内不重新请求服务端
// 可通过 prefetch 预热
import Link from "next/link"
;<Link href="/dashboard" prefetch>
  Dashboard
</Link>
```

## 七、认证与安全

### Q18: Next.js 如何实现认证？

```ts
// 1. 使用 NextAuth (Auth.js) — 配置文件 auth.ts
import NextAuth from "next-auth"
import Credentials from "next-auth/providers/credentials"

export const { handlers, signIn, signOut, auth } = NextAuth({
  providers: [Credentials({ /* ... */ })],
  callbacks: {
    jwt({ token, user }) { if (user) token.role = user.role; return token },
    session({ session, token }) { session.user.role = token.role; return session },
  },
})

// 2. 在 Server Component / Server Action 中获取 session
import { auth } from "@/auth"

export default async function Dashboard() {
  const session = await auth()
  if (!session) redirect("/login")
  return <div>欢迎, {session.user.name}</div>
}

// 3. 在 middleware 中保护路由
import { auth } from "@/auth"
export default auth((req) => {
  if (!req.auth && req.nextUrl.pathname.startsWith("/dashboard")) {
    return Response.redirect(new URL("/login", req.url))
  }
})
```

### Q19: Next.js 有哪些内置的安全特性？

| 特性                     | 说明                                             |
| ------------------------ | ------------------------------------------------ |
| **CSP**                  | 通过 Headers 配置 Content-Security-Policy        |
| **Server Actions**       | 自动 CSRF 保护（同源 POST + 加密 token 校验）    |
| **Image 优化**           | 外部图片需白名单 `remotePatterns` 防止 SSRF      |
| **环境变量**             | `NEXT_PUBLIC_*` 仅暴露给客户端，其余仅服务端可用 |
| **中间件校验**           | 在请求到达页面前做鉴权/限流                      |
| **taintObjectReference** | 标记对象仅服务端可用，防止泄露到客户端（实验性） |

| 方案                     | 适用       | 说明                                                                            |

## 汇总速查表

### 渲染方式速查

| 方式   | 实现                               | 静态/动态 |
| ------ | ---------------------------------- | --------- |
| SSR    | `cache: "no-store"` 或不设 cache   | 动态      |
| SSG    | `cache: "force-cache"`             | 静态      |
| ISR    | `next: { revalidate: 60 }`         | 定时更新  |
| Stream | `<Suspense>` + async 组件          | 流式      |
| CSR    | `"use client"` + `useEffect` fetch | 动态      |

### 缓存 API 速查

| API                                       | 作用                       |
| ----------------------------------------- | -------------------------- |
| `fetch(url, { next: { revalidate: N } })` | 设置单次 fetch 的 ISR 间隔 |
| `fetch(url, { next: { tags: ["x"] } })`   | 按标签分组                 |
| `revalidateTag("x")`                      | 按标签失效缓存（按需）     |
| `revalidatePath("/")`                     | 按路径失效缓存（按需）     |
| `unstable_cache(fn, ["key"])`             | 缓存任意函数               |
| `generateStaticParams()`                  | SSG 动态路由               |

### 文件约定速查

| 文件                  | 作用                  |
| --------------------- | --------------------- |
| `page.tsx`            | 页面                  |
| `layout.tsx`          | 布局（持久化）        |
| `template.tsx`        | 模板（每次重置）      |
| `loading.tsx`         | 加载中 UI             |
| `error.tsx`           | 错误边界              |
| `not-found.tsx`       | 404                   |
| `route.ts`            | API Route             |

### Q38: React Server Components 在 Next.js 底层是如何工作的？

```
1. 构建/请求时:
   RSC 在服务端执行 → 序列化为特殊格式 (RSC Payload)
   → 发送给客户端

2. 客户端:
   React 用 RSC Payload 协调 (reconcile) DOM
   → 不下载 RSC 对应的 JS bundle

3. 客户端组件标记 "use client":
   - 只在需要交互的部分标记
   - 客户端组件内部可以渲染 RSC (通过 children prop)
```

### Q42: 如何在 Next.js 中处理 File Upload 的进度？

```tsx
// Server Actions 不直接支持上传进度，需用 API Route + fetch
// app/api/upload/route.ts
export async function POST(req: Request) {
  const formData = await req.formData()
  const file = formData.get("file") as File
  await writeFile(`./uploads/${file.name}`, Buffer.from(await file.arrayBuffer()))
  return Response.json({ url: `/uploads/${file.name}` })
}

// 客户端 — XMLHttpRequest 获取进度
function uploadWithProgress(file: File, onProgress: (pct: number) => void) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest()
    xhr.upload.onprogress = (e) =>
      e.lengthComputable && onProgress(Math.round((e.loaded / e.total) * 100))
    xhr.onload = () => resolve(JSON.parse(xhr.responseText))
    xhr.onerror = reject
    const formData = new FormData()
    formData.append("file", file)
    xhr.open("POST", "/api/upload")
    xhr.send(formData)
  })
}
```

### Q43: 如何实现 Next.js 的 Api Route 限流？

```ts
// middleware.ts — 全局限流
import { Ratelimit } from "@upstash/ratelimit"
import { Redis } from "@upstash/redis"

const ratelimit = new Ratelimit({
  redis: Redis.fromEnv(),
  limiter: Ratelimit.slidingWindow(10, "10 s"),
})

export async function middleware(request: NextRequest) {
  const ip = request.headers.get("x-forwarded-for") ?? "anonymous"
  const { success } = await ratelimit.limit(ip)
  if (!success) {
    return NextResponse.json({ error: "Too Many Requests" }, { status: 429 })
  }
  return NextResponse.next()
}
```
