## 二、语义化与 SEO

### Q4: 什么是语义化 HTML？有哪些好处？

| 好处         | 说明                                     |
| ------------ | ---------------------------------------- |
| **SEO**      | 搜索引擎理解页面结构和内容权重           |
| **可访问性** | 屏幕阅读器按语义导航（`<nav>` = 导航区） |
| **可维护性** | `<main>` 比 `<div class="main">` 更清晰  |
| **设备适配** | 阅读模式、智能音箱等依赖语义解析         |

```html
<!-- ❌ 全用 div -->
<div class="header">...</div>
<div class="nav">...</div>
<div class="main">...</div>

<!-- ✅ 语义化 -->
<header>...</header>
<nav>...</nav>
<main>...</main>
```

### Q5: SEO 相关的 HTML 优化手段？

```html
<!-- 1. 标题层级 — 一个页面一个 h1 -->
<h1>页面主标题（核心关键词）</h1>

<!-- 2. meta 标签 -->
<meta name="description" content="150字内的页面描述（搜索摘要展示）" />
<meta name="robots" content="index, follow" />

<!-- 3. Open Graph — 社交分享卡片 -->
<meta property="og:title" content="页面标题" />
<meta property="og:image" content="https://example.com/og.jpg" />

<!-- 4. 结构化数据 (JSON-LD) — 富文本搜索结果 -->
<script type="application/ld+json">
  { "@context": "https://schema.org", "@type": "Article", "headline": "..." }
</script>

<!-- 5. img alt — 搜索引擎读图 + 无障碍 -->
<img src="photo.jpg" alt="团队合影：10 位员工在办公室微笑" />

<!-- 6. canonical — 解决重复内容 -->
<link rel="canonical" href="https://example.com/original-page" />

<!-- 7. 语义化链接文本 — "了解产品" 优于 "点击这里" -->
<a href="/product">了解产品</a>
```

### Q6: h1 标签的使用原则是什么？

- **每个页面只有一个** `h1`（SEO 最佳实践）
- 标题层级不跳级：`h1 → h2 → h3`（不用 `h1 → h3`）
- `h1` 应包含核心关键词
- 语义化：`h1` 是页面主题，不是用来控制字体大小的

## 五、性能与加载

### Q13: script 标签的 async / defer / module 有什么区别？

```html
<!-- 普通: 阻塞 HTML 解析，按顺序执行 -->
<script src="app.js"></script>

<!-- defer: 不阻塞解析，DOM 解析完后按顺序执行（推荐） -->
<script src="app.js" defer></script>

<!-- async: 不阻塞解析，下载完立刻执行（顺序不保证） -->
<script src="analytics.js" async></script>

<!-- type="module": 默认 defer，支持 import/export -->
<script type="module" src="app.js"></script>
```

| 方式     | 阻塞解析 | 执行顺序   | 适用      |
| -------- | -------- | ---------- | --------- |
| 普通     | ✅       | 按出现顺序 | —         |
| `defer`  | ❌       | 按出现顺序 | 业务代码  |
| `async`  | ❌       | 下载完立即 | 独立脚本  |
| `module` | ❌       | 按依赖图   | ES Module |

### Q14: 资源预加载 (preload/prefetch/preconnect) 怎么用？

```html
<!-- preload: 提前加载当前页面需要的资源（高优先级） -->
<link rel="preload" href="critical.css" as="style" />
<link rel="preload" href="hero.jpg" as="image" />
<link rel="preload" href="font.woff2" as="font" crossorigin />

<!-- prefetch: 预加载后续页面可能需要的资源（低优先级，空闲时） -->
<link rel="prefetch" href="next-page.js" as="script" />

<!-- preconnect: 提前建立连接（DNS + TCP + TLS） -->
<link rel="preconnect" href="https://api.example.com" />

<!-- dns-prefetch: 仅 DNS 解析 -->
<link rel="dns-prefetch" href="https://cdn.example.com" />
```

| 方式           | 时机   | 优先级 | 用途                 |
| -------------- | ------ | ------ | -------------------- |
| `preload`      | 立即   | 高     | 当前页面必需资源     |
| `prefetch`     | 空闲时 | 低     | 下一页可能用到的资源 |
| `preconnect`   | 立即   | —      | 第三方域名预热连接   |
| `dns-prefetch` | 立即   | —      | 仅 DNS 解析          |

### Q15: img loading="lazy" 的实现原理？

浏览器原生懒加载：图片进入视口前不下载。

```html
<img src="photo.jpg" loading="lazy" alt="描述" />
<!-- loading="lazy" — 视口外不加载 -->
<!-- loading="eager" — 立即加载（默认） -->
```

## 七、meta 与 head

### Q17: viewport 是什么？为什么移动端必须设置？

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

| 属性                 | 说明                    |
| -------------------- | ----------------------- |
| `width=device-width` | 视口宽度 = 设备屏幕宽度 |
| `initial-scale=1.0`  | 初始缩放 100%           |
| `maximum-scale=5.0`  | 最大缩放                |
| `user-scalable=no`   | 禁止用户缩放（不推荐）  |

不设置 viewport → 移动浏览器以 980px 桌面宽度渲染 → 页面缩小（字体极小，需手动放大）。

```html

<!-- 防止 MIME 嗅探 -->
<meta http-equiv="X-Content-Type-Options" content="nosniff" />

<!-- IE 兼容模式 -->
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```

### Q20: Web Worker 是什么？什么场景用？

```js
// 主线程
const worker = new Worker("worker.js")
worker.postMessage({ data: largeArray })
worker.onmessage = (e) => console.log("结果:", e.data)

// worker.js — 独立线程，不阻塞 UI
self.onmessage = (e) => {
  const result = e.data.data.map(heavyComputation) // 耗时计算
  self.postMessage(result)
}
```

- **独立线程**，不能操作 DOM
- 适合：大量计算、数据处理、加密、图像处理

### Q21: Web Components 由哪三个技术组成？

| 技术                | 说明                                   |
| ------------------- | -------------------------------------- |
| **Custom Elements** | 自定义 HTML 标签 + 生命周期回调        |

```js
}
customElements.define("my-counter", MyCounter)
```

## 十、高频真题

### Q22: src 和 href 的区别？

- `src`（source）— **替换**当前元素，把资源嵌入当前位置（`<script src>` `<img src>` `<iframe src>`）
- `href`（hypertext reference）— **关联**外部资源，建立链接（`<a href>` `<link href>`）

### Q24: 行内元素间的空白怎么产生的？怎么解决？

### Q25: HTML5 的离线存储和 Service Worker 是什么关系？

| 技术              | 说明                               | 状态            |
| ----------------- | ---------------------------------- | --------------- |
| Application Cache | HTML5 离线缓存，使用 manifest 文件 | **已废弃**      |

```js
// Service Worker — 离线可用
self.addEventListener("fetch", (e) => {
  e.respondWith(caches.match(e.request).then((cached) => cached || fetch(e.request)))
```

### Q28: 有过期时间的 localStorage 如何实现？

```js
function setWithExpiry(key, value, ttlMs) {
  const item = { value, expiry: Date.now() + ttlMs }
  localStorage.setItem(key, JSON.stringify(item))
}

function getWithExpiry(key) {
  const raw = localStorage.getItem(key)
  if (!raw) return null
  const item = JSON.parse(raw)
  if (Date.now() > item.expiry) {
    localStorage.removeItem(key)
    return null
  }
  return item.value
}
```

## 十一、更多核心概念

### Q29: DOCTYPE 的作用？不写会怎样？

```html
<!DOCTYPE html>
```

作用：告诉浏览器使用**标准模式**（Standards Mode）渲染，而非怪异模式（Quirks Mode）。

| 模式     | 盒模型        | 行为                              |
| -------- | ------------- | --------------------------------- |
| 标准模式 | 按 W3C 规范   | 跨浏览器一致                      |
| 怪异模式 | 模拟 IE5 行为 | 布局/尺寸计算不一致（盒模型不同） |

不写 DOCTYPE → 浏览器进入怪异模式 → 最明显的是 `width` 的计算方式不同（IE 盒模型）→ 布局错乱。

### Q30: HTML 解析过程中遇到 script 会发生什么？

```
1. HTML 解析器遇到 <script> 标签
2. 暂停 HTML 解析
3. 下载 JS 文件（如果外链） → 执行 JS 代码
4. JS 执行完 → 恢复 HTML 解析
```

→ 所以 `<script>` 放 `<body>` 底部，或用 `defer`/`async` 避免阻塞渲染。

### Q31: iframe 的优缺点？srcdoc 属性是什么？

| 优点                               | 缺点                 |
| ---------------------------------- | -------------------- |
| 隔离环境（独立的 Window/Document） | 阻塞主页面 onload    |

### Q38: 如何实现一个懒加载的 img？

```html

<!-- 2. Intersection Observer Polyfill -->

<script>
  const observer = new IntersectionObserver((entries) => {
    entries.forEach((entry) => {
      if (entry.isIntersecting) {
        const img = entry.target
        img.src = img.dataset.src
        observer.unobserve(img)
      }
    })
  })
  document.querySelectorAll("img.lazy").forEach((img) => observer.observe(img))
</script>
```

### Q57: img 的 srcset 和 sizes 的计算规则？


## 十九、HTML 解析与浏览器细节

### Q61: 浏览器如何解析 HTML？（从字节到 DOM）

```
字节 (Bytes) → 字符 (Chars) → Token → 节点 (Node) → DOM 树
```

1. 网络层接收字节流
2. 按 `charset` 解码为字符
3. 词法分析 → Token（开始标签/结束标签/属性/文本）
4. 语法分析 → DOM 节点 → DOM 树
5. 遇到 `<script>` 阻塞（除非 async/defer）
6. 遇到 `<link>` 异步加载（不阻塞解析，但可能阻塞渲染）

### Q62: 什么是重排（reflow）和重绘（repaint）？HTML 层面如何优化？

| 操作 | 触发                                                                      |
| ---- | ------------------------------------------------------------------------- |
| 重排 | 修改几何属性（width/height/padding/display/position/offsetTop scrollTop） |
| 重绘 | 修改外观属性（color/background/visibility 不影响几何）                    |

```html
<!-- HTML 层面优化 — 批量 DOM 操作 -->

<!-- ❌ 逐个操作 — 每次都触发重排 -->
<script>
  for (let i = 0; i < 1000; i++) {
    ul.innerHTML += `<li>Item ${i}</li>` // 1000 次重排
  }
</script>

<!-- ✅ 批量 — DocumentFragment 或一次性 innerHTML -->
<script>
  const fragment = document.createDocumentFragment()
  for (let i = 0; i < 1000; i++) {
    const li = document.createElement("li")
    li.textContent = `Item ${i}`
    fragment.appendChild(li)
  }
  ul.appendChild(fragment) // 1 次重排
</script>
```

### Q63: HTML 与浏览器的回流触发条件？

```js
// 读取以下属性会触发强制回流（浏览器需要先计算布局才能返回正确值）
element.offsetTop / offsetLeft / offsetWidth / offsetHeight
element.scrollTop / scrollLeft / scrollWidth / scrollHeight
element.clientTop / clientLeft / clientWidth / clientHeight
element.getBoundingClientRect()
window.getComputedStyle(element)

// ❌ 读写交替 → 强制同步布局（性能杀手）
el.style.width = "100px"
const h = el.offsetHeight // 读取 → 浏览器被迫立即计算
el.style.height = h + "px"

// ✅ 先批量读，再批量写
const h = el.offsetHeight
el.style.width = "100px"
el.style.height = h + "px"
```

## 二十、安全与性能

### Q64: HTML 注入（XSS）如何防范？

```js
// ❌ 危险：直接插入用户输入
el.innerHTML = userInput

// ✅ 安全方式 1：textContent（不解析 HTML）
el.textContent = userInput

// ✅ 安全方式 2：HTML 实体编码
function escapeHTML(str) {
  return str.replace(
    /[&<>"']/g,
    (c) => ({ "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;", "'": "&#x27;" })[c]
  )
}

// ✅ 安全方式 3：净化（需 DOMPurify 库）
el.innerHTML = DOMPurify.sanitize(userInput)
```

### Q65: Clickjacking 是什么？如何防范？

攻击者将目标网站放在透明 iframe 中覆盖在诱饵按钮上，用户以为在点诱饵，实际在点击目标网站。

```html
<!-- 防范方式 1: HTTP 头（推荐，非 HTML） -->
<!-- X-Frame-Options: DENY -->
<!-- Content-Security-Policy: frame-ancestors 'none' -->

<!-- 防范方式 2: JS frame-busting（可被绕过） -->
<script>
  if (window.top !== window.self) window.top.location = window.self.location
</script>
```
