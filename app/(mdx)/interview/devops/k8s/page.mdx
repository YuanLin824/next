## 一、基础概念

### Q1: Kubernetes 是什么？解决了什么问题？

Kubernetes（K8s）是**容器编排平台**，自动化管理容器的部署、扩缩容、负载均衡、自愈。

**解决的问题：**

- 手动启动/停止容器 → K8s 自动调度
- 容器挂了 → K8s 自动重启
- 流量增大 → K8s 水平扩展（HPA）
- 滚动更新不停机 → K8s 滚动更新
- 服务发现 → K8s Service + DNS

### Q2: K8s 的核心组件有哪些？

```
┌──────────────────────────────────────────┐
│                Master Node               │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐  │
│  │API Server│ │ Scheduler│ │Controller│  │
│  │ (入口)   │ │ (调度器) │ │Manager   │  │
│  └──────────┘ └──────────┘ └──────────┘  │
│  ┌──────────┐                            │
│  │  etcd    │ ← 集群状态存储（分布式KV） │
│  └──────────┘                            │
└──────────────────────────────────────────┘
         │                    │
    ┌────▼────────────────────▼──────┐
    │          Worker Nodes          │
    │  ┌──────────┐    ┌──────────┐  │
    │  │ kubelet  │    │kube-proxy│  │
    │  │(节点代理)│    │(网络代理)│  │
    │  └──────────┘    └──────────┘  │
    │  ┌─────────────────────────┐   │
    │  │    Pods (容器组)        │   │
    │  └─────────────────────────┘   │
    └────────────────────────────────┘
```

| 组件                   | 角色   | 职责                                       |
| ---------------------- | ------ | ------------------------------------------ |
| **API Server**         | Master | 集群统一入口（REST API）                   |
| **etcd**               | Master | 分布式 KV 存储（集群状态）                 |
| **Scheduler**          | Master | 为新 Pod 选择合适 Node                     |
| **Controller Manager** | Master | 运行各种控制器（Deployment/ReplicaSet...） |
| **kubelet**            | Worker | 节点代理，执行 Pod 操作                    |
| **kube-proxy**         | Worker | 网络代理，实现 Service 负载均衡            |

### Q3: Pod 是什么？为什么需要 Pod（而不是直接用容器）？

Pod 是 K8s 的**最小调度单元**，可以包含 1 个或多个紧密耦合的容器：

```
Pod:
├── Container A (主应用)
├── Container B (Sidecar: 日志收集/代理)
├── 共享网络命名空间（同一 IP + Port 空间）
└── 共享存储卷
```

**为什么需要 Pod？**

- **Sidecar 模式**：主容器 + 日志/代理/配置刷新等辅助容器
- **共享网络**：同一 Pod 内的容器通过 `localhost` 通信
- **原子调度**：要么一起调度成功，要么都失败

### Q4: Deployment 和 StatefulSet 的区别？

| 维度     | Deployment                | StatefulSet                               |
| -------- | ------------------------- | ----------------------------------------- |
| 适用     | **无状态**应用（Web/API） | **有状态**应用（数据库/消息队列）         |
| Pod 名称 | 随机（abc123-xyz）        | 固定序号（mysql-0, mysql-1）              |
| 网络标识 | 无                        | 稳定 DNS（pod-name.service-name）         |
| 存储     | 共享 PVC                  | 每个 Pod 独立 PVC（volumeClaimTemplates） |
| 扩缩容   | 任意顺序                  | 顺序操作（0→1→2，2→1→0）                  |

```yaml
# Deployment
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
        - name: app
          image: myapp:v1
          ports:
            - containerPort: 3000
```

### Q5: Service 的三种类型（ClusterIP/NodePort/LoadBalancer）？

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  selector:
    app: web
  ports:
    - port: 80 # Service 端口
      targetPort: 3000 # Pod 端口
  type: ClusterIP # | NodePort | LoadBalancer
```

| 类型                  | 访问方式                | 适用                   |
| --------------------- | ----------------------- | ---------------------- |
| **ClusterIP**（默认） | 集群内部访问（内网 IP） | 内部服务               |
| **NodePort**          | `NodeIP:30000-32767`    | 开发/调试              |
| **LoadBalancer**      | 云 LB 分配公网 IP       | **生产——外部流量入口** |

### Q6: ConfigMap 和 Secret 的区别？

|          | ConfigMap  | Secret                          |
| -------- | ---------- | ------------------------------- |
| 用途     | 非敏感配置 | **敏感数据**（密码/Token/证书） |
| 存储     | 明文       | Base64 编码（非加密！）         |
| 大小限制 | 1MB        | 1MB                             |

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: db-secret
type: Opaque
data:
  username: YWRtaW4= # echo -n 'admin' | base64
  password: cGFzczEyMw==
---
# 使用：环境变量注入
env:
  - name: DB_PASSWORD
    valueFrom:
      secretKeyRef:
        name: db-secret
        key: password
```

### Q7: 如何实现滚动更新和回滚？

```yaml
# Deployment 默认就是滚动更新
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1 # 更新时最多多 1 个 Pod
      maxUnavailable: 1 # 更新时最多 1 个不可用
```

```bash
kubectl set image deployment/web app=myapp:v2  # 更新镜像
kubectl rollout status deployment/web           # 查看状态
kubectl rollout history deployment/web          # 历史版本
kubectl rollout undo deployment/web             # 回滚到上一版本
kubectl rollout undo deployment/web --to-revision=2 # 回滚到指定版本
```

### Q8: 资源限制（requests vs limits）？

```yaml
resources:
  requests: # 调度保证（Pod 必须得到这么多资源才被调度）
    memory: "128Mi"
    cpu: "250m" # 0.25 核
  limits: # 硬上限（Pod 绝对不能超过）
    memory: "256Mi"
    cpu: "500m" # 0.5 核
```

|          | requests | limits                |
| -------- | -------- | --------------------- |
| CPU 行为 | 保证最低 | 超限 throttle（不杀） |
| 内存行为 | 保证最低 | **超限 OOM Kill**     |

## 三、速查

### Q9: kubectl 常用命令速查

| 操作      | 命令                                        |
| --------- | ------------------------------------------- |
| 查看 Pod  | `kubectl get pods`                          |
| Pod 详情  | `kubectl describe pod <name>`               |
| Pod 日志  | `kubectl logs <pod> [-c container]`         |
| 进入容器  | `kubectl exec -it <pod> -- bash`            |
| 扩缩容    | `kubectl scale deployment/app --replicas=5` |
| 应用 YAML | `kubectl apply -f app.yaml`                 |
| 删除      | `kubectl delete -f app.yaml`                |
| 端口转发  | `kubectl port-forward pod/app 3000:3000`    |

### Q10: 核心资源速查

| 资源        | 作用                              |
| ----------- | --------------------------------- |
| Pod         | 最小调度单位                      |
| Deployment  | 无状态应用管理                    |
| StatefulSet | 有状态应用                        |
| DaemonSet   | 每节点一个 Pod（日志/监控 agent） |
| Service     | 服务发现 + 负载均衡               |
| Ingress     | HTTP(S) 路由/域名绑定             |
| ConfigMap   | 配置注入                          |
| Secret      | 密钥注入                          |
| PVC/PV      | 持久化存储                        |
| HPA         | 水平自动扩缩容                    |
