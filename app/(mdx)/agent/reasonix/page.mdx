# Reasonix 学习指南

> DeepSeek 原生 AI 编程智能体——终端驱动的代码生成、重构与自动化工具。难度递进式学习文档，以 v1.0 Go 版为主，兼顾 v0.x TypeScript 版。

---

## 第一阶段：认识 Reasonix（入门）

### 1. Reasonix 是什么？

Reasonix 是 DeepSeek 团队打造的**终端 AI 编程智能体**（Coding Agent），运行在命令行中，可以直接读写文件、执行 Shell 命令、使用 Git，像一个真正的工程师一样完成编码任务。

```
AI 编程工具光谱：

Chatbot        →  Copilot      →  Coding Agent
(ChatGPT)        (代码补全)       (Reasonix / Claude Code)
  对话式           编辑器内嵌         终端原生，全文件系统访问
  无项目上下文      行级建议            可以改文件、跑命令、git 操作
```

**核心特征：**

| 特征              | 说明                                                        |
| ----------------- | ----------------------------------------------------------- |
| **DeepSeek 原生** | 专为 DeepSeek 模型优化，享受前缀缓存带来的极致降本          |
| **终端原生**      | 运行在终端，全文件系统读写 + Shell 执行                     |
| **前缀缓存**      | 连续对话中前缀不变的部分重用缓存，长会话 token 成本大幅降低 |
| **多模型组合**    | executor（执行）+ planner（规划）各自独立配置               |
| **执行模式**      | review / AUTO / YOLO 三级安全粒度                           |
| **v1.0 Go 重写**  | 从 TypeScript 迁移到 Go，单一静态二进制，启动更快           |

**与同类工具的定位：**

| 工具         | 优势                                     | 劣势                             |
| ------------ | ---------------------------------------- | -------------------------------- |
| **Reasonix** | DeepSeek 前缀缓存降本、终端原生、QQ 集成 | 生态较新、国内网络要求           |
| Claude Code  | Anthropic 生态、Claude 模型能力强        | 需要 Anthropic API Key、海外网络 |
| Cursor       | 图形 IDE、补全体验丝滑                   | 封闭生态、成本不透明             |
| Cline        | VSCode 插件、多模型自由切换              | 依赖 VSCode                      |

### 2. 前置条件

- **Node.js ≥ 22**（推荐；最低 20.10）
- Windows 用户需 **Git for Windows**
- **DeepSeek API Key**（从 [platform.deepseek.com](https://platform.deepseek.com) 获取）
- macOS / Linux / Windows 均支持

### 3. 安装

```bash
# ====== CLI —— 方式一：npm 全局安装（推荐日常使用） ======
npm install -g reasonix

# 短别名
npm install -g dsnix

# 指定版本
npm install -g reasonix@0.36.0

# ====== CLI —— 方式二：不安装，直接运行 ======
npx reasonix code

# ====== CLI —— 方式三：Homebrew（macOS） ======
brew install esengine/reasonix/reasonix
```

**桌面版安装：**

| 平台        | 安装说明                                                                                              |
| ----------- | ----------------------------------------------------------------------------------------------------- |
| **macOS**   | 下载 `.dmg`，首次启动可能触发 Gatekeeper：`xattr -dr com.apple.quarantine /Applications/Reasonix.app` |
| **Windows** | 下载 `-installer.exe`，SmartScreen 警告时点"更多信息 → 仍要运行"                                      |
| **Linux**   | 下载 `.deb` 或 `.AppImage`，`sudo dpkg -i reasonix.deb`                                               |

> 桌面版**内置 Node.js 运行时**，无需单独安装 Node。

### 4. 首次配置

```bash
# 方式一：向导式配置（推荐）
reasonix setup
# → 交互式填入 API Key、选择默认模型
# → 生成 reasonix.toml 配置文件

# 方式二：手动配置环境变量
export DEEPSEEK_API_KEY=sk-your-key-here

# 验证
reasonix doctor
# → ✅ Node.js v22.x  ✅ API Key  ✅ MCP ready
```

**第一条命令：**

```bash
# 进入你的项目目录，启动编码智能体
cd ~/my-project
reasonix
# → 启动交互式会话，可以输入自然语言指令

# 示例对话：
# 你： "帮我创建一个 Express 服务器，包含 /api/health 端点"
# Reasonix：自动创建文件、写代码、安装依赖、运行验证
```

## 第二阶段：基础工作流（核心技能）

### 5. 三种运行模式

| 命令                  | 模式             | 说明                               |
| --------------------- | ---------------- | ---------------------------------- |
| `reasonix`            | 交互式编码智能体 | 完整文件系统 + Shell + Git，最常用 |
| `reasonix code [dir]` | 同上，指定目录   | 等同于 `reasonix`                  |
| `reasonix chat`       | 纯聊天           | 无文件系统/Shell 工具，纯对话      |
| `reasonix run "task"` | 一次性任务       | 流式输出到 stdout，完成后退出      |

```bash
# 一次性任务（适合脚本、CI）
reasonix run "解释这个项目的目录结构"
reasonix run "为 src/utils.js 中的每个函数写 JSDoc 注释"
reasonix run --model deepseek-pro "审查 src/auth.js 的安全隐患"

# 管道输入
cat error.log | reasonix run "分析这些错误日志并给出修复建议"
git diff HEAD~1 | reasonix run "审查这次提交的代码变更"
```

### 6. 文件操作与 Shell 执行

在交互式会话中，Reasonix 可以：

- **读取文件**：自动搜索、读取项目文件
- **创建/编辑文件**：直接写入或精确替换
- **执行命令**：`npm install`、`git status`、`node test.js` 等
- **Git 操作**：创建分支、提交、查看 diff

```
# 典型交互
你："帮我把所有的 var 改成 const，然后跑一下测试"

Reasonix 会：
1. grep 搜索所有包含 var 的 .js 文件
2. 逐个文件替换 var → const
3. 运行 npm test
4. 如果测试失败，分析原因并修复
5. 报告结果
```

### 7. 执行模式（安全粒度）

按 `Shift+Tab` 切换模式，或直接输入 `/mode` 命令：

| 模式               | 行为                                             | 适用场景                      |
| ------------------ | ------------------------------------------------ | ----------------------------- |
| **review**（默认） | 敏感操作（写文件、删文件、Shell 命令）需用户确认 | **日常开发**、不熟悉的新项目  |
| **AUTO**           | 编辑操作自动执行，终端命令仍需确认               | 信任度较高时                  |
| **YOLO**           | 一切自动执行，不询问                             | ⚠️ 仅限沙盒环境 / Docker 容器 |

```
安全边界（review 模式下需要确认的操作）：
- 文件写入（Write / Edit）
- 文件删除
- Shell 命令执行（任何 Bash/PowerShell）
- Git push / 修改远程仓库
```

### 8. 模型与思维模式控制

```bash
# ====== 临时切换模型（下一轮对话后自动回退） ======

# ====== 切换推理深度 ======
/effort fast          # 快速模式：简单任务
/effort smart         # 智能模式：日常编码（默认）

# ====== 查看消耗 ======
```

**模型选择建议：**

| 任务类型              | 推荐模型             | 推荐推理深度 |
| --------------------- | -------------------- | ------------ |
| 重命名变量、加注释    | deepseek-flash       | fast         |
| CRUD 接口、组件编写   | deepseek-flash / pro | smart        |
| 架构重构、复杂算法    | deepseek-pro         | max          |
| 安全审查、代码 review | deepseek-pro         | smart        |

## 第三阶段：配置与定制

### 10. reasonix.toml 详解（v1.0+）

v1.0 Go 版使用 TOML 配置文件，替代 v0.x 的 JSON 配置。

**配置解析顺序（优先级从高到低）：**

1. 命令行 flag
2. 当前目录 `./reasonix.toml`
3. `~/.reasonix/config.toml`
4. 内置默认值

**最小可运行配置：**

```toml
# reasonix.toml
default_model = "deepseek-flash"

[[providers]]
name        = "deepseek-flash"
kind        = "openai"
base_url    = "https://api.deepseek.com"
model       = "deepseek-v4-flash"
api_key_env = "DEEPSEEK_API_KEY"
```

**完整生产配置：**

```toml
# reasonix.toml —— 生产级配置
default_model = "deepseek-pro"

# ====== API Key ======
api_key_file = "~/.reasonix/.env"       # 与桌面版共享

# ====== 模型提供商 ======
[[providers]]
name        = "deepseek-flash"
kind        = "openai"
base_url    = "https://api.deepseek.com"
model       = "deepseek-v4-flash"
api_key_env = "DEEPSEEK_API_KEY"
# 经济模型参数
max_tokens     = 4096
temperature    = 0.1

[[providers]]
name        = "deepseek-pro"
kind        = "openai"
base_url    = "https://api.deepseek.com"
model       = "deepseek-v4-pro"
api_key_env = "DEEPSEEK_API_KEY"
max_tokens     = 8192
temperature    = 0.1

# ====== 执行器与规划器分离（高级） ======
[executor]
model = "deepseek-pro"                 # 写代码用 Pro

[planner]
model = "deepseek-flash"               # 定计划用 Flash（便宜）
cache  = true                           # 启用前缀缓存

# ====== 安全 ======
[safety]
require_confirmation_for = ["delete", "git_push", "npm_publish"]
auto_confirm_reads       = true
blocked_commands         = ["rm -rf /", "git push --force origin main"]

# ====== 上下文 ======
[context]
max_context_tokens = 128000             # 上下文窗口上限
auto_compact       = true               # 接近上限时自动压缩
compact_ratio      = 0.8                # 达到 80% 时触发

# ====== UI ======
[ui]
theme    = "dark"
language = "zh-CN"
```

### 11. 多模型组合策略

Reasonix 支持 **executor（执行者）和 planner（规划者）使用不同模型**：

```
Planner（Flash）              Executor（Pro）
    │                              │
    │ "创建 3 个文件"              │ 逐个写文件
    │ "修改 5 处引用"              │ 精确替换
    │ "运行 npm test"              │ 执行测试
    │                              │
    └──────────────────────────────┘
              分工协作
```

**设计哲学：** Planner 做高层决策——"做什么"，用便宜模型。Executor 做具体实现——"怎么做"，用强模型。

### 12. MCP 扩展

MCP（Model Context Protocol）允许 Reasonix 连接外部工具和数据源：

```bash
# 查看内置可用 MCP
/mcp

# v0.x 配置（~/.reasonix/config.json）
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/data"]
    }
  }
}

# v1.0+ 配置（reasonix.toml）
[[mcpservers]]
name    = "database"
command = "npx"
args    = ["-y", "@anthropic/mcp-server-postgres", "postgresql://..."]

[[mcpservers]]
name    = "github"
command = "npx"
args    = ["-y", "@modelcontextprotocol/server-github"]
env     = { GITHUB_TOKEN = "ghp_xxx" }
```

**常用 MCP 场景：**

| MCP Server            | 用途                |
| --------------------- | ------------------- |
| `filesystem`          | 访问项目外目录      |
| `postgres` / `sqlite` | 直接查询数据库      |
| `github`              | 创建 Issue、读取 PR |
| `playwright`          | 浏览器自动化测试    |
| `docker`              | 管理容器            |

## 第四阶段：高级特性

### 15. 规划模式（/plan）

规划模式是一种**先规划后执行**的工作方式——Agent 先分析任务、制定步骤，用户确认后再逐步执行：

```bash
/plan                   # 进入规划模式

# 工作流：
# 1. 你："用 TypeScript 重构 src/utils.js"
# 2. Reasonix 分析文件依赖、输出迁移计划：
#    - 第一步：创建 tsconfig.json
#    - 第二步：重命名 utils.js → utils.ts，添加类型注解
#    - 第三步：查找所有引用，更新 import 路径
#    - 第四步：运行类型检查
# 3. 你审查计划 → 同意 / 修改 → 执行
```

**何时用规划模式：**

- 跨多文件的大规模重构
- 新手不熟悉的代码库
- 希望先行审查 AI 计划的场景

### 16. 前缀缓存机制

这是 Reasonix 的核心降本技术：

```
第一次对话：
┌────────────────────────────────────────────┐
│ system prompt │ context │ query1           │  ← 全部 token 计费
└────────────────────────────────────────────┘

第二次对话（同一会话）：
┌────────────────────────────────────────────┐
│ system prompt │ context │ query2           │  ← 前缀不变部分 ✅ 缓存命中免计费
└────────────────┬───────────────────────────┘
                 │        └── 新 query：计费
                 └── 前缀：0 元
```

**效果：** 长会话中，system prompt + 项目上下文（固定前缀）只计费一次，后续每次只计新增消息的 token。在长编码会话中可节省 60-90% token 成本。

**通过 `/stats` 查看缓存收益：**

```bash
/stats
# → 总 token:  245,320
# → 缓存命中:   168,000 (68.5%)
# → 实际计费:    77,320
# → 成本节省:   ~68%
```

### 17. 上下文管理

```bash
/compact               # 手动触发上下文压缩
```

**自动压缩配置：**

```toml
[context]
auto_compact  = true        # 接近上限自动压缩
compact_ratio = 0.8          # 达到 80% 窗口时触发
```

压缩过程：Agent 将对话历史压缩为摘要，保留关键决策和上下文，丢弃冗余细节，释放 token 空间。

**什么会被保留 / 丢弃：**

| 保留                    | 丢弃               |
| ----------------------- | ------------------ |
| 项目上下文（AGENTS.md） | 中间步骤的输出     |
| 关键决策和变更描述      | 失败尝试的细节     |
| 当前任务目标            | 已完成的子任务对话 |

### 22. 常见问题速查

| 问题                          | 原因                   | 解决方案                                                    |
| ----------------------------- | ---------------------- | ----------------------------------------------------------- |
| `reasonix: command not found` | npm 全局 bin 不在 PATH | `npm install -g reasonix` 或 `npx reasonix`                 |
| API Key 401 / 403             | Key 过期或余额不足     | 检查 [platform.deepseek.com](https://platform.deepseek.com) |
| 连接超时                      | 网络问题 / 代理        | 检查 `base_url` 是否正确可达                                |
| 内存使用过高                  | 上下文过长             | `/compact` 手动压缩，或配置 `auto_compact`                  |
| 生成代码不符合项目规范        | 缺少 AGENTS.md         | `/init` 生成项目配置                                        |
| v1.0 API 兼容                 | 配置格式变更           | `reasonix setup` 自动迁移                                   |

### 23. 版本迁移（v0.x → v1.0）

```bash
# 1. 升级
npm install -g reasonix@latest

# 2. 自动迁移配置
reasonix setup
# → 检测旧版 config.json → 交互式迁移到 reasonix.toml

# 3. 验证
reasonix doctor

# 主要变更：
# - 配置文件：config.json → reasonix.toml
# - 实现语言：TypeScript → Go（更快启动、更低内存）
# - API Key：独立 .env 文件（~/.reasonix/.env）
```

### 24. 最佳实践清单

| 实践               | 说明                           |
| ------------------ | ------------------------------ |
| 先 `/init` 再开始  | 生成 AGENTS.md 让 AI 理解项目  |
| 小任务优于大任务   | 一次一个功能，而非"写整个 App" |
| 善用 `/plan`       | 复杂变更先规划再执行           |
| 保持 review 模式   | 除非沙盒环境，不要长期用 YOLO  |
| CI 中用 `--no-tui` | 无头模式不启动交互界面         |
| Pla ner 用 Flash   | 便宜模型做计划，Pro 模型写代码 |
| 提交 AGENTS.md     | 团队共享 AI 指令               |
| 定期 `/stats`      | 关注缓存命中率和成本           |
